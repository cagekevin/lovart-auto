### TD-04-4 · 死样式（无主灵活性）

- **位置**：`ui/style.css` `.dialog-add.is-danger:hover, .dialog-close.is-danger:hover { color: var(--bad); }`
- **现象**：这两个类组合没有任何元素使用 —— 标题栏的加号（新建 / 添加）与叉（关闭）都不是危险动作；删除图标用的是 `.icon-btn.is-danger`（另有消费者）。
- **判据**：ADR-0001「说不出存在理由就删」· 找债方法六类第 2 类「死代码」。
- **证据级别**：**契约证据**（`grep -rn 'dialog-add.*is-danger\|dialog-close.*is-danger' ui/` = 0；`index.html` 两个 `.dialog-add` 与两个 `.dialog-close` 均无 `is-danger`）。
- **Proof**：删掉该规则后 `grep -c 'is-danger' ui/index.html` 仍为 1（只 `.icon-btn.is-danger` 在卡片里），编译与手测不受影响。
- **净效果**：删 1 条规则，不新增机制 = **净 −1 概念**。

### TD-04-5 · 编辑态间距三种机制（边界表演）

- **位置**：`ui/style.css` `.preset-name`（`width: calc(100% - 32px)` + `margin: 12px 16px 0`）· `.preset-composer`（`margin: 8px 16px 0`）· 容器 `#presetFormView`（`display:flex; flex-direction:column`，本可给 padding 却没给）。
- **现象**：「编辑态左右各留 16px」这一件事有三种表达：`calc` 扣宽、子项 margin ×2、容器无 padding。任一处改了另外两处不会跟着动，且 `calc(100% - 32px)` 把 16 这个数字写死进宽度公式（与 `--sp-4` 两处真相）。
- **判据**：style.css 查1「间距来源唯一：区块间距只由父容器给，子项不再写同方向的值」· ADR-0001「一份事实只放一处」。
- **证据级别**：**契约证据**（三条规则同处一个文件、`#presetFormView` 确定是它们的唯一父容器）。
- **Proof**：改后 `#presetFormView { padding: var(--sp-3) var(--sp-4) 0 }`、`.preset-name { width: 100%; margin: 0 }`、`.preset-composer { margin: var(--sp-2) 0 0 }` —— 名字框宽度 = 容器内容宽，左右留白只来自容器一处；若漏改任一处，视觉上会出现 32px 或 0px 的错位，一眼可见。
- **净效果**：删 `calc` + 2 处子项横向 margin（3 个概念）− 新增 1 处容器 padding = **净 −2 概念**。

**终态检查**：两个债都只涉及 CSS 规则删除 / 归属移动，不持有写入、回调、资源。改动后 `node --check ui/app.js` 不相关 CSS 但作为兜底仍跑；迟到的视觉副作用由手工 H1–H9 发现。

**生命周期四问**：无 flag / promise / 队列 / 哨兵新增。

## 二·补 用户追问后的二次自查（同日）

> 用户质疑「就这些吗？你自己写的代码心里没数吗？」⇒ 回头逐条查自己写的 `renderPresetList` / `renderLibrary`。
> **认错**：上一版体检说「重复实现无债」是错的 —— 我只收口了 `openPresets` 的调用点，没看渲染函数内部的 `clear → await → append` 结构。

### TD-04-6 · 两次异步渲染重叠会 append 两份（契约证据）

- **位置**：`ui/app.js` `renderPresetList` 与 `renderLibrary`，原结构都是 `clear(box) → await list() → append`。
- **现象**：两个调用重叠（删图时另一次打开、连点按钮）⇒ 两次 clear 后各自 append ⇒ 卡片 / 网格翻倍。这与上一轮「6 张卡」是**同一个根因**，上次只堵了一个调用点，没堵结构。
- **判据**：ADR-0001「半收口比不做更糟」· ADR-0005「一个能力一条线」。
- **Proof**：注入 `await` 前强制并发调用两次 `renderPresetList`，改前 DOM 里两个 `.preset-grid`，改后只有一个（令牌让旧的那次直接 return）。
- **净效果**：每个渲染函数加 1 个 token 变量 + 2 处复查（共 6 行），消除「翻倍」这一类 bug + 以后每加一个调用点都要担心并发的心智负担 = **净负**。
- **处置**：`let presetListToken / libraryToken`，`await` 前后各查一次 token，旧渲染直接放弃。

### TD-04-7 · `images` 字段读取口径不一（契约证据）

- **位置**：`ui/app.js` 同一文件里 `renderPresetList` 用 `(p.images || [])`，`applyPreset` 用 `latest.images.length`。
- **现象**：Rust 侧 `#[serde(default)]`（`preset.rs:166` 测试锁死）保证字段一定在；`|| []` 是把「清单被外部改坏」伪装成「没垫图」（找债方法第 4 类兜底默认值）。
- **Proof**：把 `manifest.json` 某条预设的 `images` 字段删掉，改前 `|| []` 静默当空、改后 `p.images.map` 抛错可见。
- **净效果**：删 2 处兜底 + 1 处注释说明 = **净 −2 概念**。
- **处置**：统一删掉 `|| []`，两处都直接读 `p.images`。

**二次自查覆盖**：`renderPresetList` / `renderLibrary` 的 `clear→await→append` 结构 · `applyPreset` / `openPresetEditor` 的字段读取 · `closePresetEditor` 变 async 后的事件绑定 · `openPresets` 与 `closePresetEditor` 是否重复表达同一状态转移（试过拆开，马上撤回——那会变成两个可抄样本，违反 ADR-0001，最终保留一个入口 + 令牌）。

## 三、结论

- 四条债当场解决（用户裁定「解决」 + 追问后二次自查）：TD-04-4 删死样式、TD-04-5 间距收口到容器、TD-04-6 渲染写者令牌、TD-04-7 删 `images || []` 兜底。
- 未收口：账本既有 TD-04-1 / TD-04-2（picker catch / presetMessage 兜底），本轮范围外，不动。
- 判非债：见 §二「九透镜结论」六类。
- **仍存在的风险（如实报）**：令牌只防「两个渲染重叠」，不防「取数成功后用户已关面板还继续 append」——但那只是往隐藏的 DOM 里画一次，下次打开先 `clear`，无可见后果；且加 flag 会引入新状态，违反 ＡＤＲ-0010。手工 H1–H9 仍是唯一行为验证。
