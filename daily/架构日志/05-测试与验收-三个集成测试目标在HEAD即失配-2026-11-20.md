# 05 测试与验收 · 三个集成测试目标在 HEAD 即失配

- **日期**：2026-11-20
- **发现于**：`docs/plan/16` 第一步（拆 `crates/lovart-core`）之后跑 `cargo test`
- **结论**：不是拆分引入的；拆分前（HEAD）这三个目标就编译不过。

## 现象与证据

| 测试目标 | 错误 | HEAD 同样存在的证据 |
|---|---|---|
| `tests/cancel_all.rs` | `unresolved imports lovart_client::gui::remove_finished_tasks_core, remove_open_tasks_core`（`gui` 里没有这两个函数） | `git show HEAD:src-tauri/src/gui.rs` 搜这两个名字 = 0 命中 |
| `tests/support/mod.rs:300` | `method set_mode has an incompatible type for trait: expected Mode, found bool` | `git show HEAD:src-tauri/tests/support/mod.rs` 里就是 `unlimited: bool` |
| `tests/client_contract.rs:340` | `mismatched types: expected Mode, found bool`（`set_mode(&deps, true)`） | `git show HEAD:src-tauri/src/lovart/client.rs` 的签名已是 `set_mode(deps, mode: Mode)` |

`gate_contract` 也红，但根因是 `support/mod.rs` 那一处（共用 mock）。

## 为什么本轮不修

`ADR-0001` 检查项 6：范围外的发现另开一债，不混进本次。
本轮是"拆 crate、行为零变化"，修测试要**先定 canonical API**，属独立决定：

1. `cancel_all.rs` 的两个作用域函数是补成 `gui` 的具名函数，还是让测试直接调
   `remove_board_tasks_core(&path, engine::group::is_board_open)`？
   （后者更符合"一个能力一个入口"，但要把 `remove_board_tasks_core` 放开可见性。）
2. `set_mode` 的测试调用改成 `Mode::Queue`（对应原 `unlimited = true`）还是 `Mode::Fast`？
   需要按用例意图逐条确认，不能机械替换。

## 影响

- `cargo check --workspace` 绿；两个 crate 的 `--lib` 单测全绿（53 + 11）。
- `cargo test --workspace` 因这三个目标**编译失败**而整体不绿 —— 修之前不能声称"全绿"。

## 偿债判据

- `cargo test --workspace` 通过；
- 三个目标的用例意图没变（`cancel_all` 仍是"两个作用域互为补集"，`set_mode` 仍覆盖
  unlimited / fast 两条）；
- 不新增同义入口：作用域判据仍只有 `engine::group::{is_board_open, is_board_finished}`。
