# lovart 自动生图 · 详细说明

> `README.md` 是给 AI 的操作说明（四步）。这里是给人看的：界面动作、设计取舍、打包、
> 验证规则、以及那些踩过一次不想再踩的坑。

---

## 1. 打包与工作区

**macOS**：`make app` → 仓库根下的 `lovart.app`（`scripts/make-app.sh`）。
双击开图形界面（同一份二进制；现在没有命令行模式）。

**Windows**：`make win` / 双击 `scripts\build-win.bat` → 仓库根下的 `lovart-client.exe`
（`scripts/make-exe.ps1`）。脚本做三件事：从 `packaging/icon.png` 生成 `.ico` → 载入 MSVC 环境编译
→ 把 exe 拷到仓库根。产物自包含，运行时依赖为 0。

> ⚠️ 必须是 `pwsh`（PowerShell 7），不能用 `powershell`（5.1）：脚本是 UTF-8 **无 BOM**，
> 5.1 按 GBK 解码 ⇒ 中文乱码、括号错位，报 `Unexpected token '}'`（2026-11-18 实测）。
>
> ⚠️ `build-win.bat` 发现 exe 还在运行时会提示先关闭，**不替你杀进程**，免得中断正在跑的任务。

> ⚠️ **改过 `ui/` 必须重新 `make app` / `make win` / `cargo build`** —— 前端资源是**编译期**
> 由 `tauri-build` 嵌进二进制的（`frontendDist: ../ui`），运行时不读磁盘上的 `ui/`。

**工作区判定**（`gui.rs` 的 `workspace_dir()`）：双击启动时 Finder 给的当前目录是 `/`，
所以 `.app` 同级目录是仓库 ⇒ 用它。Windows 上没有这层外壳，走「当前目录是工作区」分支
（双击时当前目录 = exe 所在目录）。两者都要求产物与 `data/` 同级
（`data/` 内是 `.env` / `inbox/` / `var/` / `output/` 等；旧根目录布局在启动时一次性迁移进去）。

**产品形态**：双击 = 图形界面（一个自包含二进制，没有命令行模式）。
其他程序要走本机 HTTP，见 `docs/接入指南-本机HTTP-其他前端-2026-11-20.md`。

## 2. 断点续跑与状态

状态写在 `data/var/state.jsonl`（每行一条，同 id 以最后一条为准）。
**状态表在代码里**：`crates/lovart-core/src/engine/state.rs` 的 `STATUS_TABLE`
（每行一个状态，字段含义写在 `StatusRow` 各字段的注释里）。
每个状态的含义也写在 `TaskStatus` 各变体注释里（同一文件）。这里**刻意不抄一份表**：
抄的那份会漂移（历史上第 4 列就与代码对不上，`download_failed` 的短名也两处不同）。

- 任务 id 由**内容哈希**生成 ⇒ 增删行、调整顺序都不打乱已有进度。
- `Ctrl+C` 中断时正在跑的任务保留 `threadId`，下次自动复查。
- ⚠️ **改了模型 / 比例 / 尺寸会重跑**：id 只哈希提示词文本，启动时比对这三个参数，
  对不上就重置为 `pending`（**旧图不覆盖**，自动加 `_r1` 后缀），日志打印「参数变更重跑 N 条」。

## 3. 设计要点（容易踩的坑）

1. **并发上限是「服务端槽位」，不是 worker 数。** 槽位 = 已提交未到终态的任务数，**从状态派生**
   （`count(SLOT_HOLDING_STATUSES)`），不维护计数器 —— 手动计数器必然漂。
   超时被放走的任务**仍占槽位**，所以要优先复查它，而不是立刻补新任务。
2. **超时 ≠ 失败。** 轮询超时只释放 worker，任务转 `timeout` 保留 threadId，收尾再查。
3. **默认不自动确认 `pending_confirmation`。** 那是高成本操作要用户批准才扣积分的闸门。
   `.env` 的 `LOVART_AUTO_CONFIRM` 打开后才会自动确认，且**同一任务每批最多一次**；
   确认失败一律转人工、**不重试**（请求可能已在服务端生效，重试就是重复扣费）。
   关着时遇到它仍记 `needs_confirm` 并跳过。
4. **每次提交前重设排队模式。** 服务端模式是**账号级持久设置**，可能被别处（如 AI Canvas）改回 fast。
5. **不要与 AI Canvas 同时用 Lovart**，两边会互相改模式。
6. **尺寸只给档位标签，不给像素。** 提示词里只写 `resolution: 2K, aspect_ratio: 3:4`，
   输出尺寸由模型决定，实际尺寸可能与档位不完全一致（实测 `3:4 + 2K` 出 1792x2400）。
7. **槽位必须能降下来，否则并发会被拖死。** 「超时保留」有上限（设置页 `LOVART_MAX_TIMEOUTS`，
   默认 3 次 = `90 + 30×3` 分钟），达到就释放槽位转 `unresolved`，交给收尾兜底复查。
   这只是「单轮」上限：`unresolved` 下次运行会继续查，跨运行没有硬上限。
8. **下载失败 ≠ 重新生成。** 生成成功时服务端槽位已释放，下载失败只是网络问题：
   立即释放本地槽位，产物 URL 记进 `state`，收尾和下次**只补下载**（幂等，绝不覆盖已有图，重名加 `_rN`）。
9. **收尾阶段只跑一轮。** `unresolved` 兜底复查与 `download_failed` 补下载各只做一次，
   不满足就留在原状态等下次 —— 避免「复查 → 超时 → 再复查」的死循环。
10. **「服务端并发满」是排队状态，不是失败。** 上游返回 402 / 409 / 429 / 2011 / 2012 / 1429 时，
    任务回 `pending`，按**本任务自己的**退避时间（5s→60s 封顶 + jitter）重投，
    计入 `LOVART_MAX_BUSY_RETRIES` 而**不是** `LOVART_MAX_ATTEMPTS`（后者 3 次会让「另一批占着几小时」直接判死）。
    **任何任务到达终态 ⇒ 立刻解除等待**。⚠️ 必须按任务记退避时间：全局闸门会被最后一次写入覆盖，一开就齐撞。

### 兜底参数

`model` / `ratio` / `size` 没写时用兜底值，优先级 **`.env`（`LOVART_DEFAULT_*`）> 内置默认**，
三个字段各自独立兜底。GUI「设置 → 兜底模型 / 兜底比例 / 兜底尺寸」写的就是这三把键，
判定只有一处（`PromptDefaults::resolve`）。

⚠️ 这是**取值**兜底，不是**校验**兜底：字段写了但不合法（`"ratio":"3x4"`）仍然报错。

### 运行参数只在设置页

并发 / 提交间隔 / 重试 / 超时 / 轮询间隔只在设置页改（2026-11-18 定）。能力没删：
界面「设置」照旧可改，落到 `.env`，唯一读取点是 `engine::settings`。

| 键 | 管什么 |
|---|---|
| `LOVART_CONCURRENCY` | 并发（硬上限 8） |
| `LOVART_TASK_INTERVAL_MS` | 提交间隔（上限 600000，`0` 关闭） |
| `LOVART_MAX_ATTEMPTS` / `LOVART_MAX_BUSY_RETRIES` | 失败重试 / 并发满重投 |
| `LOVART_MAX_TIMEOUTS` / `LOVART_DOWNLOAD_RETRIES` | 超时保留上限 / 下载重试 |
| `LOVART_TASK_TIMEOUT_MS` / `LOVART_RECHECK_TIMEOUT_MS` | 单任务超时 / 复查超时 |
| `LOVART_POLL_INTERVAL_MS` / `LOVART_POLL_MAX_INTERVAL_MS` | 轮询间隔与封顶 |

`.env` 缺键用内置默认；值非法/越界 ⇒ 回退默认 + 告警。

## 4. 界面里几个容易误解的动作

界面上没有「进度条」，这是**刻意的**：上游 `/chat/status` 只回 `status`
（`{"data":{"thread_id":"…","status":"running"}}`，2026-10-01 直连实测）——
没有百分比、没有排队位次。「这一条生成到几成」没有真值，画一条按时间猜的条就是编数字。
单条能回答的真话只有两件：**现在哪一步**（状态标签）+ **已经等了多久**。

| 动作 | 它到底做什么 | 什么时候用 |
|---|---|---|
| **导入时的份数** | 每个文件行「导入」按钮左边的数字，默认 1。**不是重复提交同一任务**：N 份把每条提示词 push 成 N 条独立待发任务，发布后 id 是 `hash` / `hash-2` / `hash-3`…，出 N 张不同的图，占 N 个并发槽位。上限 20，填错（0 / 字母 / 超上限）**报错且不入队** | 同一提示词想多抽几张 |
| **工具条的「数量」+「发送」** | 提示词框下方最右端。数量默认 1；点「发送」或按回车（同一入口）把**当前这条**入队 N 份 —— 与导入份数同一口径：N 个独立任务、每份都带完整的同一套垫图。只进「待发」，**不花钱** | 同一条提示词想多抽几张 |
| **垫图（参考图）** | 每条图生图任务卡上显示这次用的垫图（缩略图 + 路径），点缩略图看大图，`⋯ → 复制垫图地址` 可带走，也可以直接从卡片拖进右侧垫图区复用。路径来自记录里的 `refFiles`（本机文件）；CDN 地址是发送那一刻现取的产物，会过期，所以**不落记录** | 核对「我垫的是哪张图」/ 拿旧图再发一次 |
| **载入编辑区** | 卡片 `⋯ → 载入编辑区`：把这一条的提示词（`[img=图片N]` 还原成芯片）、垫图（按原顺序）、模型 / 比例 / 尺寸整体**替换**进右侧编辑区。不动这条任务、不进待发、不花额度；编辑区非空时先弹确认。载入**不写回设置** | 想拿旧图/旧提示词改一版 |
| **自动探测上游** | 打开界面时，对本地没人跟的未完成任务逐条 `GET /chat/status`（**只读**）。结论写在左侧标题行：`上游：已中止 4、仍在跑 1` | 自动 |
| **接着查** | 把未完成的记录重新交给调度器：有 `threadId` 走**复查**（不重复提交），产物已出则只补下载。未完成记录里若有垫图，记录里没存垫图本身 ⇒ 跳过并告知 | 标题行出现「N 未跟进」时 |
| **重跑异常** | 把已到终态的异常（失败 / 未产出…）重新**生成** —— **会再花一次额度** | 明确知道要重做 |
| **删除这条** | **真删**：读 → 滤 → 重写整个 `data/var/state.jsonl`（临时文件 + 原子 rename）。只删记录，不动磁盘上的图 | 收拾残记录 |
| **取消所有未完成任务** | 任务中心标题栏的 `⋯`（板级入口）：停掉当前批次 → 等批次线程退出 → 删除全部未结束记录。已结束的任务、图片、报告都不动 | 一整轮跑歪了 |
| **清空所有已完成任务** | 同一个 `⋯` 菜单（分隔线隔开）：删除全部已结束记录。不停批次，但跑批中会拒（同样要重写状态文件） | 看板被历史刷满 |
| **AI 对话** | 工具条「AI 对话」= **纯文本对话面板**（`ui/assistant-plugin/`，独立插件）：非流式、无工具、只有一句系统提示词；图片当输入上下文，回复就是文本。**不发任务、不入待发、不花出图额度**（另配 `LOVART_CHAT_*` 三键，与出图凭据不复用）。会话存在 `data/chat-history.json`；未发送的输入只在插件内存里，切会话即丢弃 | 问问题、讨论图片 |

> ⚠️ **删除有一道闸：跑批中不许删。** 删除要重写整个状态文件，而调度器正在往同一个文件
> 追加写 —— 并发会让窗口期内写的行被**静默冲掉**（不报错、不告警，就是少了）。
> 「取消所有未完成任务」走同一约束，但它先停批再删：跑批中点击只置取消标志并立刻返回
> （最坏约 60 秒），删除发生在批次线程收尾、且没有新批次能进来时。

> ⚠️ **垫图存本机路径，不存 CDN，也不存哈希**：记录里存 `refFiles`（本机文件路径）——
> 界面看垫图、重跑复用、发送前上传都读它。CDN 地址会过期变破图，所以不落记录。
> 内容哈希（原 `refSignature`）已于 2026-11-09 删除：只被存进去、原样搬出来，
> **没有任何一处基于它做判断**。后果要说清：垫图一旦没进记录，重跑**图生图会静默退化成文生图**，
> 而且不报错。所以 `new_record` 必须把 `ref_files` 带过来，`reset_for_retry` 必须保留它。

> ⚠️ **为什么会有「没人跟」的未完成任务**：调度器的队列只由当前提示词文件派生。
> 上一次被中断留下的 `running`，如果不在下一批的提示词里，就永远没人再查 ——
> 既不会完成，也不会变红。所以界面按「本批次有没有接管它」（`following`）而不是「状态是什么」
> 来画卡片，并提供「接着查」把它们接回来。

## 5. 验证规则（硬性，2026-11-11 定）

**编译不是测试。** `cargo build` / `cargo check` / `make check` / `make win` 只证明「能编过」，
不证明行为正确。拿它们当验收目标，等于用「没报错」冒充「做对了」。

| 改了什么 | 怎么验 | 禁止 |
|---|---|---|
| `ui/`（前端） | `node --check ui/app.js`（1 秒）+ 手工清单（点/拖/发） | 禁止为「验前端」跑编译 |
| `src-tauri/`（后端） | 针对性 `cargo test --release <过滤名>`，或出包后手工跑一条 | 禁止每轮跑全量 `cargo test`；禁止只拿 `make check` 全绿当行为验证 |
| 纯注释 / 文档 | 不需编译 | — |

- `make check` 是「防回归」的全量套件，代价是整棵 dev-profile 依赖重编，不是每轮的闸。
- 本机 `G:` 是 **ReFS**（不支持硬链接）⇒ cargo 增量缓存退化为整份复制，一次全量编译数分钟
  且吃满 CPU。这是环境限制，提速只能把 `CARGO_TARGET_DIR` 挪到 NTFS 盘（如 `H:`），不靠「少验」解决。
- `cargo test` 失败退出码是 **101**（不是 1）。

**验证「测试真有鉴别力」**：用 `scripts/probe.mjs`（注入一处 → 跑命令 → 精确断言 → 自动还原）。

```bash
node scripts/probe.mjs --label '…' --file crates/lovart-core/src/engine/state.rs \
  --find '<原实现>' --replace '<写坏>' --run 'cargo test --workspace' \
  --expect-exit 101 --expect-out '<哪条测试该红>'
```

它比「跑一遍看红不红」强在四处：**强制注入点唯一**（0 处 / >1 处都拒绝）·
**基线必绿前置**（防「本来就红」被当成「先红成功」）· **`--expect-out` 精确要求红在那一条** ·
**journal 兜底 + 还原自校验**（被 Ctrl+C 也不会把注入态留在工作区）。

> ⚠️ `make check` 全绿只证明「和上次一样」，**不证明「规则真的成立」**。
