# 本机 HTTP 接入指南（给「另一个前端」）

> 适用：**同一台机器**上的另一个程序，想调用本工具的生成能力。
> 真源：`src-tauri/src/http.rs`（端点）、`crates/lovart-core/src/service/api.rs`（业务）、
> `crates/lovart-core/src/engine/state.rs` 的 `STATUS_TABLE`（状态表）。
> 本文件只写「怎么调」，不重复内部实现。

---

## 0. 前提

1. 本工具的 **GUI 已启动**（HTTP 服务随 GUI 起来；没有 CLI 模式）；
2. 端口 **17863**，只绑 `127.0.0.1`（不对外网开放）；
3. token 在 **`var/http-token`**（32 位十六进制，首次启动生成，之后复用）。

## 1. 三步接入

```text
① 读 var/http-token
② GET  /state        看当前有没有在跑、任务到哪一步
③ POST /tasks        提交（想让人先确认再开跑 ⇒ 用 `POST /drafts`，见 §2.4）
```

所有请求都要带头：

```http
Authorization: Bearer <token>
```

缺 token / token 不对 ⇒ **401**。

## 2. 端点

### 2.1 `POST /tasks`

请求体：

```json
{
  "tasks": [
    {
      "prompt": "一只橘猫坐在窗台，柔和侧光",
      "model": "nano-bn-2",
      "ratio": "3:4",
      "size": "2K",
      "refs": []
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `prompt` | 是 | 空串 ⇒ 400 |
| `model` | 否 | 空/缺省 ⇒ `.env` 的 `LOVART_DEFAULT_MODEL`（内置 `nano-bn-2`） |
| `ratio` | 否 | `宽:高`，两边各 1~3 位数字；缺省 `3:4` |
| `size` | 否 | `1K` / `2K` / `4K`（大小写不敏感）；缺省 `2K` |
| `refs` | 否 | 垫图：URL、**绝对路径**、或 `data:image/...;base64,...` |

响应 **200**：

```json
{ "accepted": 1, "receivedAt": "2026-11-20T08:30:52.65Z" }
```

⚠️ `accepted` 只代表**受理**。记录是在后台线程里建的（要先解析/上传参考图），
所以 `receivedAt` 之后要等几秒才能在 `/state` 里看到这条。

⚠️ **重复 POST 同一条 prompt = 真的再生成一张**（id 顺延 `-2`、会扣额度），不是去重。

### 2.2 `GET /state`

返回**全量**看板（与 GUI 同一份构造）：

```json
{
  "stateFile": "...",
  "outputDir": "...",
  "summary": { "total": 486, "done": 400, "running": 1, "pending": 3 },
  "tasks": [
    {
      "id": "a27952e166a8",
      "prompt": "一只橘猫坐在窗台，柔和侧光",
      "model": "nano-bn-2",
      "aspectRatio": "1:1",
      "imageSize": "2K",
      "status": "running",
      "statusLabel": "生成中",
      "group": "active",
      "following": true,
      "filesPresent": [],
      "stateSinceText": "12秒",
      "missingArtifact": false,
      "abnormal": null,
      "actions": ["resume"]
    }
  ],
  "running": true,
  "runningBatch": "处理中",
  "autoConfirm": false,
  "autoConfirmed": 0,
  "spendMode": false
}
```

⚠️ **输入字段名与输出字段名不同**：提交用 `ratio` / `size`，读回是 `aspectRatio` / `imageSize`（`TaskRecord` 是 camelCase，与 `state.jsonl` 一致）。

⚠️ **没有增量**：每次都是全量（486 条约 1MB）。建议 **2 秒轮询一次**，不要更密；
服务端是**串行**处理，一次 `/state` 会挡住同刻的 `/tasks`。


### 2.4 `POST /drafts`（只递送，不开跑）

请求体与 `/tasks` **完全一样**（同一个 `{ "tasks": [ … ] }`）。差别是**语义**：

| | `/tasks` | `/drafts` |
|---|---|---|
| 写 `state.jsonl` | 是 | **否** |
| 会开跑 / 扣额度 | 是 | **否** |
| 谁决定开跑 | 调用方 | **人**（在 GUI「待发」里看过、改过再点发布） |

响应 **204**（空 body，没有要解析的东西）。401 / 400 / 413 与 `/tasks` 同。

- 草稿**只在内存**：GUI 关掉就没了，不落盘；
- 垫图三种传法都收（见 §4）；GUI 会把路径归一、把 `data:` 落盘；
- 空 `prompt` 不在这里拦 —— 人点发布时由既有校验拦。

## 3. 任务状态（看 `/state` 的 `status`）

| `status` | `statusLabel` | 终态 | 含义 |
|---|---|---|---|
| `pending` | 待提交 | 否 | 等槽位 |
| `submitting` | 提交中 | 否 | 已认领，正在发提交请求 |
| `running` | 生成中 | 否 | 上游已受理，轮询中 |
| `timeout` | 超时待查 | 否 | 单次轮询超时，继续复查 |
| `unresolved` | 超时未决 | 否 | 复查上限到了，等下次兜底 |
| `download_failed` | 待补下载 | 否 | 图已生成，只差取回 |
| `done` | 已完成 | **是** | 唯一「已产出」状态 |
| `no_artifact` | 未产出 | **是** | 上游没给图（多为内容审核），重跑结果相同 |
| `needs_confirm` | 待确认 | **是** | **要人点确认才继续，会扣积分** |
| `failed` | 失败 | **是** | 上游错误，重试已到上限 |

**判断完成**：`status === "done"` 且 `filesPresent[].present === true`。
**判断结束（不管结果）**：`terminal` 那五个。
⚠️ `needs_confirm` 是终态，但**任务没结束** —— 它等人；此时 `group` 是 `waiting`。

`group` 只有四个值：`active`（占槽在跑）/ `queued`（排队）/ `waiting`（待你确认）/ `finished`。

## 4. 垫图（`refs`）

| 传法 | 限制 |
|---|---|
| 公网 URL | 上游能访问即可 |
| 本机绝对路径 | 必须**绝对**（相对路径按本工具的工作目录解析，不是调用方目录） |
| `data:image/png;base64,...` | 受 body 8MB 限制 ⇒ 原图约 **≤6MB** |

三种都会走 `engine::refs` 同一套解析：落 `var/refs/`、按哈希去重、发送时上传 CDN。
**没有** `POST /refs` 二进制上传端点（大图请给路径或 URL）。

## 5. 错误码

| 码 | 含义 | 典型原因 |
|---|---|---|
| 200 | 成功 | — |
| 400 | 输入不合法 | 空 prompt、未知模型、比例/尺寸格式错、body 不是 JSON；**原话在 `error` 里** |
| 401 | token 缺失/不对 | 没带 `Authorization` |
| 404 | 没有这个端点 | 路径/方法不在两个端点内（没有 `/settings`、`/models`、**也没有 `/stop`**） |
| 413 | body > 8MB | 内联图片太大 |
| 500 | 服务端内部错误 | `/state` 构造失败等；`error` 带原话，**不会静默返回空** |

## 6. 已知限制（不做）

- **只本机**：绑 `127.0.0.1`，无 TLS、无账号体系；
- **无 CORS**：浏览器页面跨源调用会被拦 ⇒ 调用方应是**后端/桌面进程**，不是网页 JS；
- **串行**：同一刻只处理一个请求；
- **无增量 / 无 SSE**：只能轮询 `/state`；
- **无 `/models`**：模型别名在 GUI 发送面板的模型下拉里看，或用 `/state` 返回任务里的 `model` 值；
- **无按 id 查单条**：只能拉全量再过滤；
- **无 `source` 字段**：服务端不区分「这条是谁提交的」，调用方自己按 prompt / 时间认领。

## 7. 完整示例（PowerShell）

```powershell
$t = (Get-Content 'var/http-token' -Raw).Trim()

# 提交
$body = @{
  tasks = @(@{
    prompt = '一只橘猫坐在窗台，柔和侧光'
    model  = 'nano-bn-2'
    ratio  = '3:4'
    size   = '2K'
    refs   = @()
  })
} | ConvertTo-Json -Depth 5 -Compress

$r = Invoke-RestMethod -Uri 'http://127.0.0.1:17863/tasks' -Method Post `
  -Headers @{ Authorization = "Bearer $t" } -ContentType 'application/json' -Body $body
$r | ConvertTo-Json -Compress

# 轮询到完成
for ($i = 0; $i -lt 120; $i++) {
  $s = Invoke-RestMethod -Uri 'http://127.0.0.1:17863/state' -Headers @{ Authorization = "Bearer $t" }
  $task = $s.tasks | Where-Object { $_.prompt -eq '一只橘猫坐在窗台，柔和侧光' } | Select-Object -Last 1
  if ($task) {
    "status=$($task.status) files=$($task.filesPresent.file -join ',')"
    if ($task.status -in 'done','no_artifact','needs_confirm','failed') { break }
  }
  Start-Sleep -Seconds 2
}
```

## 8. 排错

| 现象 | 先查 |
|---|---|
| 连接被拒 | GUI 是否在跑；`var/http-token` 是否存在 |
| 401 | 头是否 `Bearer <token>`（大小写、空格） |
| 404 | 路径是否打错；没有 `/models` / `/settings` |
| 413 | 图片是否内联过大（改用绝对路径） |
| 提交成功但看不到任务 | 等 3~10 秒（参考图要上传）；再按 prompt 精确匹配 |
| `/state` 很慢 | 任务多（全量序列化）；降低轮询频率到 2s |
