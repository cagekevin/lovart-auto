# ADR-0010 · 可观察先于可诊断：先过必要性与可见性，再谈复杂度排序

- **状态**：生效
- **结论**：先过两问再谈排序：删掉它需求就消失的必须做；失败用户已经看得见的不许再加解释层。剩下的才按代价乘概念增量四象限排先后。可观察不等于可诊断。
- **日期**：2026-11-26
- **裁定人**：用户（「我想提这个是因为你刚刚破图那个，明明破图用户一眼就看出来了，拿非要加一堆」）
- **触发**：预设垫图取用时，图文件被删 ⇒ 我加了后端 `fs::metadata` 判存在、前端 `missing` 分支、逐张 notice、取用失败面板不关，四层；用户指出**破图本身就是可见的失败**，一层都不用加。

## 背景

同一轮里四次出现同一个错位：**我把"可诊断"当成需求，而"可观察"早就够了。**

| 现象 | 我做了什么 | 用户实际要的 |
|---|---|---|
| 预设图被删 | 判存在 + `missing` + 通知 + 面板不关（四层） | 破图，一眼看见 |
| 工作区在哪 | `LOVART_HOME` / cwd / `.app` 同级三候选 + 认目录内容 | 「软件在哪，工作区就在哪」（一个判据） |
| 跨工作区预设 | 假设用户会换工作区，写进 plan 的理由 | 「我只有这一个工作区」 |
| 清单落盘中途崩 | 编了 `.tmp` 恢复兜底 | 「错了就明说，别搞兜底」 |

根子在 ADR-0008：它说「失败必须带原因」，我把"带原因"泛化成了「处处解释」。
但 0008 的本意是**拆兜底** —— 别让失败和"没有"长得一样。破图恰恰是"长得不一样"，**已经满足 0008**。

`docs/写plan的方法-删除测试.md` §2 早有四象限，但只在写 plan 时读 —— 这个错位发生在每次动手前那一秒，文档够不着。

## 判据（它凭什么成立 / 为什么不成立）

**两问是顺序，不是并列**：

```
① 删除测试：删掉它，用户原话里哪件事做不成？
   → 第一性：必须全做，**不参与排序**（不能因为"贵"砍掉）
② 可观察测试：失败用户已经看得见吗？
   → 看得见（破图 / 空列表 / 灰按钮 / 报错弹窗）⇒ "解释层"不是需求，砍
③ 剩下的，才按「实现代价 × 概念增量」四象限：
   双低先做 · 单高先简化再做 · 双高砍掉并写进 plan 的"不做"
```

- **"复杂度"的真意是概念增量**：新增几个必须同时保持一致的东西，不是代码行数。破图那四层 = `missing` / `reason` / 通知 / 面板状态，三个新概念。
- **"功能完成度"用删除测试判**，不用百分比：能指回用户原话 = 完成；指不回 = 锦上添花。
- **边界（与既有条的关系）**：本条是 ADR-0003「同一个失败只变形一次」与 ADR-0008「先拆兜底」的**适用边界**，不替代它们。
  - 0003 的「不许静默丢图」可由**可见状态**满足 —— 破图就算"不静默"，不必须用提示满足。
  - 0008 的「失败带原因」针对**被兜底吞掉**的失败（本来不可见）；可见的失败不加解释层，**仍按 0008 带原因上报**。
  - 与本条同族但不同面：0002 管「能不能做干净」、0004 管「结构 vs 文档」、0009 管「约定落哪一级」—— 都不管「该不该做、先做哪个」。

## 决议

- 动手前**先过①②再谈排序**；四象限只是③的执行细节，不进本条正文。
- 失败状态若用户已经看得见 ⇒ **不加**第二层解释（不判存在、不弹 notice、不拦流程）。
- 第一性（用户原话）**不进四象限** —— 四象限只给非第一性排先后。
- 单高象限（代价低复杂度高 / 代价高复杂度低）⇒ **先简化**再决定做不做，不直接排期。
- 双高 ⇒ 砍掉，把理由写进对应 plan 的「不做」段。
- 落点：判据进 `docs/写plan的方法-删除测试.md` §2（四象限已有）；本条只管①→②→③的顺序与②的边界。

## 后果

- ✅ 收益：排障不再靠"我当时为什么加这层"的考古；可见的失败保持简单，复杂留给真正看不见的失败。
- ⚠️ 代价 / 回潮风险：③ 的四象限要自己判，机器挡不住（语义判断）；「保险起见加一层」的冲动会反复出现。
- 📌 违反时的判据（怎么发现"又回去了"）：
  1. 交付说明出现"为了保险加了 X"，而 X 对应的失败用户已经看得见 ⇒ 违反。
  2. 被砍项能指回用户原话，却因"贵 / 复杂"被排到后面 ⇒ 违反（第一性不参与排序）。
  3. 选了双高象限却没在 plan 的「不做」里写理由 ⇒ 违反。
  4. 拿 0003 / 0008 当"所以要加解释层"的理由 ⇒ 违反（它们管的是**不可见**的失败）。
