# 接入案例：maomao「只发送」到 lovart

> 记录日期：2026-11-20（2026-11-21 按"无认证改动 / 回执现状"订正）
> 参与仓库：`lovart-auto`（本仓，出图引擎）· `maomao`（另一个前端）
> 目标：**maomao 只负责把任务发出去**；产物由用户去 lovart 的窗口看。

---

## 1. 为什么是这个形状

maomao 是浏览器前端（Vite）+ 一个本地 Node 服务（`localTool`，端口 18080）。

- 浏览器**不能**直连 `127.0.0.1:17863`：没有 CORS，且 token 不该下发到页面；
- maomao 的架构规则：**出站唯一** = `localTool/src/utils/netProxy.ts` 的 `fetchWithProxy`；
- 用户明确：**不建任务中心记录、不轮询、不回填产物**。

⇒ 不新增 `/api/generate` 的 provider，也不做 `/api/lovart/tasks|state|stop` 一整套；
只在 localTool 加**一个发送端点**，前端加一个按钮。

## 2. 链路

```
maomao 前端（图片生成节点）
   │  POST /api/lovart/send        （同源到 localTool，不碰 token）
   ▼
maomao localTool :18080
   │  fetchWithProxy → http://127.0.0.1:17863/tasks
   │  （isLocalTarget ⇒ 直连，不走代理）
   │  Bearer token 读自 lovart-auto/var/http-token
   ▼
lovart-auto GUI :17863
   └─ 受理后入队，用户在 lovart 窗口看结果
```

## 3. 改动清单（都在 `maomao` 仓）

| 文件 | 改动 |
|---|---|
| `localTool/src/routes/lovartSend.ts` | 新端点：读 token → 转发给 `/tasks`；支持 `{tasks:[…]}` 与单条 `{prompt,…}` |
| `localTool/src/router.ts` | 注册 `POST /api/lovart/send` |
| `src/components/image/nodes/ImageGenerate.tsx` | 生成按钮左侧新增「发 Lovart」；组装参数并调用端点 |

`lovart-auto` 侧**零改动**：用的是已经存在的 `POST /tasks`。

## 4. 参数映射（节点 → lovart）

| 节点参数 | 目标字段 | 规则 |
|---|---|---|
| `prompt`（芯片解析后） | `prompt` | 直传 |
| `aspectRatio` | `ratio` | 是 `w:h` 直传；`Auto`/自定义像素时按像素约分（如 `1024×1536` → `2:3`） |
| `imageSize` / 像素长边 | `size` | `1K/2K/4K` 直传；自定义像素按长边归档（≤1280→1K，≤2048→2K，否则 4K） |
| `refImages` | `refs` | 前端给 `/files/...`；localTool 用 `resolveUploadFile` 转成**本机绝对路径**；公网 URL / `data:` 原样 |
| `count`（xN） | 多条任务 | lovart 无 count，同一条重复 N 次（id 顺延 `-2/-3`） |
| `model` | **不发** | 节点模型 id 与 lovart 别名不是一套，盲发会 400；用 lovart `.env` 默认 |
| `quality` | **不发** | lovart 无此参数（档位编码在模型名里） |

## 5. 端点契约

### maomao 自己的端点（`POST /api/lovart/send`）

请求（两种形状等价）：

```json
{ "prompt": "一只橘猫", "ratio": "3:4", "size": "2K", "refs": ["C:/…/a.png"] }
```

```json
{ "tasks": [ { "prompt": "…", "ratio": "1:1", "size": "1K" } ] }
```

响应：**原样透传 lovart**。

### lovart 的端点（`POST /tasks`）

- 成功 ⇒ `200 {"accepted":N,"receivedAt":"…"}`（受理条数 + 时间戳）；
- 失败 ⇒ `400 {"error":"…"}` / `401`（token）/ `413`（body > 8MB）。

## 6. 边界（明确不做）

- **不建任务中心记录**：没有 `/api/tasks` 写入、没有 `frontTaskId`；
- **不轮询、不回填**：节点不会收到图片；结果只在 lovart 侧；
- **不新增 `/api/lovart/tasks|state|stop`**：只用这一个发送端点；
- **不出站绕行**：localTool 内只允许 `fetchWithProxy`，不许裸 `fetch`。

## 7. 启动与验证

1. 先启动 `lovart-client.exe`（GUI）⇒ `var/http-token` 存在、17863 监听；
2. 再启动 / 重启 maomao 的 localTool（改动需要重启才生效）；
3. 冒烟（不发任务）：

   ```powershell
   Invoke-WebRequest -Method Post http://127.0.0.1:18080/api/lovart/send `
     -ContentType 'application/json' -Body '{}'
   # 预期 400（缺 prompt），说明路由已加载
   ```

4. 前端：打开图片生成节点 → 填提示词/比例/尺寸/垫图 → 点「发 Lovart」→
   弹「已提交 N 条」，去 lovart 窗口看结果。

## 8. 排错

| 现象 | 先查 |
|---|---|
| 按钮点了报 503 | lovart GUI 是否在跑；`var/http-token` 是否存在 |
| 400「模型不在别名表」 | 不应出现（当前不发 model）；若手动发了 model，改用 lovart 别名 |
| 400「比例格式不对」 | 传了 `Auto`/像素值；只发 `w:h` |
| 413 | 垫图是内联 data URL 且超过 8MB |
| 提交成功但长时间没图 | 7 并发排队；或 `needs_confirm` 需要人去 lovart 点确认 |
| 点了两次生成两张 | 设计如此：lovart 不去重，重复提交 = 再生成一张 |
