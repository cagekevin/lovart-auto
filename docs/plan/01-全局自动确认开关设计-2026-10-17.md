## 0. 结论

一个**全局持久**开关，值住 `.env`（`LOVART_AUTO_CONFIRM`），运行时由 `Arc<AtomicBool>` 承载，**切换立即生效（含正在跑的批次）**；遇到 `pending_confirmation` 自动确认并继续；历史 `needs_confirm` 不补；同一任务每批最多自动确认一次；确认失败转人工、不重试。

**一个控件**（顶栏 chip）、**一个写命令**（`set_auto_confirm`）、**一个读字段**（`get_state`）、**一份 `.env` 读写实现**（`connection.rs`）。

---

## 1. 目标与非目标

### 1.1 目标

1. 一次设置、所有批次生效（GUI 发布 / 重跑 / 接着查 / CLI）。
2. 持久：写 `.env`，重启后保持。
3. 热更新：双向立即生效（开=开始自动确认；关=立刻停止后续确认）。
4. 花钱可见：顶栏常驻状态 + 本批计数 + 批次结束告警。
5. 防跑飞：每任务每批最多一次；确认失败不重试。

### 1.2 非目标

历史 `needs_confirm` 补确认；批量确认 UI；配额闸；多实例同步；改 `TaskRecord` / `prompts.jsonl` / 状态文件 schema；新增 logger / eventBus；**设置页第二个开关**（同一件事的第二套 UI/命令面）。

## 3. 约束（为什么不能只是加个 checkbox）

1. **官方 Do NOT auto-confirm**：确认是「先告知花费 → 等用户回答」的闸门。开关必须有一次明确的后果告知。
2. **静默花钱是本仓头号缺陷**：花钱必须能对账（计数 + 告警），失败必须可见。
3. **`.env` 已是设置载体**：再加一个键是沿用，不是第二套配置。
4. **花钱只此一处**：`confirm_thread` 是唯一 HTTP 入口；自动路径是第二个调用方，不是第二个实现。
5. **成功必须为真**：开关状态、计数、告警都不能"看起来做了"。

## 4. 方案对比与决策

| | A `.env` 全局（开跑快照） | **B `.env` 全局 + 热更新** | C 独立 `settings.json` | D 全局 + 配额闸 |
|---|---|---|---|---|
| 真源 | `.env` | `.env` + 内存原子量 | 新配置文件 | 同 B + 计数 |
| 生效时机 | 下一批 | **立即（含在跑批次）** | 立即 | 立即 |
| 成本 | 最低 | 低 | 中（第二套配置） | 中高 |
| 主要问题 | **关掉也要等下一批**（安全方向失效） | 打开会立刻影响后续任务（需常驻可见） | 两处配置必然分叉 | 与"别管我"相抵 |

**决策：B。**
- A 淘汰是正确性问题：用户看到"本批自动确认 3 条"想立刻关，A 却继续确认到本批结束。
- C 淘汰：`.env` 已经住着并发数与输出目录，再开一个配置文件就是同一事实两处定义。
- D 推迟：配额闸是 B 之上的一层，不影响结构。
- 批次级开关（发布时勾选、每批复位）已否决：用户要的是全局。

## 5. 四个语义

### 5.1 全局

所有开跑路径都继承，没有"派工路径强制 false"的特例。唯一例外：历史 `needs_confirm`（5.3）。

### 5.2 热更新

- 开关值在**每次判定那一刻**读（`Relaxed`），不是开跑快照。
- 关掉：下一次 pending 立刻不确认。打开：正在跑的任务也能立刻用上。
- **不可撤回**：已发出的 `confirm` 请求撤不回；已确认的（钱已花）不可逆。

### 5.3 历史 `needs_confirm` 不补

`job: None`，不在任何队列。补确认 = 在没有批次上下文的情况下追认历史花费，还可能一次复活几十条、占满服务端 8 个槽位。开关只对"开关生效之后、轮询中遇到的 pending"负责。

### 5.4 同一任务每批最多一次

- 许可在**即将确认的那一刻**由 `AutoConfirm::decide` 发放（检查开关 + 原子占位一步完成）。
- 用掉后（含确认失败）本批再遇到 pending 一律转人工。
- 许可作用域 = 一个 `run_scheduler` 调用；重跑 / 接着查 / 人工确认后的单跑都是**新批次**（用户明确要求再跑，许可重置是合理的）。

## 6. 机制要点（为什么这么收口）

1. **一个结构，不是散装字段**：`AutoConfirm { enabled, confirmed, attempted }`。开关是全局的，计数与许可是**批次**的；三者放一起，避免"两个 Arc + 一个集合 + 一个局部标志"四处漂。
2. **协议层不碰策略**：`poll_thread` 只收 `allow` 回调 + 计数引用，不知道 `.env`、不知道 UI。`AutoConfirmDecision` 三态定义在协议层，由调度层构造。
3. **三态而不是 bool**：`Disabled`（开关关）与 `AlreadyUsed`（本批已用过）对用户是两句不同的话；压成 bool 就只能写含糊的兜底话。
4. **计数在确认成功那一刻落**：不经过返回值。轮询后面超时 / 取消 / 报错都不丢账。
5. **确认失败不重试**：请求可能已在服务端生效，重试 = 重复扣费风险；宁可转人工。
6. **`.env` 规则只有一份**：读、写、行识别都在 `connection.rs`，`update_env_keys` 与 `parse_dot_env` 共用行识别。否则 `export KEY=…` 会让开关**静默不生效**并每次多一行。
7. **`.env` 是唯一真源**：系统环境变量不参与。一个看不见的变量不能推翻用户在界面上点的开关（密钥仍允许环境变量优先——那是部署需要，两者语义不同）。
8. **写盘成功后才改内存**：否则界面显示开、磁盘是 false，重启悄悄变回去。
9. **一处 pending 逻辑**：status 与 result 两个分支共用一个 `resolve_pending`，不再抄两遍。
10. **不 reload 环境变量**：切开关只写文件 + 存原子量；`reload_dot_env` 是进程级全局改写，为一个开关动它没有收益。

---

## 7. 不变量（施工自检）

1. 缺键 / 非法值 / 读失败 / 未配置 ⇒ **关**。任何情况下不默认开。
2. 只有 `pending_confirmation` 触发自动确认；其它错误绝不自动重试花钱。
3. 同一任务每批**最多一次**（`decide` 占位），跨重试/超时复查都成立。
4. 确认请求失败 ⇒ 转人工，**不重试**。
5. 关掉后不再产生新的确认；在途请求不撤回。
6. 历史 `needs_confirm` 永不被自动补确认。
7. 确认后仍走 `running → … → done` 原状态机。
8. 计数在 confirm 成功那一刻落，与轮询收场无关。
9. 开关只认 `.env` + CLI 显式参数；环境变量不参与。
10. 自动确认条数必须可见（chip 计数 + 批次告警），否则就是静默花钱。

## 8. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 重复扣费（确认超时后重试） | 失败即转人工，不重试 |
| 上游反复要确认，额度被烧穿 | 每任务每批一次许可 |
| 跑批中打开影响后续任务，用户没注意 | 顶栏常驻警示色 + 本批计数 + 开启时一次说明 |
| 系统环境变量悄悄推翻 UI 开关 | 只读 `.env` |
| 计数随轮询错误丢失 | 成功即落账，不经返回值 |
| 保存设置与切开关并发覆盖 | `env_lock` 串行化 |
| `export` / 空格写法导致开关不生效 | 读写共用同一行识别规则 |
| 无逐条报价 | 开启时明确告知；卡片仍可人工确认看报价 |
| 多实例 | 不支持；`.env` 后写覆盖先写，行为确定 |

## 9. 后续（本次不做）

1. **批量确认**：`needs_confirm` 组多选 → 逐条报价 → 一次确认。
2. **配额闸**：每批/每天最多自动确认 N 条，超限降级人工。
3. **审计文件**：把每次自动确认的 id / 时间 / 上游原文追加到 `var/auto-confirm.log`。
