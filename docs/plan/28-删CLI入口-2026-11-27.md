# 删 CLI 入口：只留 GUI + 本机 HTTP · 施工契约

> 状态：**可施工**（2026-11-27，用户已裁定）
> 用户裁定：
> 1. 「我准备删掉 cli 模块，因为我们现在已经通过 curl 和 gui 已经满足需求了，cli 目前是多余的」
> 2. 「cli 我完全就不要，你说那个 status 我觉得也用不上」
> 3. 「那自检也不需要，ai 完全不需要 cli 了」
> ⇒ **整条 CLI 删除，不保留任何子命令**（`--check` / `--status` / `--list-models` / `--status-table` 全删）。
> 判据：ADR-0001（一处样本）· ADR-0005（一个能力一个入口）· ADR-0008（数据链不清不许动手）

---

## 1. 第一性问题

> **删掉 CLI 之后，同一能力是否只剩一个入口？**

CLI 的每一项能力，删掉后都要能回答「用户/其他程序从哪做这件事」：

| CLI 能力 | 删后从哪做 | 判定 |
|---|---|---|
| 跑批（`--prompts`） | GUI「发送」/ `POST /tasks` | **真重复** ⇒ 删 |
| 看状态（`--status/--json/--full`） | GUI 看板 / `GET /state` | **真重复** ⇒ 删 |
| 列模型（`--list-models`） | GUI 发送面板的模型下拉 | **真重复** ⇒ 删 |
| 状态表（`--status-table`） | **没有替代** | 删 = 删能力（用户裁定「用不上」） |
| 离线校验（`--check`） | GUI 编辑区校验（`validate_draft`）；`POST /tasks` 提交时也拦 | **等价** ⇒ 删（用户裁定「自检也不需要」） |

> ⚠️ `--check` 的等价性论证：`validate_draft`（`gui.rs:292`）与 `--check` 走**同一个**
> `parse_prompts` + `ParseOptions::default()`；`POST /tasks` 走 `tasks_from_inputs`
> （`service/api.rs:35`），同样在开跑前拦非法字段。删掉 `--check` **不丢失校验能力**，
> 只是不再有「命令行一次校验一个文件」这个用法。

**不新增任何模块**。删掉的 1048 行不留空壳（ADR-0001：不留半套）。

### 3.3 README 的形状收口

删完只剩两条入口：
1. **人**：双击 `lovart-client.exe` → GUI；

`prompts.jsonl` 字段表**保留**（GUI 导入与 HTTP `POST /tasks` 用同一契约）。
