# 删 CLI 入口：只留 GUI + 本机 HTTP · 施工契约

> 状态：**可施工**（2026-11-27，用户已裁定全部问题）
> 用户裁定：
> 1. 「cli 我完全就不要，你说那个 status 我觉得也用不上」
> 2. 「那自检也不需要，ai 完全不需要 cli 了」
> 3. 「按删处理，把他变成文档也可以。因为他的价值就是文档」
> 4. 「其他该收敛的如何收敛」「如何删的干净，下个 ai 完全不用被误导」
> 判据：ADR-0001（一处样本）· ADR-0005（一个能力一个入口）· ADR-0008（数据链不清不许动手）

---

## 1. 第一性问题

> **删掉 CLI 之后，同一能力是否只剩一个入口？**

| CLI 能力 | 删后从哪做 | 判定 |
|---|---|---|
| 跑批 `--prompts` | GUI 发送 / `POST /tasks` | 真重复 ⇒ 删 |
| 看状态 `--status` | GUI 看板 / `GET /state` | 真重复 ⇒ 删 |
| 列模型 `--list-models` | GUI 发送面板的模型下拉 | 真重复 ⇒ 删 |
| 离线校验 `--check` | GUI 校验（`validate_draft`）+ 提交时拦（`tasks_from_inputs`） | 等价 ⇒ 删 |
| **状态表 `--status-table`** | 信息本来就在 `engine/state.rs::STATUS_TABLE`（对外契约部分已在接入指南） | **删命令，不补文档** |

### 1.1 `--status-table` 的处理：**删掉命令，信息留在代码里**

`--status-table` 打印的是 `STATUS_TABLE` 的渲染结果。删掉它之后：

| 那些信息 | 在哪 |
|---|---|
| 10 个状态、wire 名、label、是否终态 | `engine/state.rs::STATUS_TABLE`；对外契约部分已在 `docs/接入指南 §3`（这是给人读的，人维护） |
| 占槽位 / 再跑一次 / 界面动作 / 异常说明 | `StatusRow` 各字段的注释（`state.rs:160-193`），改代码就能看到 |

**不做的事**：不新建文档、不把 4 个实现细节抄进文档、不写任何「文档与代码一致」的检查。
文档由人维护；它和代码对不上时，以代码为准。

## 3. 收敛（「该收敛的如何收敛」）

### 3.1 状态知识只有一处

```
engine::state::STATUS_TABLE    ← 唯一真源（代码）
        │
        ├─→ docs/接入指南 §3      ← 对外契约（人写人维护）
        └─→ docs/详细说明:38      ← 只放指针，不抄表
```

删掉 CLI 后 `详细说明:38` 那句「随时可打印 `./lovart-client --status-table`」失效，
改成指向 `STATE` 表所在的代码文件。

### 3.2 `src-tauri` 的形状

```
main.rs    22 → ~10 行
lib.rs     39 → 37 行
gui.rs     1934 行（不变）
http.rs    311 行（不变）
```

删掉的 1048 行**不留空壳**。

### 3.3 删后数据链（ADR-0008：先摆清再动手）

```
data/inbox/*.jsonl  → GUI 导入 / POST /tasks
                    → engine::scheduler 提交
                    → data/var/state.jsonl（FileLock 单写者，不变）
                    → data/output/ + data/var/report.csv + data/var/run.log
```

**`report.csv` 照旧写**：它由 `Workbench::ensure_scheduler` 传 `report_file: Some(cwd.join("var/report.csv"))`
进调度器（`service/workbench.rs`），实现是 `engine::report`——**与 CLI 无关**。
`run.rs::resolve_refs` 只是 `service::refs::resolve_refs_core` 的薄封装，删它不动参考图链。

⇒ 删 `run.rs` 后**数据链一个环节都不变**，只是少了「命令行触发」这一个入口。

### 3.4 `run.rs` 不需要下沉任何东西

| 函数 | 判定 |
|---|---|
| `resolve_refs` | 薄封装 `service::refs::resolve_refs_core` ⇒ 随文件删 |
| `print_status` / `print_models` / `print_status_table` | CLI 文本渲染 ⇒ 删（表格价值转入 §1.1 文档） |
| `install_sigint_handler` / `print_summary` / `pad_label` / `count_of` | CLI 专属 ⇒ 删 |

⇒ core 早是真相，`run.rs` 只是适配层。

### 3.5 「下个 AI 不被误导」的具体做法

| 手段 | 内容 |
|---|---|
| 结构上删净 | 文件不存在 → `cargo check` 立刻红，不可能误用 |
| 文档不留悬空指针 | `grep "lovart-client --"` 全仓 = 0 |
| `详细说明` 不留死命令 | 「随时可打印」改成指向代码里的 `STATUS_TABLE` |
| 注释不留旧名 | README/AGENTS 里 `run.rs`/`cli.rs` 的 Map 条目删掉 |

## 7. 验收（分环）

| 环 | 命令 | 过法 |
