# 删 CLI 入口：只留 GUI + 本机 HTTP · 施工契约

> 状态：**可施工**（2026-11-27，用户已裁定全部问题）
> 用户裁定：
> 1. 「cli 我完全就不要，你说那个 status 我觉得也用不上」
> 2. 「那自检也不需要，ai 完全不需要 cli 了」
> 3. 「按删处理，把他变成文档也可以。因为他的价值就是文档」
> 4. 「其他该收敛的如何收敛」「如何删的干净，下个 ai 完全不用被误导」
> 判据：ADR-0001（一处样本）· ADR-0005（一个能力一个入口）· ADR-0008（数据链不清不许动手）

---

## 1. 第一性问题

> **删掉 CLI 之后，同一能力是否只剩一个入口？**

| CLI 能力 | 删后从哪做 | 判定 |
|---|---|---|
| 跑批 `--prompts` | GUI 发送 / `POST /tasks` | 真重复 ⇒ 删 |
| 看状态 `--status` | GUI 看板 / `GET /state` | 真重复 ⇒ 删 |
| 列模型 `--list-models` | GUI 发送面板的模型下拉 | 真重复 ⇒ 删 |
| 离线校验 `--check` | GUI 校验（`validate_draft`）+ 提交时拦（`tasks_from_inputs`） | 等价 ⇒ 删 |
| **状态表 `--status-table`** | **`docs/接入指南 §3` 已有的那张表**（补齐 4 列） | **转文档 ⇒ 删** |

### 1.1 `--status-table` 转文档：不新开第三处

**现状**（已核实）：

| 位置 | 内容 | 是否漂移 |
|---|---|---|
| `engine/state.rs::STATUS_TABLE` | 真源，10 行 × 12 字段 | — |
| `docs/详细说明.md:38` | **刻意不抄表**，只给指针（原因：历史上第 4 列漂移过） | 正确 |
| `docs/接入指南 §3` | 已有一份 10 行表（`status` / `label` / 终态 / 含义） | **当前与代码一致**（已逐行核对） |

⇒ 做法：**把 `--status-table` 独有的 4 列补进接入指南 §3**（占槽位 / 再跑一次 / 界面动作 / 异常说明），
**不新建文档**，`详细说明` 那句「随时可打印」改成指向接入指南。

**防漂移（这是关键）**：文档表靠人维护必然漂（本仓付过代价）。所以补一条**测试**：
`src-tauri/tests/state_invariants.rs` 已有 `STATUS_TABLE.len() == 10`；
再加一条**逐行比对文档表与 `STATUS_TABLE`**（读 md 文件、按行匹配 `wire` / `label` / `terminal`）。
让「文档抄错」这件事变成**测试红**，而不是靠自觉。

## 3. 收敛（「该收敛的如何收敛」）

### 3.1 状态知识收成「一份真源 + 一份文档 + 一条测试」

```
engine::state::STATUS_TABLE    ← 唯一真源（代码）
        │
        ├─→ docs/接入指南 §3      ← 唯一文档（人读 / 外部接入方读）
        │        ▲
        │        └── 测试逐行比对（state_invariants.rs）⇒ 漂了就红
        │
        └─→ docs/详细说明:38      ← 只放指针（不抄表）
```

**三处的关系**：真源唯一、文档唯一、指针唯一。没有第二份表。

### 3.2 `src-tauri` 的形状

```
main.rs    22 → ~10 行
lib.rs     39 → 37 行
gui.rs     1934 行（不变）
http.rs    311 行（不变）
```

删掉的 1048 行**不留空壳**。

### 3.3 `run.rs` 不需要下沉任何东西

| 函数 | 判定 |
|---|---|
| `resolve_refs` | 薄封装 `service::refs::resolve_refs_core` ⇒ 随文件删 |
| `print_status` / `print_models` / `print_status_table` | CLI 文本渲染 ⇒ 删（表格价值转入 §1.1 文档） |
| `install_sigint_handler` / `print_summary` / `pad_label` / `count_of` | CLI 专属 ⇒ 删 |

⇒ core 早是真相，`run.rs` 只是适配层。

### 3.4 「下个 AI 不被误导」的具体做法

| 手段 | 内容 |
|---|---|
| 结构上删净 | 文件不存在 → `cargo check` 立刻红，不可能误用 |
| 文档不留悬空指针 | `grep "lovart-client --"` 全仓 = 0 |
| `详细说明` 不留死命令 | 「随时可打印」改成「见接入指南 §3」 |
| 注释不留旧名 | README/AGENTS 里 `run.rs`/`cli.rs` 的 Map 条目删掉 |
| 状态表防漂 | 测试逐行比对文档 ↔ `STATUS_TABLE` |

## 8. 删除测试

| 构造 | 删掉它需求还在吗 | 结论 |
|---|---|---|
| `cli.rs` / `run.rs` | GUI/HTTP 都不依赖 | 删 |
| `--check` | GUI 校验 + 提交校验覆盖 | 删 |
| `--status-table` 打印 | 价值转文档 ⇒ 需求仍在 | 删命令，**留文档** |
| 接入指南 §3 状态表 | 外部接入方判断完成/结束要用 | **留**（补齐 4 列） |
| 文档↔代码比对测试 | 删掉 ⇒ 表会漂（本仓付过代价） | **必做** |
| 新建第二份状态表文档 | `详细说明` 刻意不抄表已裁定 | **不做** |
| 保留半个 `cli.rs` | 没人调 ⇒ 死代码 | **不做** |

## 9. 怎么撤

- 文档：同 commit 回退；
