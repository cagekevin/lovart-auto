# 草稿通道：外部递送来，人确认后才开跑

> 状态：**已实现**（2026-11-21；步骤 4 待 GUI 手工验证，见 §14）
> 基线：`HEAD 8833cdd`（HTTP 两端点：`/tasks`、`/state`；`/stop` 已移除，见 plan 16 §18）
> 前一版被撤回，原因见 §11（载荷爆炸 / 误删新草稿 / 转换堵住串行 HTTP）

---

## 0. 需求（一句话）

**外部程序可以把任务递送进来；它落在编辑窗的「待发」里，人看过、改过、删过之后点「发布」，任务才真正入队开跑。**

| 端点 | 语义 | 写 `state.jsonl` | 会开跑 | 谁有"开跑权" |
|---|---|---|---|---|
| `POST /tasks`（已有，不改） | 直接提交 | ✅ | ✅ | 外部 |
| `POST /drafts`（本 plan） | 只递送 | ❌ | ❌ | **人** |

## 1. 第一性

> **「谁有权让机器开始花钱？」——人。**

草稿通道的全部理由就是把"开跑"从外部程序手里收回给人。由此三条是**归属**，不是限制：

1. 草稿**不是任务**：不写 `state.jsonl`、不进调度器、不占槽、不影响看板；
2. 草稿**不自动开跑**：外部只有"递送"；
3. 草稿是**递送中**的东西：进程结束就没了（落盘是另一种能力，本 plan 不做）。

## 2. 形状

### 2.1 内存形状

```rust
pub struct Draft {
    pub id: String,            // d-<序号>，收到时生成，永不复用
    pub task: TaskInput,       // 就是 intake::TaskInput，不改字段名
    pub refs_state: RefsState, // 见 §2.4
}

pub enum RefsState {
    Ready,                     // 路径已确认可读（前端能显示）
    Unavailable(String),       // 读不到 / 不是文件；原因要能给人看
}

pub struct DraftsStore {
    items: Vec<Draft>,
    seq: u32,
}
```

- `DraftsStore` 挂在 `Workbench` 上（`Mutex<DraftsStore>`），**只在内存**；定义在 `service::workbench`（字段私有，方法必须同文件，否则要开 `pub(crate)` 后门）；
- **唯一写入口**：`Workbench::draft(tasks)`（HTTP、将来的 CLI 都只能调它）。
- `Draft` 序列化给 `get_drafts`：`{ id, …task, refsState }`（`#[serde(flatten)]`）——前端 `{...d, draftId: d.id}` 直接就是队列项，不用再映射字段；
- `RefsState` 序列化：`"ready"` / `{"unavailable": "原因"}`。

### 2.2 对外形状

| 面 | 形状 |
|---|---|
| HTTP `POST /drafts` | body **必须** `{ "tasks": [ { … } ] }`；成功 **204** 空 body；401（token 缺/错）/ 400（body 不合法）。**空 prompt 不拦**（发布时 `tasks_from_inputs` 会拦） |
| Tauri 命令 `get_drafts()` | 返回**全部草稿**（refs 是绝对路径），**按需调用**，不进 `get_state` |
| Tauri 命令 `clear_drafts(ids: Vec<String>)` | **按 id 删**：删单条传 `[id]`，发布成功后清"本次发出去的"，不是全清 |
| 前端队列项 | `{ …task, draftId? }`（`TaskInput` 无 `deny_unknown_fields` ⇒ 多带无害） |

### 2.3 为什么草稿**不进** `get_state`（前一版的错）

`get_state` 是**3 秒**一次的全量看板快照（`ui/app.js:498` `REFRESH_MS = 3000`；2026-11-09 由 1 秒改来）。草稿塞进去有两个致命后果：

1. 草稿的 `refs` 带 `data:` 时一条就是 13MB（10MB 图 ⇒ base64）⇒ 每轮全量下发 ⇒ **界面卡**（这正是 2026-11-21 实测"发 25 条卡 3 秒"的形状）；
2. 前端拿到草稿后**已经**并进本地队列了 ⇒ 后端再重复发一遍是纯浪费。

⇒ 草稿走**独立命令**，前端只在需要时拉一次。

### 2.4 垫图：一律落成"前端能显示的形式"（三种输入都收）

`TaskInput.refs` 的契约本来认三种（`prompt.rs:26`：路径 / URL / `data:`）。草稿收到时逐个归一：

| 输入 | 处理 | 复用 |
|---|---|---|
| 本机路径（绝对 / 相对 / `file:`） | 归一成绝对路径 + stat | `engine::refs::resolve_local_ref`（从 `local_file_entry` 抽出，发布链共用） |
| `data:` | 落盘成 `var/refs/<哈希>` 路径 | `engine::refs::materialize_data_url`（既有；**反方向**，不是被删掉的"文件→data:"） |
| `http(s):` | 原样存 | 前端 `refSrc` 认、发布链认 |

```
归一后草稿里只有"路径 / URL"
   → 载入编辑窗 / 待发队列都能显示、能改   ← applyDraft / addRefs / renderQueue 既有
   → 发布时读盘 → data: → 上传            ← engine::refs::read_ref_inputs（既有，不动）
```

- **不需要"文件 → data:"**：前端 `refSrc`（`ui/app.js:1338`）认本机路径，`tauri.conf.json:26` 的 `assetProtocol.scope = ["**"]` 让任意路径可显示；发布链 `read_ref_inputs`（`engine/refs.rs:178`）本来就读盘转 `data:`。草稿存路径与「本地选图」（存 `var/refs/<哈希>` 路径）**同构**。
- **不拒收任何合法输入**：三种都收；只有"路径读不到 / `data:` 解不开"才标 `Unavailable`。
- **`data:` 落盘失败** ⇒ `Unavailable(原因)`（不静默保留 13MB 常驻内存）。
- **读不到 / 不是文件** ⇒ `RefsState::Unavailable(原因)`，**前端要看见**（不许静默丢图）；存在性在**收到草稿时**就查一次（正确性：否则人看到白板不知道原因，发布时才发现）。
- **锁内不做 I/O**：归一（stat / 落盘）在草稿锁**外**做，进集合只 push。

### 2.5 前端什么时候拉草稿（到达通知）

草稿存路径 ⇒ `get_drafts()` 的载荷是几百字节/条（不是 13MB）。所以**跟着看板刷新一起拉**：

```
refreshBoard()（3 秒一轮）→ 顺带 invoke('get_drafts')
   → 按 id 去重并进待发队列
   → 返回里没有的 draftId 从队列移除（别人删了 / 已经发掉）
```

- **只有带 `draftId` 的队列项参与联动移除**：人手动加的任务没有 `draftId`，不受影响；
- **必须放在 `refreshBoardOnce` 的 `data.unchanged` 早退之前**：草稿不在 `get_state` 指纹里，空闲时每轮都是 `unchanged`，放早退之后就永远拉不到；
- **不用 Tauri 事件**：多一条订阅生命周期，收益为零（3 秒延迟已够）；
- **不把草稿塞进 `get_state`**：那会让草稿变化触发看板全量重算（§2.3）。

## 3. 多来源、单一出入口

| 来源 | 怎么进来 |
|---|---|
| 外部 HTTP（maomao / 其他 AI） | `POST /drafts` |
| 将来 CLI / GUI 内部 | 直接调 `Workbench::draft()` |

**三条禁令**：

1. 除 `Workbench::draft` 外，任何地方不许往草稿里加东西；
2. 除 `DraftsStore` 外，任何地方不许持有草稿集合；
3. 草稿只有一份内存副本，`get_drafts` / 命令都读它。

## 6. 两个设计点（2026-11-21 用户已裁定）

> 裁定原话：「**别牺牲我改垫图，改提示词的能力**」⇒ 草稿必须能载入编辑窗、改完再发。

| # | 问题 | 结论 | 依据 |
|---|---|---|---|
| **A** | 垫图要不要在服务端转成 `data:` | **不转，存绝对路径** | 前端 `refSrc`（`ui/app.js:1338`）认本机路径，`assetProtocol.scope = ["**"]`（`tauri.conf.json:26`）⇒ 编辑窗与待发队列都能显示；发布链 `read_ref_inputs` 读盘。转 `data:` 只多一个状态机与每张 13MB 内存，能力零增加 |
| **B** | 「编辑」回填要不要做 | **做，且是必做** | 用户原话；复用 `applyDraft(队列项)` 即可（`Draft` 已 `#[serde(flatten)]`，`TaskInput` 的 `model/ratio/size/refs` 与 `applyDraft` 入参同形），芯片回写走既有 `writePrompt`，**不需要新写** |

> 前一版把"只能看/删/发"当最小版是错的：那等于砍掉用户要的核心能力。**最小切片 = 递送 + 载入编辑窗（改提示词/改垫图）+ 删 + 发。**

## 7. 施工步骤（每步绿了再下一步；每步可单独回滚）

| 步 | 内容 | 验收 | 回滚 |

## 9. 失败语义

| 情形 | 行为 |
|---|---|
| token 缺/错 | 401（同 `/tasks`） |
| body 不合法 | 400 + 原话 |
| 垫图路径读不到 / 不是文件 | 草稿保留、`Unavailable(原因)`、**前端显示出来**；发布时既有链仍会再报一次 |
| `data:` 落盘失败 | 同上：`Unavailable(原因)`、草稿保留、前端显示 |
| 多张大图 | 路径只 stat、`data:` 只解码落盘（都是本地小操作），没有"转换很慢" |
| 发布失败 | 不清草稿、不清队列 |
| 发布成功 | 按本次 `draftId` 清草稿（**不全清**） |
| 关 GUI | 草稿消失（内存）；**不做提示**（用户已定） |

## 10. 不做（本 plan 不新增）

- 不挑选 / 全选 / 只发所选；
- 不分批入队；
- 不设数量上限；
- 不自动发布、不做草稿超时清理；
- 不做草稿持久化；
- 不新增图片路由（垫图靠本机路径，前端 `convertFileSrc` 显示）；
- 不改 `/tasks` 的响应与认证；
- 不做垫图转换（不读盘、不转 base64；草稿存路径）；
- 不新增 Tauri 事件订阅（到达靠 3 秒刷新顺带拉，§2.5）。

## 11. 前一版为什么被撤回（决策留痕）

| # | 问题 | 后果 | 本版怎么改 |
|---|---|---|---|
| 1 | 草稿（含 base64 垫图）每轮进 `get_state` | 每轮 13MB 载荷 ⇒ 界面卡（`get_state` 实为 3 秒一轮） | 草稿走独立命令（§2.3 / §2.5） |
| 2 | 发布成功调 `clear_drafts()` **全清** | 把发布期间新到的草稿一起清掉 ⇒ 静默丢 | 按本次 `draftId` 清（§2.2 / T7） |
| 3 | 垫图转换在 HTTP 请求线程同步做 | 串行服务器被堵 2–3 秒 | 不做转换：草稿存路径，前端直接显示（§2.4 / §6-A） |
| 4 | 转换失败静默降级 | 人看不到图，也没人知道 | `RefsState::Unavailable(原因)` 前端可见 |
| 5 | 草稿功能 0 单测 | "全绿"只是因为没覆盖 | §8 列 9 条必写用例 |
| 6 | 最小版把"载入编辑区"砍掉 | 用户不能改提示词/改垫图 | 用户裁定：**必做**（§6-B），复用 `applyDraft` |

## 13. 删除测试（每个新构造为什么必要）

| 备选 | 为什么不用 |
|---|---|
| 草稿进 `get_state` | 每轮重复下发 + base64 载荷炸界面（前版 P0-1） |
| 发布后全清草稿 | 会静默丢掉发布期间新到的草稿（前版 P0-2） |
| HTTP 里同步转垫图 | 串行服务器被大图堵住（前版 P0-3） |
| 新写 `engine::refs::file_to_data_url` | 仓库已有 `local_file_entry`（读盘 → `data:`，`refs.rs:78`）；前端 `refSrc` 也能直接显示路径 ⇒ 写了就是第二份 |
| 转换失败静默保留路径 | 人看不到图、也没人知道（P1） |
| 草稿落盘 `var/drafts.jsonl` | 用户已定：临时递送，重启即没 |
| `/tasks?mode=draft` | 同一端点两种语义，调用方要记参数 |
| 前端 localStorage | 外部进程发不到前端 |
| 草稿写进 `state.jsonl` | 会进看板与断点续跑，草稿就不是草稿 |
| 独立草稿列表 UI | 现成「待发队列」能承载（还自带缩略图与摘要） |
| 把「载入编辑区」砍成 B2 | 用户原话否掉：改提示词/改垫图是核心能力 |
| HTTP 直接往队列 push | 会长出第二套校验/落盘/id 生成 |
