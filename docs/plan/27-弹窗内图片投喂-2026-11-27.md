### 0.3 用户裁定（2026-11-27，拖放方案）

> 原话：「方案3合理，拖放一条路，粘贴一条路，又不是说非要把两个不同的事情要一条路，
> 而且更重要的是这个不会让后面ai看不懂，他不会被误导才是最主要的」

**两条通道，各自一条路，不合并**：

| 通道 | 谁来 |
|---|---|
| **粘贴** | 网页层 HTML5 `paste` → `ImageIntake.installPaste` → `routePastedFiles` |
| **拖放** | Tauri `onDragDropEvent` → `wireDropZone` → `routeDroppedPaths`（按**鼠标坐标**命中弹窗） |

**为什么拖放不能走网页层**：窗口没关 `dragDropEnabled`（Tauri 2 默认开），
WebView2 **不向网页派发** drag/drop ⇒ 挂 DOM 的 `drop` 监听永不触发（2026-11-27 实测：
拖进预设仍落主编辑区）。**这条写进 `ui/imageIntake.js` 文件头**，
防止下一个 AI 又往那里加 `drop` 监听。

## 1. 第一性问题

> **弹窗打开时，拖入 / 粘贴的图片能不能落进「当前弹窗」，而不是一律进编辑区？**

去掉它 ⇒ 只能点「＋」选文件，或关弹窗再去编辑区 ⇒ 需求消失。唯一第一性。

**同一条链上必然一起收的**：「图片摄入」现在三份（§0.2 第 2 行），其中 composer paste 那份是整条重写。
要加拖入就必须回答「新代码放哪一份里」——三个答案都在（所以只能收成一份）。

## 2. 最小切片

一次拖入（或粘贴）1 张图到**素材库弹窗**：图进网格、面板不关、编辑区垫图不变。
预设编辑态同样 1 张：图进图片条。

## 3. 形状与数据链

### 3.1 两条通道，互不合并（用户裁定 2026-11-27）

```
① 粘贴（网页层 HTML5）
   paste → ImageIntake.readPastedFiles(event) → File[]
        → admitFiles(files)          裁剪 + 唯一播报
        → routePastedFiles(files)    按弹窗 hidden 选落点
        → addLibraryImages / addPresetImages / addRefs

② 拖放（Tauri 通道；网页层**收不到** drop 事件）
   onDragDropEvent(drop) → { paths, position }
        → routeDroppedPaths(paths, position, dpr)
        → maskAtPoint(position, dpr) 命中可见弹窗？
             是 ⇒ 直接用 paths（本机绝对路径，不读内容）
             否 ⇒ addRefs(paths)（老行为）
```

**为什么必须两条**：窗口没关 `dragDropEnabled`（Tauri 2 默认开），WebView2 不向网页派发
drag/drop ⇒ 挂 DOM 的 `drop` 监听是**永不触发的死代码**（2026-11-27 实测：拖进预设仍落主编辑区）。
粘贴与拖放本来就是不同事件源、不同数据形态（`File` vs 本机路径），硬合并才是造抽象。

**落点入参统一成「来源」**：`[{ kind:'path'|'data', value }]`
—— 粘贴给 `{kind:'data'}`（File → data:），拖放给 `{kind:'path'}`（不白读大图）。
`toImageInputs` 一处转成后端能收的字符串数组（`ImageSource` 两种都认）。

### 3.2 模块边界：`ui/imageIntake.js` 只管粘贴

| 导出 | 作用 |
|---|---|
| `readPastedFiles(event)` | clipboard → `File[]` |
| `limitFiles(files,max,maxBytes)` | 裁剪（纯函数，返回 rejected 数据） |
| `readAsDataUrls(files)` | `File` → `data:`（全工具唯一转换点） |
| `installPaste({zone,accept})` | 只绑 `paste` |

**刻意不导出** `readDroppedFiles` / `install`：拖放不在网页层。
测试有一条断言守着这点（`模块不导出拖放函数（拖放不走网页层）`），
文件头也写明「这里没有拖放，别在这加」——**防下一个 AI 找错门**。

**依赖方向**：本模块不 import / 不调用 `app.js`（不 `notice`、不碰 DOM 状态）⇒ 可纯单测。

### 3.3 `maskAtPoint`：拖放落点的唯一判据

`position` 是 Tauri 的**物理像素**，`getBoundingClientRect` 是 CSS 像素
⇒ 除以 `devicePixelRatio` 才能比；不换算的话 2x 屏偏一倍。

落点由**鼠标实际位置**决定，不是「弹窗开着」：弹窗开着但把图拖到编辑区 ⇒ 进编辑区。

### 3.4 旧代码去向

| 旧代码 | 本轮 |
|---|---|
| `readFilesAsDataUrls`（`:2079-2090`） | **搬进** `ImageIntake.readAsDataUrls`；4 个调用点改调模块 |
| `clipboardImagePaths`（`:2039-2051`） | 改成调 `ImageIntake.readPastedFiles`；**adapter 契约不变**，插件零改动 |
| composer paste（`:3693-3709`） | **删净**，改调 `routePastedFiles`；text 分支原样保留 |
| `routeDroppedPaths` | **改签名** `(paths, position, dpr)`；加 `maskAtPoint` 命中判断 |
| `MAX_PASTE_IMAGES` / `MAX_PASTE_BYTES` | 留在 `app.js`（常量归业务）：粘贴传 `limitFiles`（数量+体积），拖放传 `limitPaths`（**只卡数量**，路径无 `size`，体积交后端 `materialize_image` 的 64MB 闸） |

### 3.5 失败归属（ADR-0003）

| 失败 | 产生 | 播报 | 次数 |
|---|---|---|---|
| 超数量 / 超体积 | `limitFiles` 返回 `rejected` | `admitFiles`（唯一） | 1 条/次 |
| 读不出文件 | `readAsDataUrls` 抛 | 落点 catch（库/预设已有，composer 补） | 1 条/次 |
| 存库/存预设失败 | 后端 `reason` | `libraryMessage`/`presetMessage` | 1 条/次 |
