## 1. 第一性问题（一句话）

**`gui.rs` 里的编排（提交 / 停止 / 看板）只存在于 Tauri 适配层，没有任何「非 GUI 入口」能调到它 —— 第二个前端要么复制一份 `publish`，要么无法提交。**

## 2. 每条约定的落点（`ADR-0009`：先问能不能编译不过）

| # | 约定 / 错误路径 | 能编译不过？ | 落点 |
|---|---|---|---|
| 1 | service 里 `use tauri` | **能**：`lovart-core` 没有 tauri 依赖 ⇒ **E0432** | 级 1 |
| 2 | service 依赖 `run::resolve_refs_core` | **能**：core 里没有 `run` 模块 ⇒ `use crate::run` 编译不过；`resolve_refs_core` 下沉 **`service::run`**（上传编排属提交，解析/缓存仍在 `engine::refs`） | 级 1 |
| 3 | gui 命令直接读写 `Workbench` 字段 | **能**：字段私有 ⇒ **E0616**（`Board` / `Config` 在 service 内部，不受影响） | 级 1 |
| 4 | 看板出现第二条投影（`get_state` 与 `snapshot` 各算一遍） | **能**：只有 `snapshot(since)` 一个方法，**没有第二个解析函数**；`payload: Option<Value>` 是判别位 | 级 1 |
| 5 | HTTP 拿到 `unchanged`（`since` 由 HTTP 自己存） | **不能**：`snapshot(Some(key))` 类型上允许任何调用方传 | **级 2**：唯一范本 —— HTTP 的 `snapshot` 调用点只写 `None`；没有状态可存 |
| 6 | HTTP 暴露 `save_settings` / 消耗开关 | **能**：路由是穷尽 `match` 的枚举，没有该分支 ⇒ `_ => 404`，代码里无可执行路径 | 级 1 |
| 7 | `/state` 并发打满机器 | **能**：监听循环串行，不 `spawn` ⇒ 无并发、无锁、无锁中毒 | 级 1 |
| 8 | 停止后报 `stopped`（假话） | **能**：`StopAck` 只有 `note`，响应体里没有 `stopped` 可返回 | 级 1 |
| 9 | `engine` 反向 `use service`（同 crate） | **不能**：Rust 同 crate 模块互引合法，crate 边界只挡 tauri | **级 3**：写明"靠评审 + 单向范本"，不假装结构 |
| 10 | body > 8MB | 不能（运行时输入） | 级 3 |
| 11 | token 读 / 写失败 | 不能（文件系统行为） | 级 3：显式失败 |
| 12 | 端口冲突 / 读超时 | 不能（OS 行为） | 级 3 |
| 13 | 2 秒轮询建议 | 不能（调用方行为） | 级 3 |
| 14 | `cargo clippy` 全仓零警告 | — | **不作为验收条件**：只看本次新增文件，避免"为过检查而改" |

⇒ plan 里不出现任何 grep / 正则 / 自建闸；"零 tauri"由 crate 边界保证，验收用负例证据。

## 3. 形状

### 3.1 crate 边界

```text
crates/lovart-core/          ← 新 crate，Cargo.toml 里没有 tauri
  src/lib.rs
  src/lovart/                从 src-tauri/src/lovart 整体移入
  src/engine/                从 src-tauri/src/engine 整体移入
                             engine/refs.rs  ← resolve_refs_core 从 run.rs 下沉
  src/service/
    workbench.rs             Workbench + Board + Config（字段全私有）
    api.rs                   publish / snapshot / stop
    run.rs                   ensure_scheduler / start_run
src-tauri/
  Cargo.toml                 lovart-core + tauri
  src/main.rs                入口（CLI 分支保留）
  src/run.rs                 CLI 参数与主流程，调 lovart_core
  src/gui.rs                 Tauri 命令薄壳
```

- 移动是机械的：core 内 `crate::engine` 不变；`src-tauri` 改 `lovart_core::engine`。
- **这项不做，第 2 节 #1 退回级 3（文字）+ 登记债**，且不许用 grep 补。
- 成本：2~3 天机械大改（约 50 个文件），行为零变化。
- **同 crate 内无法禁止 `engine → service`**（第 2 节 #9）：依赖方向写成一行范本放在 `service/mod.rs` 文件头，靠评审；要结构强制需拆 3 个 crate，本轮不拆（`ADR-0002` 第 69 行：不必要地拆也是加壳）。

### 3.2 `Workbench`：3 个业务入口 + 2 个领域句柄

**不做"命令名搬家"**：`ADR-0002` 第 13 行写明"接口与内部一一对应，深度为零"；`ADR-0006` 判据"同一操作名散落 2 个以上文件"。所以按**领域**聚合，不镜像 gui 命令。

```rust
pub struct Workbench { /* 原 GuiState 字段，全部去掉 pub */ }

impl Workbench {
    pub fn new(cwd: PathBuf) -> Arc<Self>;
    fn ensure_scheduler(self: &Arc<Self>) -> Result<Scheduler, String>;  // 必须 &Arc<Self>

    pub fn publish(&self, tasks: Vec<TaskInput>) -> Result<Accepted, String>;
    pub fn snapshot(&self, since: Option<&str>) -> Result<Snapshot, String>;
    pub fn stop(&self) -> Result<StopAck, String>;
    pub fn take_alerts(&self) -> Vec<String>;        // 取走即清，语义不变

    pub fn board(&self) -> Board<'_>;                // 看板领域（持锁）
    pub fn config(&self) -> Config<'_>;              // 配置领域
}

pub struct Board<'a> { core: &'a Workbench }
impl Board<'_> {
    pub fn remove(&self, ids: &[String]);
    pub fn clear_finished(&self);
    pub fn cancel_all(&self);
    pub fn cancel_queued(&self);
    pub fn import_inbox(&self, path: &Path) -> Result<Value, String>;  // 签名照抄现有命令
    pub fn probe(&self) -> Result<Value, String>;
    pub fn save_ref_image(&self, data_url: &str, name: &str) -> Result<String, String>;
}

pub struct Config<'a> { core: &'a Workbench }
impl Config<'_> {
    pub fn get(&self) -> Value;
    pub fn save(&self, patch: Value) -> Result<Value, String>;
    pub fn set_auto_confirm(&self, on: bool);
    pub fn set_spend_mode(&self, on: bool);
}
```

- `Board` / `Config` 在 `workbench.rs` 内，可访问 `Workbench` 私有字段；gui 只能通过句柄 ⇒ 直接摸字段是 E0616。
- `save_ref_image` 现在用 `tauri::async_runtime::spawn_blocking`（`gui.rs:872-877`）；方法改为同步，gui 命令保留 `async` + `spawn_blocking` 包装。
- 这是**结构护栏 + 领域聚合**，不是深模块：调用方分支数没有下降（gui 命令本来就 1~3 行），按 `ADR-0002` 第 13 行如实归类为"消重复"，不宣称深度。

### 3.3 看板：只有一个 `snapshot(since)`，没有第二解析函数

```rust
pub struct Snapshot {
    pub key: String,              // 内容指纹（不含 elapsed / 时钟）
    pub payload: Option<Value>,   // None = since 命中（未变化）
    pub elapsed: u64,
}
pub struct Accepted { pub accepted: usize, pub received_at: String } // UTC ISO 8601
pub struct StopAck { pub note: String }
```

- `snapshot(Some(&last))`：`key` 命中 ⇒ `payload = None`，**不构建全量**；未命中 ⇒ `payload = Some(全量)`。
- `snapshot(None)`：永远全量。
- `view_input` / `build_status_json` / `finish_payload` 只在这里出现一次 ⇒ 不违反 `ADR-0003` 判据 1（同一状态第二个解析函数）。
- **GUI**（`gui.rs`）：
  ```rust
  let s = core.snapshot(view_cache.last().as_deref())?;
  match s.payload {
      None => Ok(json!({ "unchanged": true, "elapsed": s.elapsed })),
      Some(v) => { view_cache.set(s.key); Ok(v) }
  }
  ```
  `GuiViewCache(Mutex<Option<String>>)` 在 gui 层 `manage`，service 无缓存字段。
- **HTTP**：`core.snapshot(None)`，`payload` 必为 `Some`；若 `None`（内部 bug）⇒ 500，不折成 `{}`。
- `unchanged` 判别位只出现在 GUI 传输层；HTTP 的类型上没有它的位置。

### 3.4 HTTP：串行 + 穷尽路由

```rust
for request in server.incoming_requests() {
    handle(request, &core);            // 无 spawn ⇒ 结构上无并发
}

fn handle(req: Request, core: &Arc<Workbench>) {
    match Route::parse(req.method(), req.url()) {
        Route::Tasks   => post_tasks(req, core),
        Route::State   => get_state(req, core),   // 只传 None
        Route::Stop    => post_stop(req, core),
        Route::Options => cors_preflight(req),
        Route::Other   => not_found(req),         // 没有 settings 分支
    }
}
```

```text
POST /tasks    { "tasks": [ … ] }
  → 200 { "accepted": 3, "receivedAt": "2026-11-20T06:55:44.394Z" }
  → 400 { "error": "第 2 条：…" }        → 413 { "error": "请求体超过 8MB" }

GET  /state    → 200 snapshot(None).payload（每次全量）
POST /stop     → 200 { "stopping": true, "note": "…最坏 60 秒…" } | 409 { "error": "当前没有在跑的批次" }
```

- 键名 `tasks`（与 Tauri 命令同名，`gui.rs:945`；`ui/app.js:2605` 传 `{ tasks }`）。
- 串行的代价：`/state` 约 200ms 会挡住紧随的 `/tasks`；外部前端 2 秒轮询，无感知。
- `snapshot` 的 `since` 参数不在 HTTP 暴露（调用点只有 `None`，第 2 节 #5 级 2 范本）。

### 3.5 失败语义（级 3，每条显式）

| 情形 | 行为 |
|---|---|
| `snapshot` 的 `view_input` / 序列化失败 | 返 `Err`；**不折成 `payload: Some({})`** |
| token 文件不存在 | 生成 32 hex 写入 |
| token 文件存在但**读失败** | **服务不启动** + `push_alert`；**不覆盖、不静默重生成** |
| token 写不进 `var/` | 服务不启动 + 告警；绝不"无 token 放行" |
| 端口 `17863` 被占 | 服务不启动 + 告警；GUI 其余功能照常 |
| body 超过 8MB | 413（先看 `Content-Length`；无长度头则 `take(8MB+1)`） |
| 请求读超时（10s） | 400 + 原因 |
| `/state` 的 `payload` 为 `None` | 500 + 原因（内部 bug） |
| `/stop` 无调度器 | 409 + 原话 |
| 后台解析 / 入队失败 | 告警（HTTP 看不到）；调用方用 `receivedAt` + `/state` 的 `status` 判断 |

**本轮兜底口径（`ADR-0008` 决议 2）**：diff 里不许新增 `unwrap_or_default()` / `?? 默认值` / `catch {}` 式写法；失败必须带原因。评审看，不做扫描闸。

## 4. 紧邻（同批接线）

1. **gui 命令变薄**：业务命令只剩「取 `State<Arc<Workbench>>` → 调入口 / 句柄 → 转 String / Value」；对话框、`reveal_path`、`open_output_dir`、窗口事件留在 gui。
2. **`GuiViewCache` 的失效**：`snapshot` 的 key 由内容决定，写操作后 key 自然变化；另外在写命令成功后调 `view_cache.clear()`（保险）。漏清的后果是"下一次轮询显示旧数据"，可见，不静默。
3. **前端零改动**：`publish_queue` 入参仍 `{ tasks }`，返回 `{ accepted, receivedAt }`（`app.js:2605` 不读）；`stop_run` 返回 `{ stopping, note }`（前端不读）。
4. **设置页一行只读说明**：`本机接口：http://127.0.0.1:17863（token 见 var/http-token）`。
5. **文档**：`docs/详细说明.md` 补「另一个前端怎么接」：三端点、`tasks` 键名、`receivedAt` 用法、2 秒轮询、token 位置与轮换。

## 5. 之后 / 不做

| 项 | 判定 | 理由 |
|---|---|---|
| 重复提交去重 | 之后 | 不写坏状态，只多花钱 |
| 告警环形缓冲 + 游标 | 之后 | 现在单消费者，要广播先改模型 |
| SSE / WebSocket | 之后 | 与"状态文件是唯一真相"冲突 |
| 端口可配置 / 自动发现 | 之后 | 固定端口够用 |
| 任务 `source` / `batch` 字段 | 之后 | 精确区分来源的唯一干净办法；改 schema 属另一件事 |
| **`/tasks` 返回 `ids`** | 不做 | id 最终值由 `spawn_extra` 在参考图上传**之后**决定、可顺延 `-2/-3`（`intake.rs:234-251`、`213-214`），且发生在 `start_run` 后台线程（`gui.rs:682-708`）。同步返回只能是候选 id ⇒ 会命中**上一批旧记录**。"查到错的那条"比不给更糟。要真 id 只有两条路：把 refs 解析塞进锁里（阻塞几十秒），或改 engine 让"先建记录后回填 refs"（改投喂时序）——都不在本轮 |
| HTTP 侧缓存 key | 不做 | 默认删除测试 #12；第 2 节 #5 已把 HTTP 调用点固定为 `None` |
| 绑定 `0.0.0.0` / HTTPS / 账号 | 不做 | 远程访问是另一套威胁模型 |
| HTTP 暴露配置 / 消耗开关 | 不做 | 本机任意程序能替你扣积分；路由表里没有分支 |
| 在 `gui.rs` 先写一份 HTTP | 不做 | 用户明确不要中间态 |
| CLI 改 socket | 不做 | 锁冲突是独立问题 |

## 6. 数据链

```
                       ┌── gui 命令（薄壳；写命令后 clear 缓存）
外部前端 ──HTTP──► service::Workbench ──┬─► publish：intake 校验（候选 id）
（token）           （core crate，无 tauri）│            └─► start_run（后台线程）
                       │                              └─► engine::refs 解析 ─► enqueue
                       │                                    （锁内 spawn_extra 定真 id）
                       └──► snapshot(None|Some) ─► build_status_json（唯一看板投影）
```

- **产生**：`publish` 唯一提交入口；`accepted` 在投递那一刻返回。
- **变形**：校验只在 `intake`；id 只在 `spawn_extra`；看板只在 `snapshot`。
- **消费**：GUI 传上次 key（`payload: None` 时不发全量），HTTP 只传 `None`。
- **失败语义**：HTTP 错误原话透传；`accepted` 只代表受理，结果用 `receivedAt` + `/state` 的 `status` 判断。
- **停止语义**：`stopping` = 已发信号；结束看 `/state` 的 `running` 变 `false`。
- **两条记录、不修**：
  1. `ensure_scheduler` 的 `reload_dot_env` 写进程环境（`gui.rs:207-208`），`output_dir()` 每秒读它（`gui.rs:309-314`）⇒ 并发提交时读写竞态，最坏"某一秒看板指向旧目录"，下一轮自愈。
  2. `enqueue` 开头复位 `stopped`（`scheduler.rs:2016-2017`）⇒ `/stop` 后再 `/tasks` 会重新开跑（"投喂即恢复"的既有语义）。

## 7. 验收（只用官方命令 + 真机）

1. `cargo test --workspace` 绿；新增：
   - `publish` 拒绝空 prompt / 未知模型（原话文案）；
   - `snapshot(None)` 连调两次都是全量；`snapshot(Some(key))` 命中时 `payload = None` 且不再构建全量（用计数或耗时断言）；
   - `key` 在记录状态变化后必然不同（与旧 `ViewCache.key` 逐条比对）；
   - `stop` 无调度器 ⇒ `Err`（HTTP 映射 409）。
2. **负例证据（`ADR-0009` 第 48 行允许的形态）**：
   1. core 里临时加 `use tauri::AppHandle;` ⇒ `cargo check -p lovart-core` **必报 E0432** ⇒ 删掉还原；
   2. `gui.rs` 里临时写 `core.scheduler` ⇒ **必报 E0616** ⇒ 删掉还原。
3. `cargo check --workspace`；`cargo clippy --workspace` 只看**本次新增/修改文件**零新增警告（不追求全仓零警告）。
4. 真机（`make win`）：
   1. `POST /tasks` 两条同 prompt ⇒ `{"accepted":2,"receivedAt":"…"}`，看板出现两条；再提一次同 prompt ⇒ `receivedAt` 之后出现 `-3`，旧记录不变（证明不能用 id 定位）；
   2. `GET /state` 两次都是全量；GUI 看板 1Hz 不卡（命中时 `payload = None`）；
   3. 错 token / 漏 header ⇒ 401；body 9MB ⇒ 413；
   4. `POST /stop` ⇒ `{"stopping":true,"note":"…"}`；无批次 ⇒ 409；
   5. token：重启 GUI ⇒ 文件内容不变；删文件再重启 ⇒ 变化，旧 token 被拒；把文件改成不可读 ⇒ **服务不启动 + 告警**；
   6. `netstat -ano | findstr 17863` ⇒ `127.0.0.1`；
   7. 关 GUI ⇒ 端口释放。
5. 回归：GUI 发布 / 停止 / 看板 / 重跑 / 接着查 / 确认 / 清空 / 导入 / 设置保存逐项点一遍；断点续跑与 `--status` 一致；`git diff` 对 `ui/` 只有设置页那一行。

`2B-2` 形状已定：

```rust
pub struct Snapshot {
    pub key: String,
    pub payload: Option<Value>,              // None = 命中（未变化）
    pub active: Vec<(String, Option<String>)>, // 命中时 GUI 用它重算文案
}
impl Workbench {
    pub fn snapshot(&self, since: Option<&str>) -> Result<Snapshot, String>;
}
```

- GUI：`GuiViewCache { key, elapsed }` 放到 gui 层（`Mutex` 托管）；

- 删除 `Workbench::view()` 与 `Workbench::invalidate_view()`；
- HTTP：`snapshot(None)`（永远全量）。

**为什么是 `active` 而不是 `elapsed: u64`**：命中时 GUI 要用上次的 `(id, stateSince)` 重算「已持续」，服务端此时不读盘；只给一个总秒数无法拼出逐条文案。
