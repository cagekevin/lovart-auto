## 0. 诊断：缺的是四个"所有权"，不是缺字段

v1/v2 都是按**功能清单**写的（maomao 有 A 就取 A、有 B 就取 B），所以每个问题只能长出一条孤立条款；条款互相不认账，就出现"补丁接补丁"。缺的顶层形状就四条：

| # | 缺的所有权 | 已暴露的症状（v2 原文级） |
|---|---|---|
| **S1 状态** | 谁算派生值、谁是投影 | 六个 mutator 返回整状态，`assistant_send` 只回 `text` ⇒ 标题/`updated_at` 只能前端自己算 ⇒ 界面说谎 |
| **S2 写入** | 谁串行化、一次写的边界在哪 | `assistant_send` 拿 t0 的快照写回 ⇒ 请求那 30 秒里的切会话/草稿/删除全被覆盖；请求中途删掉会话，行为未定义 |
| **S3 失败** | 一个失败有几处表达 | `prompt_config.ready=false` 与 `reason:'missing_key'` 说的是同一件事；单值枚举装不下"同时缺 endpoint 和 key"；`sent` 是第四个轴 |
| **S4 契约** | 宿主到底必须实现什么 | 8 条命令 + 4 个 adapter + 7 条宿主清单，三处各说一套；数字一旦漂移就互相打脸 |

**结论**：把这四条定成形状，验收按**不变量**设闸。其余一切（maomao 骨架、四入口、确认弹窗、渲染分支、插件目录）都是挂在形状外面的 UI 规格，不再出现在形状里，也不再各自占一条"第一性"。

## 1. 第一性（只有一条链，不再数"十条"）

**能问、能答、能接着问。** 多会话 / 改名 / 草稿 / 附件跟随不是独立能力，而是**同一个状态的不同变换**，共用 S1/S2，不给独立第一性、不新增形状。

| 要素 | 删掉后 | 判定 |
|---|---|---|
| 一次问答（系统提示词 + 非流式 + 无 tools） | 组件不存在 | **第一性** |
| 历史回传 | 第二句失忆 ⇒ 不是"对话软件" | **第一性** |
| 回复可读（markdown / 代码块 / 表格 / 图片渲染） | 回复是裸字符串 | **第一性** |
| 图片进上下文（拖拽 / 粘贴 / 导入 / 点图，一条落点） | 「把图加到对话框」不成立 | **第一性** |
| 多会话 / 改名 / 删除 / 草稿与附件跟随 | 用户裁定过「A 是个半成品不行」 | 第一性的**同一状态变换** |
| 非流式 / 无工具 / 只保留系统提示词 / 不出图 | 用户明说的约束 | **约束**（违反就变成另一个产品） |
| 插件形态 / 骨架照 maomao / 确认弹窗同款 | 是形态与外观 | **非第一性**：交付约束（§6），不进最小切片 |

## 2. 最小切片（一个状态、三条命令）

```
assistant_get_state → assistant_send → 渲染回复
```

跑通即算需求满足。多会话的六个变换共用同一条写路径，因此**不需要额外的链路、也不需要额外的第一性**。

## 3. 四个顶层形状

### S1 状态形状（唯一真相 + 唯一投影）

```rust
// crates/lovart-core/src/assistant/mod.rs（新顶层模块，**不进 lovart/**：那是出图网关的域）
pub struct ChatState {
    pub config: ConfigStatus,
    pub conversations: Vec<Conversation>,
    pub active_id: Option<String>,     // "还没有会话" = None，不是空串
}

pub struct ConfigStatus {
    pub missing: Vec<MissingPart>,      // 空 = 可发送；同时缺两个必须一次说完
}
pub enum MissingPart { SystemPrompt, Endpoint, Key }

pub struct Conversation {
    pub id: String,
    pub title: String,          // title_custom=false 时 = 首条 user 前 16 字，**后端算**
    pub title_custom: bool,
    pub ts: i64,
    pub updated_at: i64,        // **后端算**
    pub draft: String,
    pub messages: Vec<ChatMessage>,
    pub attachments: Vec<String>,       // 待发附件 = 本机路径
}

pub struct ChatMessage {
    pub id: String,
    pub role: String,           // 只有 "user" | "assistant"（system 只有提示词文件，不入会话）
    pub text: String,
    pub image_paths: Vec<String>,
    pub created_at: i64,
}
```

三条规则（是形状，不是建议）：

1. **任何改变状态的命令都返回完整 `ChatState`**，没有第二形状。`assistant_send` 也一样（`messageId` 从 `state` 的最后一条取，不做第二个返回值）。⇒ 前端永远是投影，不"乐观更新标题"（S1 治 §0 第一条症状）。
2. **派生值只由后端算**：`title` / `updated_at`。前端不拼、不猜。
3. `active_id` 用 `Option`：让"没有会话"编译期不可忽略（ADR-0004 优先于文档约定）。

### S2 写入形状（唯一写者 + 单一事务单位）

```rust
// crates/lovart-core/src/assistant/store.rs —— 全仓**唯一**碰 chat-history.json 的类型
pub struct ChatStore { /* 文件路径私有，外部拿不到 */ }

impl ChatStore {
    pub fn state(&self) -> Result<ChatState, ChatError>;
    pub fn apply(&mut self, mutation: Mutation) -> Result<ChatState, ChatError>;
    pub fn append_turn(&mut self, id: &str, user: ChatMessage, assistant: ChatMessage)
        -> Result<ChatState, ChatError>;
}

pub enum Mutation { New, Select{id}, Delete{id}, Rename{id, title}, SetDraft{id, draft}, SetAttachments{id, paths} }
```

文件（`<工作区>/data/chat-history.json`，路径由 plan 19 的 `Workbench` 具名访问器给，`gui.rs` 不许裸拼目录）：

```json
{ "version": 1, "active_id": "c…", "conversations": [ … ] }
```

不变量（判对错只看这五条，不看"哪里加了 if"）：

- **I-1 每次写 = 重新读文件 → 改一个字段 → `write_atomic`**。不缓存整表，不用上一命令的快照。
- **I-2 网络请求期间不持锁、不持表**：`assistant_send` = ①`state()` 取历史 ②发请求（无锁、无表）③`append_turn`（内部重新读文件、按 id 追加）。请求期间该会话被删 ⇒ ③ 返回 `NotFound`，落 `Delivered`（钱可能已花，见 S3），**文件里不出现幽灵会话**。
- **I-3 并发只有一个闸**：Tauri 侧注册一个 `Mutex<ChatStore>`，8 条命令过同一把锁。不另造 `FileLock`（那是出图 `state.jsonl` 的单写者，语义不同，混用即第二套）。
- **I-4 文件不存在 = 空状态**（`active_id: None`）；**文件存在但 JSON 坏 / 形状非法 = `BadHistory`**，绝不回空列表。
- **I-5 `write_atomic` 只留一份，落点在**下层**（`engine/` 或 `lovart/` 内部工具）——`lovart/preset.rs::save()` 在下层调用它，放 `service/` 就是反向依赖（ADR-0007）。同批把 `preset.rs::save` 与 `engine/state.rs:977`（`compact()`）改调它。
  ⚠️ `state.rs` 的常态落盘是**追加 pending 行**，不是原子重写 ⇒ 收口范围只到 `compact()`；回执里不许写成"所有写已原子"。

### S3 失败形状（一个枚举，一处表达）

```rust
pub enum ChatError {
    BadHistory { path: String, detail: String },
    NotFound { id: String },
    MissingConfig { missing: Vec<MissingPart> },
    BadImage { path: String, why: String },
    Upstream { kind: UpstreamKind, detail: String },  // Http | Envelope | Timeout | Io
    PersistFailed { detail: String },
}

pub enum SendResult {
    Ok { state: ChatState, reply: String },
    NotSent(ChatError),                                  // 未发出 / 非 2xx ⇒ 可原样重试
    Delivered { error: ChatError, reply: Option<String> }, // 上游 2xx（钱可能花了）⇒ 禁止自动重试
}
```

- **判据只有一个轴：上游是否返回 2xx。** `sent:false/true` 这个布尔消失，它就是 `NotSent` / `Delivered` 两个分支——同一件事只表达一次。
- `Delivered` 的四个来源，UI 处理完全一样（显示 `reply`（若有）+ `message`，**不给重试**）：2xx 但信封坏 / 2xx 但无 text / 2xx+text 但写盘失败 / 2xx+text 但会话已被删。超时同理（请求已发出，钱可能花了）。
- `{reason, message, detail}` 由 `ChatError` 序列化**一处**产生（`reason` = 枚举 tag），不手写第二份文案；`message` 必须含路径与动作（例：缺提示词 ⇒ "请写入 `data/chat-system-prompt.txt`"），因为本项目**没有设置页**。
- `config.missing` 是**状态**，`MissingConfig` 是**发送时的拦截**：`assistant_get_state` 永不因缺配置失败——缺配置只让"发"停，不让"看/改"停。
- 网络部分作为参数注入（`post: impl Fn(&Value) -> Result<String, UpstreamKind>`），四个分支才能不联网测。

### S4 契约形状（宿主必须实现的，只有三个返回形状）

```
invoke('assistant_get_state')                          -> ChatState | ChatError
invoke('assistant_<mutation>', payload)                -> ChatState | ChatError     // 6 个动作，同入同出
invoke('assistant_send', {conversationId, text, imagePaths}) -> SendResult
adapters = { openImage(src), pickFiles(), imagesFromClipboard(event), saveImageFile(file) }
插件自带 confirm.js（用户裁定；不 import 本仓 askConfirm，不用 window.confirm）
```

- 宿主清单 = **三个返回形状 + 四个 adapter + 它自己的密钥**。加 UI 动作只加 mutation，契约不动。
- **一条命令一个动作**（不做 `assistant_mutate({op})` 通用袋子：ADR-0002 明确"只靠泛型通用"不做）；但 6 个 mutation **共用一张表驱动验收**，不各写一套。
- 插件不持密钥、不 import 本仓、不读 `.env` 键名。本仓宿主的端点/密钥（`LOVART_CHAT_BASE_URL` / `LOVART_CHAT_KEY`）是**宿主实现细节**，写进 `data/.env`，不复用出图网关的 `LOVART_BASE_URL` / `LOVART_ACCESS_KEY`。
  ⚠️ 键名怎么让用户知道：由 `MissingConfig` 的 `message` 直接写出来（`data/.env.example` 当前**不存在**——即便 `connection.rs` 的旧文案提到"可复制 .env.example"，那是既有漂移，不改它、也不假装它存在）。

### 3.5 请求组装（唯一函数，例外清零）

```rust
fn build_messages(prompt: &str, conv: &Conversation, text: &str, image_paths: &[String])
    -> Result<Value, ChatError>
```

- 组装 = `system(系统提示词)` + **该会话全部历史**（user/assistant，**含历史图片**）+ 本轮 user（text + 本轮图片）。
- **不为"历史图片"开例外**：v2 的"历史图片不回传"是自加限制，且删掉这个分叉需求不变 ⇒ 按"例外清单"不许留。token 变多是"把话说全"的代价，不是另立规则的理由；真要限，等用户开口。
- 图片：本机路径 → 读字节 → base64 → `data:image/<ext>;base64,…`。读不到 / 非图 ⇒ `BadImage{path,why}`，不吞、不跳过、不塞 `convertFileSrc`（那只给 `<img>` 显示用）。
- 请求体**不出现 `tools`**；`stream:false`；role 只有 system/user/assistant。超时不新造数值，沿现有单请求超时口径，超时归 `Delivered`。

## 4. 数据链（一条，含失败分支）

```
开面板 → assistant_get_state → ChatState（config.missing 只打标，不 ok:false）
改状态 → assistant_new / switch / delete / rename / set_draft / set_attachments
       → ChatStore.apply → 重新读 → 改一个字段 → write_atomic → ChatState
加图   → addChatAttachment({kind:'path'|'file', value})
       → kind:'file' 经 saveImageFile 落盘一次 → assistant_set_attachments → ChatState
发送   → assistant_send → state() 取历史 → POST（无锁、无表）
           ├ 未发出 / 非 2xx      → NotSent(err)      草稿与附件不动，可原样重试
           └ 2xx                  → parse text → append_turn（重新读、按 id 追加）
                                      ├ 成 → Ok{state, reply}
                                      └ 败 → Delivered{err, reply}
```

**草稿时机（UI 策略，不是形状）**：失焦 / 切会话前 / 发送前 / 关面板 四处提交，不每击键写。切会话 = 先 `set_draft`（成功）再 `switch`，失败就不切，草稿不丢。进程被杀丢最后一段，不做崩溃恢复。

## 6. 交付约束与不做

| 项 | 类别 | 理由 |
|---|---|---|
| 插件形态（可移植） | 交付约束 | 用户要"直接接给别的软件"；宿主只实现 S4 那三个形状 |
| 骨架 / 渲染照 maomao | 外观约束 | 用户多次明确；**不拿它定义最小切片**（否则把下拉/重命名/回到底部塞成"第一性"= 完整性代替必要性） |
| 独立面板 vs 独立 exe | 形态 | 能力都在；exe = 跨进程传图 + 第二份密钥/入口 ⇒ 选面板（ADR-0010 ③） |
| 确认弹窗 = 插件专用 | 插件边界 | 用户裁定；两套并存（本仓 `askConfirm` + 插件 `confirm.js`）**同批用 `debt.mjs add --area 04` 登记一条债**（编号由脚本分配，不手写；不许只在回答里提一句） |
| 从对话出图 / 发任务 / 入待发队列 | 能力 | 用户定位：不出图，纯 LLM 对话 |
| 工具 / `tools` / `role:'tool'` | 能力 | 用户明说不要 |
| 流式 / SSE / stop / steer / 状态机 | 能力 | 非流式无流可停、无队列可插 |
| AI 表格工作区（`assistantTable/*` 22 文件） | 能力 | 用户明说不要；markdown 表格是**渲染分支**，照搬 |
| skill / memory / 意图预判 / workflow / pending | 能力 | 用户没提，加了就是自造需求 |
| `innerHTML` / 原始 HTML | 安全 | 零 XSS 面 |
| 前端直连 LLM / 插件持密钥 / 插件读 `.env` 键名 | 架构 | 密钥留宿主后端 |
| 整表写回 / `stateVersion` / `sent` 布尔 | 数据流 | 第二真相 / 死字段 / 第四根失败轴（S1–S3） |
| 缺文件用默认系统提示词 | 失败语义 | 缺就报 `MissingConfig`，不自编一句兜底（ADR-0008） |
| 历史图片不回传 | —— | **v3 删除**：自加限制 + 留了个删得掉的分叉（§3.5） |
| 会话导入导出 / 搜索 / 分组 / 系统提示词编辑 UI | 之后 | 直接编辑文件即可；不是"必备" |

## 11. 已定案

- 前缀 `assistant_*`；形态 = 独立面板 + 插件目录；不出图、不发任务。
- 历史：**全量回传**（文本 + 图片，无例外）；历史就是 `ChatState` 里的会话本身。
- 失败：`SendResult` 三态，判据只有"上游是否 2xx"。
- 写入：`ChatStore` 唯一写者，请求期间不持锁不持表。
- 确认弹窗：插件专用、同款样式；本仓两套并存登记 TD-04。
- 端点/密钥：本仓 `LOVART_CHAT_BASE_URL` + `LOVART_CHAT_KEY`（含 `.env.example`），宿主细节、不进插件。
