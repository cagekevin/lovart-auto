## 0. 诊断：缺的是四个"所有权"

v1/v2/v3 都按**功能清单**写（maomao 有 A 就取 A），每个问题只能长出一条孤立条款，于是补丁接补丁。缺的顶层形状只有四条：

| # | 缺的所有权 | 已暴露的症状 |
|---|---|---|
| **S1 状态** | 谁算派生值、谁持有投影 | mutator 回整状态、`send` 只回 text ⇒ 标题只能前端猜 ⇒ 界面说谎 |
| **S2 写入** | 谁串行化、一次写的边界在哪 | `send` 拿 t0 快照写回 ⇒ 请求那 30 秒里的切换被覆盖 |
| **S3 失败** | 一个失败有几处表达 | `config.missing` 与 `reason:missing_key` 说同一件事；`sent` 是第四根轴 |
| **S4 契约** | 宿主到底必须实现什么 | 命令 / adapter / 宿主清单三处各说一套 |

**v4 多了一条（砍完才显出来的）**：**未发送的输入不归后端**。`draft` / `attachments` 是 UI 状态，写进"对话真相"文件等于把两个生命周期塞进一个 JSON —— 这也是 §6 里 A 项被砍的真正理由，不是"省事"。

## 1. 第一性（只有一条链）

**能问、能答、能接着问。**

| 要素 | 删掉后 | 判定 |
|---|---|---|
| 一次问答（系统提示词 + 非流式 + 无 tools） | 组件不存在 | **第一性** |
| 历史回传 | 第二句失忆 ⇒ 不是对话软件 | **第一性** |
| 回复可读（markdown / 代码块 / 表格 / 图片渲染） | 回复是裸字符串 | **第一性** |
| 图片进上下文（拖拽 / 粘贴 / 导入 / 点图，一条落点） | 「把图加到对话框」不成立 | **第一性** |
| 多会话（**新建 + 切换**） | 用户裁定过「A 是个半成品不行」 | 第一性的同一状态变换 |
| 非流式 / 无工具 / 只保留系统提示词 / 不出图 | 用户明说的约束 | **约束** |
| 插件形态 / 骨架照 maomao | 形态与外观 | **非第一性**：交付约束（§6） |
| 重命名 / 删除会话 | 删掉后"能对话"仍成立 ⇒ **不是第一性**；但"会话删不掉"是用户看得见、又只能手改 JSON 才能解决的缺口 ⇒ 同批做，**不进最小切片** | 紧邻（§6） |
| 草稿跟随 / 回到底部 | 删了对话照样能用（用户已同意砍） | **不做**（§6） |

## 2. 最小切片（一个状态、两条命令）

```
assistant_get_state → assistant_send → 渲染回复
```

跑通即算需求满足。`new` / `switch` / `rename` / `delete` 是同一状态的另四种变换，共用同一条写路径，不另立链路。

## 3. 四个顶层形状

### S1 状态形状（唯一真相 + 唯一投影）

```rust
// crates/lovart-core/src/assistant/mod.rs（新顶层模块，**不进 lovart/**：那是出图网关的域）
pub struct ChatState {
    pub config: ConfigStatus,
    pub conversations: Vec<Conversation>,   // 顺序由后端定：ts 降序（新建在前），插件不得重排
    pub active_id: Option<String>,          // "还没有会话" = None，不是空串
}

pub struct ConfigStatus {
    pub missing: Vec<MissingPart>,          // 空 = 可发送；同时缺两个必须一次说完
}
pub enum MissingPart { SystemPrompt, Endpoint, Key, Model }
// ⚠️ `Model` 是施工时补的：OpenAI 兼容请求体**必须有 `model`**，v5 之前漏了它
// （原稿这里是 Endpoint/Key/Model 三项 + `LOVART_CHAT_MODEL`；2026-11-26 走 Lovart 通道后
// 整条删除，只剩 `Credentials` 一项，见 plan 23。）

pub struct Conversation {
    pub id: String,             // 不透明串，后端生成；插件不得解析、不得自造
    pub title: String,          // 空串 = 未起标题（前端显示「新会话」）；首条消息时写前 16 字；**非空则永不覆盖**（重命名即写非空）
    pub ts: i64,                // Unix **毫秒**
    pub messages: Vec<ChatMessage>,
}

pub struct ChatMessage {
    pub id: String,
    pub role: Role,             // enum Role { User, Assistant }；system 不入会话（只活在 build_messages）
    pub text: String,
    pub image_paths: Vec<String>,   // 本机路径（**不复制**，见 I-6）
    pub created_at: i64,        // Unix 毫秒
}
```

**线上形状（wire）—— 宿主与插件之间唯一的耦合面**：

- JSON 字段一律 **camelCase**（`activeId` / `imagePaths` / `createdAt`），Rust 侧 `#[serde(rename_all = "camelCase")]`。本文结构体名是 Rust 内部名。
- 时间一律 **Unix 毫秒**（不写秒，不写 ISO）。
- `version` 只认 `1`；读到不认识的值 ⇒ `BadHistory`（不猜、不就地改写）。
- **未发送的输入（输入框文字 + 附件 chip）不在 `ChatState` 里**：那是插件内存，切会话 / 关面板即丢弃（§6 A 项）。

三条规则：

1. **任何改变状态的命令都返回完整 `ChatState`**，没有第二形状（`assistant_send` 的 `Ok` 里也是整个 `state`）。前端永远是投影，不"乐观更新标题"。
2. **派生值只由后端算**：`title`（首条 user 前 16 字）。前端不拼、不猜；`title` 为空时前端**只显示**「新会话」占位，不把占位写回字段。
3. `active_id` 用 `Option`：让"没有会话"编译期不可忽略（ADR-0004）。

**已记账的代价**：每次命令返回全量 `ChatState`（含所有会话的消息）⇒ IPC 大小随历史线性增长。**不做分页、不造第二形状**；真要优化只有一条路（`messages` 只回 active 会话），那会打破"投影 = 真相"，等真的卡了且用户开口再说。

### S2 写入形状（唯一写者 + 单一事务单位）

```rust
// crates/lovart-core/src/assistant/store.rs —— 全仓**唯一**碰 chat-history.json 的类型
pub struct ChatStore { /* 文件路径私有，外部拿不到 */ }

impl ChatStore {
    pub fn state(&self) -> Result<ChatState, ChatError>;
    pub fn new_conversation(&mut self) -> Result<ChatState, ChatError>;   // 新建 + 立即成为 active（同一次写）
    pub fn select(&mut self, id: &str) -> Result<ChatState, ChatError>;   // 不存在 ⇒ NotFound（不新建代替）
    pub fn rename(&mut self, id: &str, title: &str) -> Result<ChatState, ChatError>;  // 写 title：空串 = 回到未起标题
    pub fn set_config(&mut self, config: ChatConfig);   // 每条命令开头刷新（.env 走进程环境，不缓存）
    pub fn delete(&mut self, id: &str) -> Result<ChatState, ChatError>;   // 整条移除 + active 迁移（同一次写）
    pub fn append_turn(&mut self, id: &str, user: ChatMessage, assistant: ChatMessage)
        -> Result<ChatState, ChatError>;
}
```

文件（`<工作区>/data/chat-history.json`，路径由 plan 19 的 `Workbench` 具名访问器给，`gui.rs` 不许裸拼目录）：

```json
{ "version": 1, "active_id": "c…", "conversations": [ … ] }
```

不变量（判对错只看这七条，不看"哪里加了 if"）：

- **I-1 每次写 = 重新读文件 → 改一个字段 → `write_atomic`**。不缓存整表，不用上一命令的快照。
- **I-2 网络请求期间不持锁、不持表**：`assistant_send` = ①`state()` 取历史 ②发请求（无锁、无表）③`append_turn`（内部重新读文件、按 id 追加）。请求期间用户切到另一个会话 ⇒ ③ 不许把 `active_id` 改回去。
- **I-3 并发只有一个闸**：Tauri 侧注册一个 `Mutex<ChatStore>`，6 条命令过同一把锁。不另造 `FileLock`（那是出图 `state.jsonl` 的单写者，语义不同）。
- **I-4 文件不存在 = 空状态**（`active_id: None`）；**文件存在但 JSON 坏 / 形状非法 / 版本不认识 = `BadHistory`**，绝不回空列表。
- **I-5 图片读不到分两种，不许合并**（唯一分界 = **用户此刻能不能修**）：
  · **历史消息里的图**读不到 ⇒ 请求里替换为 `[图片缺失]`，**发送继续**（用户改不了那一轮，报错只会把对话变成只读）。
  · **本轮待发的图**读不到 ⇒ `BadImage`，未发出（用户此刻能修；静默吞掉他刚选的图 = 界面说谎）。
  · 标记**进入请求正文**，模型知道此处缺图 ⇒ 显式降级，不是把失败埋掉；气泡占位文案用**同一句** `[图片缺失]`。
  · 推论：**不做图片副本** —— 会话只存来源路径，不建 `chat-media/`，也不在删会话时删文件（本来也没有删会话）。
- **I-6 一轮提交 = 一次追加写**：`append_turn` 在同一次读改写里完成 ①追加 user（text = 入参正文，images = 入参图片）②追加 assistant ③若是首条消息 ⇒ 写 `title`。失败（`NotSent`）时一个字都不动。
- **I-7 删除 = 整条移除 + active 迁移，一次写**：删的是 active ⇒ `active_id` 取剩余列表的第一条；删空 ⇒ `active_id = None`；删的不是 active ⇒ `active_id` 不动。返回删后的全量 `state`，**前端不自己摘列表**。

### S3 失败形状（一个枚举，一处表达）

```rust
pub enum ChatError {
    BadHistory { path: String, why: String },
    NotFound { id: String },
    MissingConfig { missing: Vec<MissingPart> },
    BadImage { path: String, why: String },
    Upstream { kind: UpstreamKind, why: String },  // Http | Envelope | Timeout | Io
    PersistFailed { why: String },
}

pub enum SendResult {
    Ok { state: ChatState },                                // reply = state 末条 assistant，不重复带一份
    NotSent(ChatError),                                     // **没拿到 thread_id** ⇒ 可原样重试
    Delivered { error: ChatError, reply: Option<String> },  // 拿到 thread_id 之后失败 ⇒ 禁止重试
}
```

**线上判别式只有一个字段 `status`**（不用 `ok`+`sent` 两个布尔：那会允许"ok:true 且 delivered:false"这种不可达组合，ADR-0004）：

```json
{ "status": "ok",        "state": {…} }
{ "status": "not_sent",  "reason": "bad_image",      "message": "…", "detail": "…" }
{ "status": "delivered", "reason": "persist_failed", "message": "…", "detail": "…", "reply": "…" }
```

- **判据只有一个轴：上游是否给出 `thread_id`。**（⚠️ 2026-11-26 更正：原稿写"是否返回 2xx" —— 通道是「提交 → 轮询 → 取结果」三段，2xx 只覆盖第一段，而计费发生在"上游接受并建了 thread"那一刻，见 `plan 23` §3。本文件中其余仍写着"2xx"的解释性句子，一律按本句理解。）
  `sent:false/true` 这个布尔消失，它就是 `not_sent` / `delivered` 两个分支。
- `status` 的取值集合按命令固定：读/写类 = `ok` | `error`；`assistant_send` = `ok` | `not_sent` | `delivered`（`not_sent` 就是"可重试的 error"）。
- **错误通道（由结构承担，不靠文档，不落 ADR）**：命令的**业务函数返回 `Result<T, ChatError>`**（`ChatError` 是本组自己的枚举，**不是 `String`**），`gui.rs` 的 `#[tauri::command]` 只做两件事：`Ok(to_value(business(...)))` 或 `Err(panic 级) `。
  ⇒ 想让业务失败走 `Err`，必须手写一层 `ChatError → String` 的转换，**不会顺手写出来**（ADR-0004 优先于文档约定）。现有 30+ 条旧命令沿用 `Err(String)`，本组**不跟随**——插件只调 `assistant_*`，两侧不混。
- **错误线上恒为 `{reason, message, detail}` 三字段**，不开第四字段：`reason` = 枚举 tag（`bad_history` / `not_found` / `missing_config` / `bad_image` / `upstream_http` / `upstream_envelope` / `upstream_timeout` / `upstream_io` / `persist_failed`）；机器可读信息（缺哪几项、哪条路径、原始 error）由枚举载荷**编进 `message`（给人）与 `detail`（给日志）**。
- `Delivered` 的四个来源，UI 处理完全一样（显示 `reply`（若有）+ `message`，**不给重试**）：2xx 但信封坏 / 2xx 但无 text / 2xx+text 但写盘失败 / 2xx+text 但会话已被删。超时同理（请求已发出，钱可能花了）。
- **通则（比 I-5 更上位）**：**用户此刻能改的失败 ⇒ 报错**（`not_sent`，可重试；输入与附件不动）；**他改不了的失败 ⇒ 降级并显式标注**（不阻断后续，标记进入正文/界面，两端同一句）。以后遇到"缺什么"先问这句。
- `config.missing` 是**状态**，`MissingConfig` 是**发送时的拦截**：`get_state` 永不因缺配置失败——缺配置只让"发"停，不让"看"停。两处调**同一个** `config_status()`。
- `message` 必须含路径与动作（例：缺提示词 ⇒ "请写入 `data/chat-system-prompt.txt`"），因为本项目**没有设置页**；消费者只 `display(message)`，不拼文案。
- 网络部分作为参数注入（`post: impl Fn(&Value) -> Result<String, UpstreamKind>`），四个分支才能不联网测。

### S4 契约形状（宿主必须实现的全部）

```
invoke('assistant_get_state')                       -> {status:'ok', state} | {status:'error', reason, message, detail}
invoke('assistant_new')                             -> 同上两种
invoke('assistant_switch',  {id})                   -> 同上两种
invoke('assistant_rename',  {id, title})            -> 同上两种
invoke('assistant_delete',  {id})                   -> 同上两种
invoke('assistant_send', {conversationId, text, imagePaths}) -> {status:'ok'|'not_sent'|'delivered', …}

adapters（全部返回 Promise，宿主实现）：
  imageSrc(path) -> Promise<string>            // 本机路径 → <img src>（Tauri 是 convertFileSrc）
  openImage(src) -> void                       // src 可能是本机路径或 http(s)，宿主决定用哪个查看器
  saveImageFile(file) -> Promise<string>       // File → 宿主暂存路径（plan 18 的 saveRefImage）
  pathsFromClipboard(event) -> Promise<string[]>  // 只回本机路径，不回 File

插件实例方法（宿主调插件，属于契约）：
  plugin.open()                                // **必需**：宿主点按钮 → 打开面板并重读一次状态
  plugin.addAttachment(paths: string[])        // 拖拽 / 点图进对话的唯一入口（未开则先 open）
  plugin.destroy()                             // 必需：卸载 DOM（宿主关面板时不必调）
  plugin.close() / isOpen() / refresh()        // 可选，宿主自己想接管开关时用
```

- 宿主清单 = **1 个 invoke（6 条命令，两种返回）+ 4 个 adapter + 2 个实例方法 + 它自己的密钥**。加 UI 动作只加 mutation，契约不动。
- **载荷字段逐个写死**：`{id}` / `{id,title}` / `{conversationId,text,imagePaths}`。宿主照这里的键名实现，不许自创别名。
- **"导入"不需要 adapter**：插件自己建隐藏 `<input type=file>`（maomao 同款），拿到 `File` 后调 `saveImageFile`。
- **"拖拽"由宿主接管**：Tauri 会拦截 HTML5 `drop`、`File.path` 也拿不到 ⇒ 宿主监听自己的拖放源，然后调 `plugin.addAttachment(paths)`。与"点图进对话"同一个钩子（ADR-0005）。
- **粘贴在插件内**：textarea 属于插件，只有它能接 `paste` ⇒ 调 `pathsFromClipboard(event)`，落点仍是 `addAttachment`。
- **防重复发送只有一处**：等待期间发送键必须禁用（插件负责）；`assistant_send` 后端**不做去重**（不造第二个"在飞"状态）。
- **一条命令一个动作**（不做 `assistant_mutate({op})` 通用袋子：ADR-0002）；6 条命令共用一张表驱动验收，不各写一套。
- **删除的确认只在前端**：两次点击（首点变红、2 秒内再点执行、点别处复位），不调后端、不弹窗、不新增组件。后端只认"你要删这个 id"。
- 插件不持密钥、不 import 本仓、不读 `.env` 键名。本仓宿主：**复用出图那对凭据**（`LOVART_ACCESS_KEY` / `LOVART_SECRET_KEY`，见 plan 23）—— 2026-11-26 用户裁定「LLM 和 lovart 是同一个」，原计划的三个 `LOVART_CHAT_*` 键**整条删除**。缺凭据时由 `MissingConfig` 的 `message` 说清键名，模板见**根目录 `.env.example`**。

### 3.5 请求组装（唯一函数，例外清零）

```rust
fn build_messages(prompt: &str, conv: &Conversation, text: &str, image_paths: &[String])
    -> Result<Value, ChatError>
```

- **调用方先读提示词**：`data/chat-system-prompt.txt` 读不到 ⇒ `MissingConfig{SystemPrompt}`，**不空串、不默认句**（ADR-0008）。
- 组装 = `system(系统提示词)` + **该会话全部历史**（user/assistant，**含历史图片**）+ 本轮 user（text + 本轮图片）。
- **不为"历史图片"开例外**：v2 的"历史图片不回传"是自加限制，删掉这个分叉需求不变 ⇒ 不许留。
- 图片（本机路径，不复制）：读字节 → base64 → `data:image/<ext>;base64,…`。读不到按 I-5 分两种；不塞 `convertFileSrc`（那只给 `<img>` 显示）。
- 请求体**不出现 `tools`**；`stream:false`；role 只有 system/user/assistant。超时不新造数值，沿现有单请求超时口径，超时归 `Delivered`。

## 4. 数据链（一条，含失败分支）

```
开面板 → assistant_get_state → ChatState
         config.missing 只打标，不 ok:false；两种空态：
           · activeId=None（还没有会话）⇒ 提示「点 + 新建会话」，发送键禁用；assistant_send 直接 NotFound
           · 有会话、messages 空        ⇒ 「有什么可以帮你？」，可输入

新建 / 切换 / 改名 / 删除 → assistant_new / switch / rename / delete → ChatStore → 重新读
            → 改声明的那一项（new 插一条并成为 active；rename 写 title；delete 整条移除并按 I-7 迁 active）
            → write_atomic → ChatState
            （插件同时清空自己的输入与 chip —— 未发送的输入不落盘，见 §6）
            （delete 的"确认"只在前端两次点击，后端不参与）

加图   → addChatAttachment(sourcePath)：**只进插件内存**（chip 列表），不调后端
         四入口：点图/拖拽（宿主调 plugin.addAttachment）· 粘贴（pathsFromClipboard）· 导入（内建 input + saveImageFile）

发送   → assistant_send({conversationId, text, imagePaths})   // 入参 = 本轮内容的权威
       → state() 取该会话历史（锁外、不持表）
       → 读提示词（缺 ⇒ MissingConfig.SystemPrompt，未发出）
       → 图片：本轮路径读不到 ⇒ BadImage（未发出）；历史路径读不到 ⇒ 该块换成 `[图片缺失]` 继续
       → POST stream:false / 无 tools（锁外）
           ├ 未发出 / 非 2xx       → NotSent(err)：插件保留输入与 chip，可重试
           └ 2xx → parse text
                    ├ append_turn 一次写（两条消息 + 首条时写标题）
                    │              → Ok{state}
                    └ 写失败 / 会话已被删 → Delivered{err, reply}：不重试，reply 只在本次界面显示
```

**发送成功后**：插件清空自己的输入与 chip（`Ok` 的 `state` 里已经没有它们的位置）；失败时**不动**。

## 6. 交付约束与不做

| 项 | 类别 | 理由 |
|---|---|---|
| 插件形态（可移植） | 交付约束 | 用户要"直接接给别的软件"；宿主只实现 S4 |
| 骨架 / 渲染照 maomao | 外观约束 | 用户多次明确；**不拿它定义最小切片** |
| 独立面板 vs 独立 exe | 形态 | exe = 跨进程传图 + 第二份密钥/入口 ⇒ 选面板 |
| **草稿 / 附件跟随会话** | **砍（用户同意）** | 未发送的输入归前端；放进真相文件 = 两个生命周期混一个 JSON，还要 2 条命令 + 1 个顺序依赖（"发送前先提交草稿"）。**可见损失：切走会话 / 关面板，未发送的输入消失** |
| **会话重命名** | 加回（用户补裁） | 不支撑第一性但约 35 行；**不新增字段**（`title` 空串 = 未起标题，非空永不覆盖） |
| **删除会话** | 加回（用户补裁） | 不支撑第一性但约 40 行；删当前会话 ⇒ `active_id` 迁到列表第一条（I-7）。"会话删不掉"是用户看得见、却只能手改 JSON 才能解决的缺口 |
| **插件专用确认弹窗（`confirm.js`）** | **不做**（用户补裁"不要弹窗"） | 删除用**两次点击确认**（首点变红、2 秒内再点、点别处复位）⇒ 不新增组件、不登记债、不与宿主 `askConfirm` 并存 |
| **回到底部按钮** | 砍（用户同意） | 不支撑第一性；滚动监听 + `inert`/`tabIndex` 语义，删掉照样能聊 |
| **`updated_at`** | 砍（用户同意，连带） | 砍掉草稿与改名后它**没有消费者**（列表按 `ts` 排、不按它）⇒ 留着就是死字段 |
| **同批改 `engine/state.rs::compact()`** | 砍（用户同意） | 跨到出图落盘（花钱边界）+ 全量回归；本组件一行代码都不会因此变好。交付时单独登记债 |
| 会话图片副本（`data/chat-media/`） | 不做 | 历史缺图已由 `[图片缺失]` 降级解决；复制只换来磁盘翻倍 |
| 从对话出图 / 发任务 / 入待发队列 | 能力 | 用户定位：不出图，纯 LLM 对话 |
| 工具 / `tools` / `role:'tool'` | 能力 | 用户明说不要 |
| 流式 / SSE / stop / steer / 状态机 | 能力 | 非流式无流可停、无队列可插 |
| AI 表格工作区（`assistantTable/*`） | 能力 | 用户明说不要；markdown 表格是**渲染分支**，照搬 |
| skill / memory / 意图预判 / workflow / pending | 能力 | 用户没提，加了就是自造需求 |
| `innerHTML` / 原始 HTML | 安全 | 零 XSS 面 |
| 前端直连 LLM / 插件持密钥 / 插件读 `.env` 键名 | 架构 | 密钥留宿主后端 |
| 整表写回 / `stateVersion` / `sent` 布尔 | 数据流 | 第二真相 / 死字段 / 第四根失败轴 |
| 缺文件用默认系统提示词 | 失败语义 | 缺就报 `MissingConfig`，不自编一句兜底（ADR-0008） |
| 会话导入导出 / 搜索 / 分组 / 系统提示词编辑 UI | 之后 | 不是"必备"；提示词直接编辑文件 |

## 8. 之后（每条一句为什么可以等）

## 9. 验收：一条不变量一条闸

### 9.1 自动（按不变量，不按 grep 抄全仓）

| # | 验哪条不变量 | 怎么验 | 期望 |
|---|---|---|---|
| A1 | S1 唯一投影 | 类型层：所有命令返回 `Result<ChatState, ChatError>`；发送成功后 `state` 里的 `title`/消息与文件逐字节一致 | 编译即证 + 单测 |
| A2 | S2 唯写者（I-1/I-4/I-7） | 表驱动 4 个动作：`new_conversation` / `select` / `rename` / `delete`；文件不存在 ⇒ 空 `state`；坏 JSON ⇒ `BadHistory`；未知 id ⇒ `NotFound`；每次写后文件差异只落在该动作声明的字段（`delete` 额外含 `active_id` 迁移）；删最后一个 ⇒ `activeId=null` 且列表空 | 全过 |
| A3 | I-2 请求不持快照 | 假 transport 两个场景：①请求进行中 `select` 到另一会话 ②请求进行中 `delete` 掉该会话，各自再返回 2xx | ①消息追加在原会话、`active_id` 仍是新会话（**没被 t0 快照覆盖**）②`delivered{not_found}`，文件里**不出现幽灵会话** |

## 11. 已定案

- 前缀 `assistant_*`；形态 = 独立面板 + 插件目录；不出图、不发任务。
- 命令面：**6 条**（`get_state` / `new` / `switch` / `rename` / `delete` / `send`）；多会话 = 新建 / 切换 / 重命名 / 删除。
- 删除的确认 = **前端两次点击**（首点变红、2 秒内再点、点别处复位）：无弹窗组件、无新债、后端不参与。
- `title` 空串 = 未起标题（前端显示「新会话」）；首条消息写切片；非空永不覆盖 ⇒ **不需要 `title_custom`**。
- 未发送的输入归插件内存，不进真相文件；切会话/关面板即丢（用户同意）。
- 历史：**全量回传**（文本 + 图片，无例外）。
- 失败：`status` 三态，判据只有"上游是否给出 `thread_id`"（2026-11-26 更正，见 plan 23）；错误线上恒三字段。
- 写入：`ChatStore` 唯一写者，请求期间不持锁不持表；一轮提交 = 一次追加写。
- 图片：**不复制**，只存来源路径；历史缺图 ⇒ `[图片缺失]` 继续，本轮缺图 ⇒ `bad_image` 报错。
- 状态：每次命令回全量 `ChatState`；IPC 随历史线性增长是**已记账的代价**。
- 契约面：6 条 invoke（两种返回）+ 4 个 adapter（`imageSrc` / `openImage` / `saveImageFile` / `pathsFromClipboard`）+ 2 个实例方法（`addAttachment` / `destroy`）。线上 JSON 一律 camelCase，时间一律 Unix 毫秒。
- 端点/密钥：**复用出图凭据**（`LOVART_ACCESS_KEY` / `LOVART_SECRET_KEY` + `LOVART_BASE_URL`，见 plan 23），宿主细节、不进插件；缺凭据时由 `MissingConfig` 的 `message` 给出键名。
- 前置：`write_atomic` 落 crate 根 `src/fsio.rs`（P1）；本组命令的失败一律在 `Ok(status)` 里、`Err` 只留给崩溃（P2）；`data/` 路径只经 `Workbench` 访问器（P3）；残留检查用 `Select-String`（P4）。
