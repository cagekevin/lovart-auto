# 素材库（弹窗版）· 施工契约

> 状态：**待施工**（2026-11-26）
> 用户原话（上游需求）：
> - 「后面我还准备加个预设素材库，就是有一个按钮，点开，然后里面都是图片，
>   然后点击一下，就进入到编辑区的垫图里，然后打开图片的大图，那里加一个按钮，发送到素材库」
> - 「已经有 input output，如果加上素材库，就相当于所有文件都在同一个目录」
> - 「做成侧栏的形式怎么样？」+「侧栏好还是弹窗好，其实只是位置不同而已，
>   侧栏肯定是要能关掉的，因为他不是常用功能」⇒ **按建议定：弹窗**（不常用 ⇒ 居中 + 遮罩 + 点完即关）
> - 「我可没确定是eagle预设库」⇒ **不断言外部 `*.library` 是什么库、不读写它**
>
> 前置：`docs/plan/19-目录归属与访问器收口-2026-11-26.md`（`data/` 唯一数据根）·
> `docs/plan/18-垫图入预设-施工契约-2026-11-26.md`（`RefStrip` 组件 · `materialize_named_file` 底座）·
> ADR-0005（一个能力一个入口）· ADR-0010（先过必要性与可见性再排序）

## 0. 结论

素材库 = **本工具自己的一个图片目录** `<工作区>/data/library/`：
工具条加一个按钮 → 打开**弹窗**（网格列目录里的图）→ 点一张 ⇒ 进编辑区垫图 → 关面板；
「发送到素材库」有**两个触发点**（viewer 底部 + 素材库弹窗内的「＋」）⇒ 把图**复制**进 `data/library/`；两条入口汇合到同一条命令与落盘实现（§3.3）。

**不造新系统**：核心原语都已有或可从既有件抽出（`pushRef` · `#viewer` 动作区 · `materialize_image` ← 由 plan 18 的落盘件收口 · `list_files_in` ← 从 `list_inbox` 抽前半段），
本轮新增的只有一个薄薄的「列素材库图片」+ UI 接线。**先做 §2.5 的两处收口（S1 / S2）再开工。**

## 1. 第一性问题（删除测试）

| 要素 | 删掉后 | 定性 |
|---|---|---|
| 能看到图片集合的地方（网格） | 「点开，里面都是图片」做不到 | **第一性** |
| 点一张进编辑区垫图 | 看到了用不了 | **第一性** |
| 「图进素材库」（viewer 按钮 + 弹窗按钮 + 文件管理器直放，三个入口） | 只能进不能出（单向） | **第一性**（三个入口都是"目录里多一个文件"，一条真相；不是三个能力） |
| UI 删除按钮（入口 D） | 发错的图要打开文件管理器才能删 | **第一性**（用户裁定 2026-11-26「做，svg」）—— 与入口 C 共用同一真相（目录里少一个文件），只多一个触发点 |
| 弹窗 vs 侧栏 | 能力不变（只是位置） | **非第一性** → 按用户裁定 + ADR-0010 定弹窗 |
| 分页 / 搜索 / 标签 / 排序 / 索引文件 | 用户没提 ⇒ 删掉能力不减 | **不做**（§6） |
| 外部 `G:\品牌更新.library\` 的读写 | 用户没确认它是什么库；不读写不影响本能力 | **不做**（§6） |

**三条第一性 ⇒ 最小切片必须同时覆盖**：列得出、点得进、发得回。

## 2.5 前置收口（开工前先做，否则素材库会制造第二套规则）

> 用户追问「哪些要合成单一路径才能配合更好」⇒ 逐条查过现有实现，三条要收口、一条不动。
> 判据：ADR-0005（一个能力一个入口）+ ADR-0010（先简化再排期）。

| # | 现状 | 为什么要收 | 收口后 |
|---|---|---|---|
| **S1** | **复制落盘两个入口**：`materialize_data_url`（data: → 纯哈希名）· `materialize_named_file`（路径 → 原名+哈希），共享内部 `write_named_bytes` | ⚠️ **上次判"不用合"是错的**：命名策略**由入口决定** ⇒ 素材库**确定收 data:**（用户裁定 2026-11-26）⇒ 剪贴板粘图与文件选择器会在**同一个 library 目录里造两种文件名**。⇒ **命名由目标目录决定，不由入口决定** | 一个 `materialize_image(dir, source)`，**内部**按目录定命名（`var/refs` → 纯 16 位哈希；`data/presets` + `data/library` → 原名+哈希）—— ⚠️ **不把 `Naming` 暴露成参数**，否则调用方仍能传错；两个旧入口改成它的薄适配（`gui.rs:503/505` 同批） |
| **S2** | **业务层扫目录只有 `list_inbox` 一份**（`gui.rs:130`，读 inbox + 校验 JSONL）；素材库若照抄就会变成第二份 | ⚠️ 上次说"两者同构要参数化过滤"**理由错** —— `list_inbox` 后半段还调 `inspect_jsonl` 校验内容，素材库只读文件名 ⇒ **不是同构的**。真正同构的只有**前半段**：`读目录 → 过滤扩展名 → 排序 → 不存在当空 / 读不了照抛`（`gui.rs:137-159`） | 抽 `list_files_in(dir, exts) -> Vec<PathBuf>`（**只含前半段**）；`list_inbox` 与 `list_library_images` 都调它，校验/预览各留各的。（测试里的 `read_dir(fixtures)` 是夹具加载，不在此列） |
| **S3** | **看大图三个名字**：`openViewer`（本机）· `openViewerRemote`（URL）· `openRefViewer`（分流）⇒ 共享 `openViewerSrc` | ✅ **不动**：`viewerFile` 是唯一给「发送素材库」提供路径的变量（`app.js:1283`），素材库点图走 `openViewer` ⇒ `viewerFile` 自动有值 ⇒ 发送按钮直接可用。合它要动 3 个调用点，零收益 | 保持三名字、一实现 |

**顺序**：S1 / S2 **先做**（含单测 + 探针），再做 §4 的 `library_dir()` 与两条命令 —— 否则 §3.3 的「发送」会在 library 里造出两种命名，§3.1 的「列目录」会复制第二份扫目录逻辑。

## 3. 形状与数据链

### 3.1 底层原语（新增 2 个收口件 + 1 个薄封装）

| 原语 | 状态 | 位置 |
|---|---|---|
| 图片 = **本机路径**（不是内容 / base64） | 已定 | `draft.refs` |
| **网格尺寸 = CSS 自算，不存状态** | 用户裁定 2026-11-26：不要滑杆（会新增第 2 个 localStorage 键）—— `repeat(auto-fill, minmax(160px,1fr))`，要调只改这一个数字 | `ui/style.css` |
| **加图进编辑区 = `pushRef(path)`** | ✅ 唯一加图入口 | `ui/app.js` |
| **复制文件进目录 = `materialize_image(dir, source)`** | ⚠️ **plan 18 的 `materialize_data_url` / `materialize_named_file` 先按 §2.5 S1 收口**：命名**内部按目录定**，不暴露 `Naming` 参数 | `engine/refs.rs` |
| **看大图 = `#viewer`** | ✅ 底部已有「适应窗口 \| 实际大小 \| 打开所在位置 \| 复制提示词」四个动作；三名字共享 `openViewerSrc`（§2.5 S3 不动） | `ui/index.html` |
| **扫目录取路径 = `list_files_in(dir, exts)`** | ⚠️ **先按 §2.5 S2 从 `list_inbox` 抽出前半段** | `crates/lovart-core/src/service`（新） |
| **列素材库 = `list_library_images(dir) -> [{path, name}]`** | ❌ 唯一缺的；**只加"过滤图片扩展名 + 组形状"**，扫目录复用 `list_files_in` | `crates/lovart-core/src/service/library.rs`（新） |

**三个判断（现在定，免得返工）**：

1. **库 = 目录本身，不建索引文件。** 扫目录即列表；加 `index.json` 就是**第二个真相**
   —— 图被手动删了索引还在，界面说谎（ADR-0003 / 0008）。
2. **点图进编辑区 = 引用路径，不复制。** `pushRef(data/library/xxx.webp)`，发布时读盘即可。
   若图被移走 ⇒ 缩略图破图 —— 与预设图缺失同口径（ADR-0010：用户看得见，不提示）。
3. **「发送到素材库」= 复制，不是移动。** 当前大图可能来自 `data/output/`、`data/var/refs/`、
   或任意本机路径 ⇒ 统一调 `materialize_image(data_library_dir, source)`（§2.5 S1，内部按目录定命名），
   与预设**共用同一落盘原语**；无论来源是剪贴板还是文件选择器，**library 里文件名规则只有一种**。

### 3.2 目录

`<工作区>/data/library/`，与 `data/presets/` 同级、互不嵌套；`data/` 已 gitignore（plan 19），**不再加 gitignore 行**。
备份 = 备 `data/` 一次全带走。

### 3.3 数据链（谁产生 → 怎么变形 → 谁消费）

```
打开：点工具条「素材库」
  → invoke('list_library_images')    // 后端从 Workbench::library_dir() 取目录（前端永不传路径）
        → [{path, name}]（按文件名排序；非图片扩展名跳过；不递归子目录）
  → 弹窗网格渲染（每个 = <button> + <img src=refSrc(path)>，点一下 = 用）

点一张：
  → pushRef(path)  ⇒ 进 draft.refs（唯一加图入口）
  → closeMask('maskLibrary')   // 弹窗 + 遮罩 + 不常用 ⇒ 用完即关

**发送到素材库 = 两个触发点，一条路径**（用户裁定 2026-11-26）：
两个入口只是"用户从哪触发"，**都调同一个 `send_to_library` 命令 + 同一个 `materialize_image`** —— ADR-0005 管的是"实现线唯一"，不是"UI 上只能有一个按钮"。

入口 A · 大图查看器底部（看编辑区/看板/输出的图时顺手存）：
  → 来源只从 viewer 已有的两个变量取，不另存第三份：
      viewerFile 非空（本机图）⇒ source = {kind:'path', value:viewerFile}   // `app.js:1283`
      viewerFile 为空 + $('#viewerImg').src 是 `data:`（粘贴进来的图还没落盘）
          ⇒ source = {kind:'data', value:该 data: URL}
      viewerFile 为空 + src 是 `http(s):` ⇒ **禁用发送按钮**（URL 图没有"复制"语义）
入口 B · 素材库弹窗内「＋ 发送到素材库」（和编辑区「+」同款，主动加图）：
  → 复用现有 `readFilesAsDataUrls`（plan 18 抽的唯一读取点）⇒ source = {kind:'data', value:...}
  → 或窗口拖文件进来 ⇒ source = {kind:'path', value:drop 路径}
  → ⚠️ 面板**不关**（人可能连加几张）；网格重列
        —— 与"点图取用后关面板"不矛盾：那是"用完走"，这是"继续加"

入口 C · 文件管理器（**不是 UI 按钮，但同一条真相**）：
  → 用户直接把图拖/拷进 `data/library/` ⇒ 下次打开弹窗自动出现
  → 用户直接从 `data/library/` **删文件** ⇒ 下次打开弹窗自动消失
  → 加与删都**完全等价**于 A/B（只是"目录里多/少一个文件"）
  ⇒ 不新建命令、不建索引、不弹"检测到新文件/文件已删除"（每次打开本来就重扫目录）
  ⇒ 编辑区若正引用被删的图 ⇒ 缩略图破图（ADR-0010：用户看得见，不提示）；
     **预设不受影响**（预设图是复制进 `data/presets/` 的，不是引用 library）

入口 D · UI 删除按钮（用户裁定 2026-11-26「做，svg」）：
  → 网格每张图右上角一个删除键，图标用**现成的** `svgIcon('i-trash','')`（`index.html:46` 已有，预设面板在用）—— 不新画 SVG
  → invoke('remove_library_image', { file }) ⇒ 后端只 `remove_file(library_dir.join(file))`
  → **不查引用**（查 = 第二份真相 + 复杂度）、**不删预设**（预设是复制）、**不动编辑区**（破图是可见反馈，ADR-0010）
  → 网格重列；**面板不关**（与"添加"同口径：还能继续操作）

两条 UI 入口 + 文件系统汇合：
  → invoke('send_to_library', { source })  // A/B 才走；一个入参形状，两种 source 由 enum 判别（ADR-0003）
  → 后端 materialize_image(library_dir, source)（§2.5 S1，内部按目录定命名）
  → 提示「已发送到素材库」；网格下次打开时重列（不维护"当前弹窗是否开着"这个状态）
```

**失败处理**：列目录失败 ⇒ 报 `reason`（不画空网格，那是把"读不到"说成"没有"）；
发送失败 ⇒ 报错原文，不静默。两者都不加解释层（ADR-0010 ②）。

### 3.4 命令与形状

| 命令 | 入参 | 返回 |
|---|---|---|
| `list_library_images` | 无 | `{ok:true, images:[{path,name}]}` / `{ok:false, reason, detail}` |
| `send_to_library` | `source: {kind:'path'\|'data', value:string}` —— **一个入参形状，两种来源**（URL 图在前端禁用，不到后端） | `{ok:true, name}` / `{ok:false, reason, detail}` |
| `remove_library_image` | `file: string`（文件名，不是路径 —— 前端永不传目录） | `{ok:true}` / `{ok:false, reason, detail}` |

形状只在 Rust 一处（`service/library.rs` 的返回 serde + `ImageSource` enum 作入参）；前端 `ui/library.js` 只调命令，不定义形状。
⚠️ 命令层**只有一个** `send_to_library`（不是 `path` / `data` 两个命令）—— 否则来源又成两条线（ADR-0005）。

## 5. 之后（每条一句为什么可以等）

- **侧栏形态**：用户提过，但选定弹窗（不常用功能不该占边缘）；若以后变常用，改动只是同一面板的定位变体 ⇒ 不是现在的事。
- **分页**：图少时是空转；真多了再加（用户没给数量级）。
- **搜索 / 标签 / 排序 / 索引**：用户没提 ⇒ 加就是自造需求（ADR-0010）。
- **外部 `*.library` 库的读写**：用户没确认它是什么库；"写进去了但那边不显示" = 界面说谎 ⇒ 不做、不猜。
- **素材库里的图删了 ⇒ 编辑区引用处理**：沿用破图口径（ADR-0010），不新写提示。

## 6. 不做

| 项 | 为什么 |
|---|---|
| 侧栏 / 常驻图标 | 用户裁定「不是常用功能」⇒ 弹窗；且"只是位置不同"不值得两套组件 |
| 索引文件 / 标签 / 搜索 / 分页 | 用户没提；索引 = 第二真相 |
| 点图后保留面板（**"取用"路径**） | 弹窗 + 遮罩 + 不常用 ⇒ 用完即关（与预设取用同口径）；⚠️ "添加"路径的弹窗不关（§3.3），两者不矛盾 |
| 读写 `G:\品牌更新.library\` | 用户没确认；不猜库格式、不写索引 |
| 点图进编辑区时复制图 | 同一张图落两份；引用路径即可 |
| 递归子目录 | 用户没提；库是平铺目录（每张图一个文件） |
| 素材库容量上限 | 自加限制，不写（写plan的方法 §7） |
| 缩略图尺寸滑杆 / localStorage 键 | 用户裁定「不要滑杆」；`auto-fill minmax(160px)` 零状态自适应，且现在只有 1 个 localStorage 键（迁移用），不为显示偏好加第 2 个 |

| H6 | 打开素材库弹窗 → 点「＋ 发送到素材库」→ 选一张图 | 图进 `data/library/`、网格重列、**面板不关**（可连续加第二张）；文件名规则与 H4/H5 相同 |
| H7 | **直接用文件管理器**拷一张图进 `data/library/` → 打开素材库弹窗；再回文件管理器删掉它 → 重开弹窗 | 先出现、后消失（与 A/B 入口进来的无区别）—— 证明目录是真相，命令只是入口之一 |
| H8 | 备份 `data/` 后换机恢复 | 素材库图都在、网格能列 |
| H9 | 网格某张图点右上角**垃圾桶图标**（`i-trash`） | 文件从 `data/library/` 消失、网格重列、**面板不关**；若该图正在编辑区用着 ⇒ 编辑区缩略图破图（不提示）；预设不受影响 |
| H10 | 网格缩放：窗口拉宽 / 拉窄 | `grid-template-columns: repeat(auto-fill, minmax(160px,1fr))` 自动增减列数，**每张不小于 160px**；无滑杆、无状态、不写 localStorage |

## 8. 与既有契约的关系

| 既有 | 本轮 |
|---|---|
| plan 19 `data/` 唯一数据根 | 素材库 = `data/library/`，`library_dir()` 是它的访问器 |
| plan 18 `RefStrip` | 素材库点图进编辑区**不碰**组件本身，只调 `pushRef` |
| plan 18 `materialize_named_file(dir, path)` | 先按 §2.5 S1 收口成 `materialize_image(dir, source)`：**命名内部按目录定，不暴露成参数**；「发送到素材库」只传 `source` |
| ADR-0005 一个能力一个入口 | 加图 `pushRef` 唯一 · 复制 `materialize_image` 唯一（`send_to_library` 一条命令、`source` enum 两种来源）· 面板复用 `.mask` 唯一 · **入库真相唯一 = 目录里有文件**（viewer 按钮 / 弹窗按钮 / 文件管理器直放三入口都是它的触发方式） |
| ADR-0010 可观察先于可诊断 | 图被移走（入口 C 或 D）⇒ 破图可见，不加提示；删除只删文件、不查引用；不建索引（第二真相） |
| 用户「我可没确定是 eagle 预设库」 | 本 plan 不提任何库软件名、不读写外部 `*.library` |
