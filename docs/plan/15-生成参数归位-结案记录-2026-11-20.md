## 1. 结论（一句话）

**前端对"尺寸 / 并发"的合法性判定已经消失，靠的是删掉两处前端判据，而不是新增一个能力表接口。**

已归位的部分（本轮之前就成立，不在本轮范围）：排队 / 并发调度 / 退避 / 超时 / 重试 / 下载 / 状态机全在 `engine/scheduler.rs`；状态分组与可做动作由 `run.rs:545-565` 下发，前端只画。

## 2. 已做的两处删除

| # | 位置 | 之前 | 之后 |
|---|---|---|---|
| 1 | `ui/index.html` 并发数输入框 | `min="1" max="8"` | 只留 `min="1"`；上限只有 `settings.rs:73` 的 `MAX_CONCURRENCY` 一个出处。超了保存时后端拒（`settings.rs:456`），错误可见 |

## 3. 为什么不做能力表（反例留档）

原方案（`get_capabilities` 下发 `sizes` / `concurrencyMax`）的账：

| | 内容 |
|---|---|
| 收益 | 后端改 `SIZES` 或 `MAX_CONCURRENCY` 时，界面少改一处。而这两个常量**几乎不变** |
| 成本 | 一次启动 IPC · 一个「未加载」状态（必须写进每个消费点，`0` 不能当未加载）· 一个 camelCase 键名契约（只能靠单测锁）· 一条失败回退分支（尺寸下拉只读还是给非法候选） |

净效果：为"低频常量少改一处"新增一套常驻机制 —— 用加接口解决本该用**删代码**解决的问题。

另一个可选方向（把尺寸下拉改成自由输入、彻底不要候选表）形状更纯，但 UX 退化（用户不知道能填什么），也不采用。

---

## 4. 什么条件下重新提案

满足任一即重开（届时一次做完，成本摊薄）：

1. 出现**第三类**需要前端提前知道的后端常量（例如每个模型支持的比例/尺寸，或份数上限真的进了后端校验）；
2. 真的因为"改了常量、漏改界面"踩过一次；
3. 前端需要在**提交之前**就拦住非法值（而不只是保存时被后端拒）。

---

## 5. 本轮明确不做（逐条理由）

| 项 | 理由 |
|---|---|
| 份数展开搬后端（`copies` 参数） | 删除测试不成立：展开 = 把一次输入写成 N 行，CLI 同形（`docs/详细说明.md:115`）。且 `import_inbox` 是"先校验后归位"（`gui.rs:800-803`），份数校验后移会让文件搬进 `imported/` 后才报错；`publish_queue` 只能返回"受理条数"（批次在后台线程入队，`gui.rs:682-708`） |
| `MAX_COPIES` 搬能力表 | 后端从不校验份数（`intake.rs:59-71` 只有 5 个键），20 是前端产品上限；搬过去还得留一份失败兜底，副本一个没少 |
| `[img=图片N]` 解析搬后端 | **用户已定归前端**。它是富文本的序列化结果（`ui/promptChips.js`）；搬过去还要改 token 形状，会把 `docs/plan/12` 的"拖拽顺序 = 提交顺序"重新搅乱 |
| `RATIOS` / `RATIO_CHOICES` 搬后端 | 后端接受**任意** `w:h`（`prompt.rs:218-226`），这两组是常用值清单，属表达层 |
| 待发队列搬后端 | `gui.rs:804` 已定边界：「待发队列是前端的真相」；后端队列是调度队列 |
| 粘贴张数 / 单张大小上限 | IPC 载荷保护，前端是唯一能拦的位置（`app.js:51-58`） |
| 设置页其余 `min/max`（超时 / 重试 / 间隔 / 轮询） | 与并发上限同类，但下限/上限是 `settings.rs` 里的内联字面量；真要收敛，先提成一张表，属独立重构。本轮不碰 |

## 6. 验收

1. `node --check ui/app.js`；`grep -n 'max="8"' ui/index.html` = 0 命中。
2. 真机（前端编译期内嵌 ⇒ 必须 `make win` 后点）：
   1. 设置页并发填 `9` → 保存 ⇒ 后端拒绝并说明范围，界面不变（`max` 已删，不再静默卡住输入）；
   2. 并发填 `6` → 保存成功，下次启动回显 6；
   3. 载入一条历史任务（尺寸不在候选里）⇒ 尺寸仍正确回显（`ensureOption` 补项）；
   4. 设置页尺寸下拉、编辑区尺寸下拉候选项不变（仍是 `1K/2K/4K`）。
3. 反向检查：`git diff` 只应有 `ui/index.html`、`ui/app.js` 两处，**不出现** Rust 改动、不出现 `get_capabilities`、不出现 `copies`。
