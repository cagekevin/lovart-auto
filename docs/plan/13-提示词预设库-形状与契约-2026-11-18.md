## 0. 结论（一句话）

点工具条「预设」→ 弹面板；**面板默认态 = 列表，点一条就取用**；新建 / 修改在**第二个态**（编辑器）里做，
保存后回到列表。预设与编辑区之间**只有一条通道：库 → 编辑区**。

**v3 变更（用户原话：「预设还是要给预设弄个名字，不然我都分不清哪个是哪个了」）**：
每条预设**存一个名字**（可留空，留空时列表用正文首行兜底）。名字是标签，**不参与定位**，`id` 仍是主键。

## 2. 形状

```ts
Preset = { id: string, name: string, text: string }   // name 可为空串（旧数据没有它）

Result  = { ok: true,  list: Preset[] }
        | { ok: false, reason: Reason, error? }   // ⚠️ 失败**不带 list**（不把 error 折成 []）
Reason  = 'empty' | 'missing' | 'storage'

GetResult = { ok: true, preset: Preset } | { ok: false, reason: 'missing' | 'storage' }
```

- `id`：`p` + 毫秒时间戳 36 进制 + 4 位随机；生成后**与现有 id 比对，撞了重生成一次**。
  创建时生成，**永不改变**（名字会重复、会变，不能当主键 —— R1 的根）。
- `text`：唯一载荷。**存入的是 `trim()` 之后的值**；trim 后为空 ⇒ `empty`，不落盘。
  不设长度上限（超长由用户自负，不截断——截断是偷偷改内容）。
- `name`：**存**在预设里，是给人看的标签。留空合法（`''`），显示时由 `displayName()` 拿
  `nameFrom(text)` 兜底（首行前 16 字 + `…`）。**不截断**（列表靠 CSS 省略号），
  连续空白压成一个空格。可以重名 —— 定位只认 `id`。
- `empty` **只针对正文**：只有名字、没有正文 ⇒ `empty`（一条没有正文的预设没法取用）。
- 排序：**存储顺序即展示顺序**；`create` 置顶（`unshift`），`update` **原位替换**（不动位置）。
- 存储：`localStorage['lovart.promptPresets.v2']` = `[{id,name,text}]`。
  `name` 是后加字段：**不升版本**，老数据缺 `name` ⇒ 读成 `''` 走兜底名。
- **v1 兼容（判据写死）**：**v2 键存在（哪怕是 `[]`）就以 v2 为准**，不看 v1。
  只有 v2 键**不存在**时，把 v1（`{name,text}[]`）当作初始列表**读出来用**（`name` 留用，`id` 重新生成）。
  ⚠️ 若按"v2 为空就读 v1"，用户删光预设后会**复活**旧数据。
- **读不写盘**：`list()` / `get()` 一律只读。v1 的转换结果只在内存里参与后续写操作，
  第一次 `create/update/remove` 才真正写 v2。**不删 v1**（用户数据不擅自销毁）。
- 不设条数上限（面板可滚动）。

### API（唯一导出，`ui/presets.js`）

```
list()                -> Result               // 已按展示顺序排好
get(id)               -> GetResult            // 取用/改/删前按 id 拿**存储里最新**那条
create(name, text)    -> Result
update(id, name, text)-> Result
remove(id)            -> Result
nameFrom(text)        -> string               // 兜底名（首行前 16 字）
displayName(preset)   -> string               // 有名字用名字，没名字才派生
```

`get` 存在的唯一理由：列表是**快照**，取用时可能已被删/改。
`displayName` 存在的理由：**兜底规则只有一份**，界面不许自己 `preset.name || 首行`。

## 3. 职责

| 关注点 | 唯一所有者 | 其它层只能 |
|---|---|---|
| 形状 / `id` 生成 / `trim` / `nameFrom` / `displayName` / 顺序 / v1 兼容 | `ui/presets.js`（纯函数） | 壳读 `{id, name, text}`，不自己拼对象、不自己 trim、不自己算兜底名 |
| 能不能存/改 | `presets.js`（回 `reason`） | `app.js` 只翻译 reason |
| 编辑区文本的**写入**（**唯一入口**） | `ui/promptChips.js` 的 `writePrompt(root, text, metaMap)` | `app.js` 只调它：取用预设传 `metaMap=null`（token 按文字落地） |
| 面板两态 / 焦点 / 图标接线 | `app.js` | 模块不碰 DOM |
| 视觉规格 | `ui/style.css` | JS 不写 `style.*`（浮层坐标除外） |
| 图标符号（铅笔 / 垃圾桶） | `ui/index.html` 的 `svg-defs` | 用 `svgIcon('i-edit')`，不写第二份 path |
| 后端 | **没有** —— 预设不进后端 | 不加 Tauri 命令，不读写 `var/` |

**编辑区（`#promptInput`）边界**：它只装提示词。预设功能对它是**只写不读**：

- 允许：取用时 `writePlain` 写入。
- 禁止：存/改从编辑区取值；在编辑区里挂任何预设相关控件；"当前预设"绑定/高亮；
  取用前读它判断"是否为空"（那也是一次读）。

> 因此取用**不做**"非空才确认"——要确认就无条件确认，否则不确认（本轮：不确认）。

## 4. 面板（两态，与 mockup 一致）

**态一 · 列表**（默认，打开即此态）

```
┌ 提示词预设 ────────────────────────────── × ┐
│ 人像胶片风                              ✎ 🗑 │  ← 整行 = 取用
│   85mm 定焦，柔和侧逆光，肤质保留颗粒…       │
│ ─────────────────────────────────────────── │
│ （没起名字时：这一行是正文首行前 16 字）  ✎ 🗑 │
│   完整内容单行省略…                          │
│ ─────────────────────────────────────────── │
│ ＋ 新建预设                                  │
└─────────────────────────────────────────────┘
```

- 行 = 两行文本（名字 13px/500，来自 `displayName()`；内容预览 12px/灰、单行省略）+ 两个图标动作；
  **整行可点 = 取用**，`title` = 全文。
- 空态只有一行居中灰字「还没有预设」。
- 底部**只有一个**「＋ 新建预设」；关闭只留右上 `×`（不重复第二个入口）。

**态二 · 编辑器**（新建 / 修改共用）

```
┌ 新建预设 ──────────────────────────────── × ┐
│ ┌─────────────────────────────────────────┐ │
│ │ 名字（单行，聚焦）                        │ │
│ └─────────────────────────────────────────┘ │
│ ┌─────────────────────────────────────────┐ │
│ │ textarea（148px，光标在末尾）             │ │
│ └─────────────────────────────────────────┘ │
│                              取消    保存    │
└─────────────────────────────────────────────┘
```

- 标题随来源变：`新建预设` / `修改预设`。
- 两个输入：名字（单行，**可留空**，placeholder「名字（留空就用首行）」）+ 正文 textarea。
- 无任何说明性小字（正文 placeholder 只写"写一条提示词…"）。
- `Esc`：编辑态 → 回列表（**丢弃未保存内容**）；列表态 → 关面板。点遮罩：关面板。

**取用流程（顺序是契约）**：`get(id)` → 失败 ⇒ 提示、**面板不关**（用户还能选别的）；
成功 ⇒ `writePlain` 写入 → **关面板**。

## 5. 动作契约

| 动作 | 入口 | 输入 | 落盘 | 失败 reason |
|---|---|---|---|---|
| 用 | 点列表任意一行 | `id` | 不落盘；`writePlain` 写编辑区，然后关面板 | `missing` `storage` |
| 新建 | ＋ → 编辑器 → 保存 | `name` + `text` | `unshift` 置顶 | `empty` `storage` |
| 改 | 行内 ✎ → 编辑器 → 保存 | `id` + `name` + `text` | 原位替换 | `empty` `missing` `storage` |
| 删 | 行内 🗑 | `id` | 删除该条 | `missing` `storage` |

- `missing`：该 id 已不在存储里（另一个窗口删了 / 存储被外部改写）⇒ 提示，不假装成功。
- 失败文案只在 `app.js` 的 `presetMessage` 一处；`presets.js` 只回 `reason`。
- 写操作成功与否**以返回的 `ok` 为准**，不以"没抛异常"为准。

## 6. 施工项

### S1 `ui/presets.js` 重写

按 §2 的 API 与 `Result` 形状实现；`read()` 只读、v2 键存在即为准、v1 仅作初始值；

## 7. 明确不做

| 项 | 为什么 |
|---|---|
| 搜索框 | 面板一屏能滚；十几条靠眼睛找比打字快 |
| 名字唯一性校验 | 重名是允许的（定位只认 `id`）；拦重名只会让人为了保存去改名 |
| 创建/修改时间、字数、摘要 | 面板只回答"哪一条、要不要用它" |
| 条数上限 | 面板可滚动；假上限只会逼用户删东西 |
| 取用确认框 | 点一行就是要用它，再弹一次是废话 |
| 删除确认框 | 预设是一段文本，删错了重写很快 |
| 分类/标签、拖拽排序、导入导出、云同步、`lastUsedAt` | 都不属于"选一条来用" |
| 后端存储（`var/presets.json`） | 纯前端草稿，CLI 不用；加命令等于开第二个存储真相 |

## 9. 验收（交付时逐条贴证据）

1. **模块断言**（node + mock `localStorage`）：
   - `create('名', 'A')` → `ok`、`list()` 一条、`id` 非空、`name` = 「名」、`displayName` = 「名」；
   - `create('', 'A')` → `name` 存 `''`、`displayName` 兜底 = 「A」；`create('  A  ', 'B')` → 名字 trim；
   - `create` 两条同名 → **两条都在**（重名合法，不再覆盖）；
   - `update(id, 'B', '文本')` → 名字与文本都变、`id` 不变、**在数组里的下标不变**；
   - `update`/`remove` 不存在的 id → `missing`；`remove` 后少一条，再删 → `missing`；
   - `create('', '')` / `update(id, '名', '  ')` → `empty`（只校验正文）；
   - 坏 JSON → `ok:false` + `reason:'storage'`；
   - **v1 存在、v2 不存在** → `list()` 读得出 v1 的 `text`；
   - **v2 = `[]`、v1 有数据** → `list()` 为**空**（不复活 v1）；
   - 任一失败结果 **`list` 字段不存在**（不许把 error 折成空数组）。
2. **编辑区不被读**：`ui/app.js` 预设段里 `readPlain(` / `composerText(` / `serializeDOM(`
   计数全为 0；`#promptInput` 只出现 2 次：`writePrompt(...)` 写入 + 紧随的 `.focus()`。
3. **残留清理**：`overwrite(`, `renderPresetMenu`, `openPresetMenu`, `askText`, `preset-row`,
   `preset-del`, `composerText`, `readPlain`, `writePlain`, `modal-input`
   在 `ui/` 里计数全为 **0**。
4. **语法**：`node --check ui/app.js ui/presets.js ui/promptChips.js`。
5. **真机**（`make win` 出包；前端资源编译期内嵌，拷旧 exe 不算）：
   1. 点「预设」→ 列表态（**没有 textarea**），空态显示「还没有预设」；＋ → 编辑器；
   2. 写一段 → 保存 → 回列表、出现一条、名字是首行前 16 字；
   3. 再新建一条 → 新的在前；
   4. 点任意一行 → **面板关闭**、编辑区被写入该文本（不弹确认）；
   5. ✎ → 编辑器带该条内容、标题「修改预设」→ 改一个字 → 保存 → 回列表、该条**在原位**、id 未变；
   6. 编辑态按 Esc → 回列表且**不落盘**；列表态按 Esc → 关面板；
   7. 🗑 → 该行消失（无确认）；
   8. 重启程序 → 预设仍在；
   9. 文本里带 `@{abc:名字}` → 取用后编辑区是**原样文字**，不变成芯片。
6. **取用失败不关面板**：手动把 `localStorage` 里某条删掉再点它 → 提示"已经不在存储里"，
   面板**仍然打开**。

## 10. 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| localStorage 被清 / 改应用标识 | 预设全丢 | 已在注释写明落盘位置；本轮不做导出（§7）。若用户要求，另立一轮 |
| 取用不确认 + 无撤销 | 误点覆盖正在写的提示词 | 点整行是明确动作；如反馈频繁再单独做撤销 |
| 删除无确认 | 误删 | 预设是文本，重写很快；不做确认框（§7） |
| v1 → v2 转换 | 旧数据读不出 | 只读 text、写 v2、**不删 v1**；转换失败回 `storage` 并提示 |
| 列表是快照 | 取用/改/删命中旧数据 | 写操作前一律 `get(id)` 重读；失败回 `missing` |
| 两个态用一个变量表达 | "新建"与"列表"都为 null，会串态 | 用 `presetEditor`（null / `{id}`）表达，见 §6 S4 |
| `id` 同毫秒碰撞 | 更新/删除命中错条目 | 生成后查重，撞了重生成一次 |
