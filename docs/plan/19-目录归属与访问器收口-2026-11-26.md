# 运行数据收进 `data/`（目录归属与访问器收口）· 施工契约

> 状态：**待施工**（2026-11-26 · v2：从「只补一张表」改为**真结构改动**）
> 上游需求（用户原话）：
> - 「如果加上素材库，就相当于所有文件都在同一个目录」
> - 「我不想移出去，移出去的意义是什么」⇒ **数据留在仓库树内，不移出去**
> - 「有没有可能顶层设计没做好，所以对这个目录这个难搞自洽，继续往上追问题」
> - 「现在不搞清楚，素材库不还是一样」
> - 「你这个又不改代码，纯粹就是个补丁」⇒ **v1 否掉，本版动结构**
> - 「同意 data，直接移动」⇒ 目录名 `data/`；迁移用**移动**
>
> 前置：**TD-03-1**（`Workbench::cwd()` 让调用方拼路径）· ADR-0002（调用方不出现结构知识）· ADR-0004（结构优先）
> 边界：**不把数据移出仓库**（用户否决）；只把「运行数据」收进树内的一个根。

---

## 0. 结论

仓库树不变，但**运行数据全部收进 `<工作区>/data/`**：

```
<工作区>/
  data/                     ← 唯一的运行数据根（新）
    .env                    ← 凭据
    prompts.jsonl           ← CLI 的提示词文件
    inbox/                  ← 提示词输入（用户资产）
    presets/                ← 预设：清单 + 图（plan 18；用户资产）
    library/                ← 素材库（plan 20；用户资产，本轮不建）
    output/                 ← 出图（产物）
    var/                    ← 机器状态：state.jsonl / report.csv / run.log / refs/ / refs-cache.json / .lock
  crates/ src-tauri/ ui/ scripts/ docs/ daily/ fixtures/ packaging/   ← 源码与打包输入，不再混数据
```

一条判据取代 N 条特例：**「运行数据都在 `data/` 下」**；`.gitignore` 从 6 行变 **1 行**；
备份变成「备份 `data/` 一个目录」；素材库/预设/将来的缓存**不再需要各自论证归属**。

## 1. 第一性问题（删除测试）

| 要素 | 删掉后 | 定性 |
|---|---|---|
| **运行数据集中在 `data/`** | 运行数据与源码同级混住 ⇒ 每加一类目录都要现场发明一次归属（本轮已两次：`presets/`、`library/`）、`.gitignore` 逐条打补丁、备份要记"备哪几个目录" | **第一性** |
| **新增目录的唯一落点**（`Workbench` 具名访问器 + `data_dir()`） | 目录知识散在调用方 ⇒ 搬一次目录要全仓 grep（TD-03-1） | **第一性** |
| 老数据迁移 | 用户现有 `inbox/`（14 个 jsonl）· `var/state.jsonl`（任务记录）· `output/`（出图）· `.env`（凭据）原地不动 ⇒ 新布局读不到 ⇒ **看起来像数据全丢** | **第一性**（正确性：丢数据） |
| `is_workspace()` 不再认 `src-tauri/` | 源码结构继续充当"运行环境"的识别依据 ⇒ 顶层缺陷留着 | 非第一性 → **紧邻**（不认就在启动位置**初始化 `data/`**，不跑路到别处 ⇒ §3.4） |
| `.gitignore` 一行搞定 | 6 行维护 | 非第一性 → **紧邻** |
| 把数据移出仓库 | 用户已否决 | **不做**（§6） |

**三条第一性 ⇒ 最小切片必须同时覆盖**：一个根、一个落点、一次能跑的迁移。

### 3.2 迁移（启动时自动，**直接移动**，幂等）

```
Workbench::new(cwd):
  ① migrate_layout(cwd)          ← 必须在读 .env 之前
  ② read_auto_confirm(env_path()) ...

migrate_layout(cwd) -> Vec<String>（返回搬了什么，用于日志）
  mkdir data/
  对 [".env", "prompts.jsonl", "inbox", "output", "var"] 每个 name：
      src = cwd/name      dst = data/name
      src 存在 && dst 不存在  ⇒ fs::rename(src, dst)       （同卷，原子；记一条「已迁移」）
      src 存在 && dst 存在    ⇒ **不动** + 记一条告警「两处都有，没有自动合并，请自己处理」
      其它                    ⇒ 什么都不做
```

- **幂等**：每项独立判断 ⇒ 中途失败（比如 `inbox` 搬了、`var` 没搬）下次启动继续搬剩下的。
- **不覆盖**：`data/` 里已有同名 ⇒ 停手 + 告警（正确性：不静默合并/覆盖用户数据）。
- **同卷**：`data/` 与源目录同一个父目录 ⇒ `fs::rename` 是瞬时改名，不复制字节。
- ⚠️ 迁移后**旧路径不再存在** ⇒ 用户手工脚本里写死 `var/state.jsonl` 的会找不到（写进 §10 风险 + 提示文案）。

### 3.3 `OUTPUT_DIR` 的语义变化（行为变化，写清）

`.env` 里 `OUTPUT_DIR` 现在按**工作区根**解析；改后按 **`data/`** 解析。
⇒ 老 `.env` 写 `OUTPUT_DIR=output` ⇒ 指向 `data/output`（正好是迁移目标 ✔）。
⇒ 写绝对路径 ⇒ 原样用（`Path::join` 对绝对路径是替换）✔ 不受影响。

### 3.4 工作区判据：**一个**（用户裁定 2026-11-26）

> 用户原话：「软件在哪，工作区就在哪，跟着 exe 走的」「怎么有这么多逻辑，不是说就一个，exe 同目录吗」

```
工作区 = 程序所在目录  ⇒ install_dir_from_exe(exe)
  Windows / Linux：exe.parent()
  macOS：exe 在 <...>/X.app/Contents/MacOS/ 里 ⇒ 取 X.app 的同级（包内不是放数据的地方）
```

- **删掉** `LOVART_HOME`（环境变量）· cwd 候选 · `is_workspace()`（看目录内容猜）· `pick_workspace()`（三候选排序）· `bundle_sibling_dir()`。
  ⇒ 一个能力一个入口（ADR-0005）；出事时只有一条判据要查（ADR-0008）。
- **初始化 ≠ 兜底 ≠ 闪退**：首次启动在程序所在目录建 `data/`（位置用户看得见）
  ⇒ 正常进界面，`.env` 不存在是正常状态（`load_dot_env` 静默），设置页让用户填密钥。
- **建 `data/` 失败**（例如装进只读目录）⇒ 报错退出：那是真的错了，不兜底。

### 3.5 `.gitignore`（净减）

```
# ── 全部运行数据（凭据 / 提示词 / 预设 / 素材 / 出图 / 状态 / 日志）──
data/

# ── 构建与工具产物 ──
target/  src-tauri/target/  dist/  node_modules/  .metrics/  lcov.info  *.app/  lovart-client.exe  .DS_Store
```
⇒ `var/` `output/` `.env` 三行删掉（它们现在都在 `data/` 下）；`presets/` / `library/` 那两行**不需要**（plan 18、plan 20 也不用再加）。
⚠️ **`git clean -xdf` 仍会删 `data/`** ⇒ 在 `AGENTS.md §2` 与 `.gitignore` 注释里各写一句警告 + 备份命令（§5）。

## 6. 不做

| 项 | 为什么 |
|---|---|
| 把数据根移出仓库 | 用户原话否决（「我不想移出去，移出去的意义是什么」） |
| 迁移时**复制并保留**原件 | 用户选「直接移动」；本 plan 的幂等性负责"搬一半也能续" |
| 迁移时自动合并同名的两处数据 | 合并规则无法猜（哪份新？）⇒ 停手 + 告警，由人处理 |
| 给 `library/` 预建空目录/访问器 | 没有消费者 = 死代码；plan 20 真做时加 |
| 给 `prompt-library/` 加访问器 | 代码 **0 引用**（grep 过），它是资料目录，留在工作区根 |
| 保 `src-tauri/` 作为 `is_workspace` 判据 | 那正是"源码结构当运行环境判据"的缺陷；去掉后认不出来就在启动位置**初始化 `data/`**（不跑路到用户主目录） |
| 保留旧路径的"读兼容"（两套布局都读） | 会让"数据在哪"变成两处真相；只做一次性迁移（迁移后只有一个布局） |

## 10. 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 迁移中途失败 | 一半在 `data/`、一半在根 | **幂等**：每项独立判断，下次启动续搬；日志逐项写明 |
| `src` 与 `dst` 同存（用户手动搬过一半） | 数据可能分叉 | **不动 + 告警**，由人决定；不自动合并 |
| 用户脚本写死 `var/state.jsonl` | 迁移后读不到 | 只做一次性迁移；H5 明确"显式旧相对路径不重写"；文档写清新路径 |
| `OUTPUT_DIR` 相对语义变化 | 老 `.env` 指向变化 | 默认值 `output` 正好落到 `data/output`；绝对路径不受影响（§3.3） |
| 刚解压未填密钥的目录不再被认成工作区 | 在该目录**初始化 `data/`**，正常进界面 | `.env` 不存在 ⇒ `load_dot_env` 静默，设置页显示默认值让用户填；不是闪退（ADR-0008：不跑路到别处） |
| `git clean -xdf` 删掉 `data/` | 凭据 / 提示词 / 预设 / 出图全没 | `.gitignore` 注释 + `AGENTS §2` 警告 + 备份命令（§5） |
| `fixtures` 黄金断言含旧路径 | 测试红 | §4 同批改那两个文件 |
