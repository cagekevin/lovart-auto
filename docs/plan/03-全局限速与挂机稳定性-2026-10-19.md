# 全局限速与挂机稳定性 · 改造计划

> 状态：**草案（待评审）**。
> 行号按 2026-10-19 版本。
> 性质：**改造，不是新增**。每加一个能力，必须替换/删除它取代的旧实现；同一机制只留一份代码。
> 一句话：并发不动（默认 7、硬上限 8），把「per-task busy 退避」改造成「全局任务间隔 + 429 全局熔断」。

---

## 0. 结论

把现有的 busy 处理**拆开、收窄、替换**：

1. **全局任务间隔**：`--task-interval-ms` 默认 **1000**，所有 worker 共享 `last_submit_at`；提交前必须等够。重试也算一次提交。
2. **429 全局熔断**：429 从 `busy_retries` 里摘出来，改由**全局** `breaker_until` 管；提交和轮询都受它约束。
3. **402/409 保持 per-task 退避**：`busy_retries` + `ready_at` 只留给并发满 / thread 忙。
4. **Failed 可续跑**：`--retry-failed` 复用 GUI 的 `reset_for_retry`，**抽成共享函数**，不留第二份。

**并发预算不变**：`--concurrency` 默认 **7**，硬上限 **8**。

---

## 1. 改造原则（红线）

1. **一个机制只留一份实现**：不加第二套限速、第二套错误分类、第二套重试计数、第二套重置逻辑。
2. **加了什么，就必须删掉它取代的什么**：见第 2 节对照表。
3. **不加新状态**：限流仍显示 `pending`，靠 `error` 文案区分；不动 `STATUS_TABLE`。
4. **不加新 `TaskRecord` 字段**：429 不按任务计次，用全局熔断。
5. **参数只加两个**：`--task-interval-ms`、`--retry-failed`。
6. **不做请求层闸门**：`take_job` 就是唯一闸门；以后若要按请求限速，是**替换**它，不是叠加。

---

## 2. 新增 ↔ 删除对照表（核心）

| 要加的能力 | 必须删除/替换的旧实现 | 净变化 |
|---|---|---|
| 全局任务间隔 | 无（替代"7 worker 满速提交"） | `Ctx` +`last_submit_at` / `task_interval` |
| 429 全局熔断 | **429 走 `busy_retries` + `ready_at` 的分支** | 429 不再写 `busy_retries`；`Ctx` +`breaker_until` / `breaker_level` / `rate_limit_total_wait` |
| `ErrorClass` 分类 | **`BUSY_CODES` + `is_busy_error` + `is_retryable_http_status`（双口径，409 矛盾）** | 合并成 `ErrorClass` + `classify_error`；`is_retryable_error` 派生 |
| `TakeOutcome` | `take_job() -> Option<Job>` | 替换返回类型，不加第二条取件路径 |
| `finish` 删除唤醒 | **`finish` 清空所有排队任务 `ready_at` 的循环** | **删除循环**，靠 `ready_at` + `idle_wait` |
| `set_mode` 惰性初始化 | **`run.rs:920` 启动调用 + `scheduler.rs:590` 每次提交调用** | 两处删掉，只留 `run_submit` 里一个 `mode_ready` 守卫 |
| `--retry-failed` | **GUI 私有 `reset_for_retry`** | 抽成共享函数，删 GUI 本地副本 |
| 轮询 429 开熔断 | **`poll_thread` 把 429 当瞬态吞掉的分支** | 429 改为向上返回，由 `handle_poll_error` 开熔断 |
| `--task-interval-ms` | 无 | +1 参数 |
| `--retry-failed` | 无 | +1 参数 |

### 明确不做（避免重复实现）

- ❌ 不新增 `RateGate` 模块 —— 闸门就在 `Ctx` + `take_job`。
- ❌ 不新增 `rate_retries` —— 429 用全局熔断，不按任务计次。
- ❌ 不新增 `RateLimited` 错误变体 —— 429 已由 `ErrorClass::RateLimit` 表达。
- ❌ 不新增状态（`RateLimited` / `Throttled`）—— 仍用 `pending` / `running` + `error`。
- ❌ 不新增令牌桶 / `--max-api-per-min` —— 间隔就是节流。
- ❌ 不做 `Retry-After` —— 先用常量指数退避，和现有 `BUSY_BACKOFF_*` 同风格。
- ❌ 不加文件锁 —— GUI 已有 `state.running` 闸；CLI 由使用者保证单实例。
- ❌ 不把闸门下沉到 `lovart_request` —— 那会变成第二套限速。

## 3. 详细改造

### 3.1 错误分类：三份口径 → 一张 `ErrorClass`

**现状**（`lovart/errors.rs:189-233`）：

```
pub const BUSY_CODES: [i64; 6] = [402, 409, 429, 2011, 2012, 1429];
pub fn is_busy_error(error: &LovartError) -> bool { ... }
pub fn is_retryable_http_status(status: i64) -> bool { ... }  // 0/402/408/429/5xx
```

**既有矛盾**：`BUSY_CODES` 把 `409/2011` 当 thread 忙（可退避），`is_retryable_http_status` 却把 `409` 判为不可重试。结果 **提交阶段的 409 会重投，轮询阶段的 409 会被判死**。

**改成一张表 + 一个类型化结果**：

```
pub enum ErrorClass {
    RateLimit,    // 429 / 1429
    Concurrency,  // 402 / 2012
    ThreadBusy,   // 409 / 2011
    Transient,    // 0 / 408 / 5xx / Transport
    Hard,         // 400/401/403/404 / 2xx 非 JSON
}

pub fn classify_error(error: &LovartError) -> ErrorClass;

pub fn is_retryable_error(error: &LovartError) -> bool {
    matches!(classify_error(error), RateLimit | Concurrency | ThreadBusy | Transient)
}
```

- 先查 `biz_code`，再查 HTTP `code`。
- **删除 `is_busy_error`、`BUSY_CODES`、`is_retryable_http_status`**；`is_retryable_error` 变成 `ErrorClass` 的派生谓词，不再有第二份可重试码表。
- **测试要跟着改**：`tests/client_contract.rs` 改用 `classify_error` / `is_retryable_error`；`409` 的断言从「不可重试」改成「可重试（ThreadBusy）」。
- 码与语义只有一张表，409 的提交/轮询行为由此统一。

### 3.2 429 从 per-task 退避里摘出来

**现状**：429 和 402/409 一样走 `busy_retries += 1` + `ready_at`（`scheduler.rs:669-712`）。

**改成**：

| `ErrorClass` | 提交阶段处理 |
|---|---|
| `RateLimit` | **只开全局熔断**；`requeue(Pending, { ready_at: 0 })`，**不写 `busy_retries`** |
| `Concurrency` / `ThreadBusy` | 保持 `busy_retries += 1` + `ready_at` 指数退避 |

- 429 显式 `ready_at: 0`，避免残留旧的 402 退避值把任务拖住；真正的等待由全局 `breaker_until` 负责。
- `busy_retries` 语义收窄为「并发满 / thread 忙的重投次数」，不再混 429。
- `--max-busy-retries` 默认 60 → **300**。

### 3.3 全局闸门：`Ctx` 字段 + `take_job` 一个检查

**`Ctx` 加 5 个字段**（和 `queue` 同级，同一把锁）：

```
last_submit_at: Option<Instant>
task_interval: Duration
breaker_until: Option<Instant>
breaker_level: u32
rate_limit_total_wait: Duration
```

**`take_job` 返回类型改成 `TakeOutcome`：**

```
enum TakeOutcome { Job(Job), Wait(u64), Empty }
```

**取件逻辑（严格按序）：**

```
1. now = Instant::now()
2. breaker_wait = breaker_until.saturating_sub(now)
3. 遍历 queue 找最佳候选：
   - 跳过 status.job == None（终态/提交中）
   - 跳过 ready_at > now（任务自身退避未到）
   - 若是 Submit 且 slots >= concurrency → 跳过（槽满）
   - 若是 Submit 且 breaker_wait > 0 → 跳过（熔断中）
   - 若是 Submit 且 now - last_submit_at < task_interval → 跳过（间隔未到）
   - 按 priority 取最小
4. 若没有候选：
   - queue 空 → Empty
   - 否则 → Wait(min(breaker_wait, 间隔剩余, 最早 ready_at, IDLE_POLL_MS))
5. 认领：last_submit_at = now（Submit 才写）
6. 返回 Job
```

**关键点：**

- **闸门挡住 Submit 时，要跳过它继续找下一个候选**，而不是立刻 `Wait`——否则 `Redownload` / `RecheckFinal`（优先级比 Submit 低）会被饿死。
- `Wait` 取「熔断剩余、间隔剩余、最早 `ready_at`、`IDLE_POLL_MS`」的**最小值**，保证为最早的事件醒来。
- 等待发生在 `take_job` 返回之后，worker 在锁外 `sleep_or_abort`，**不占 `Submitting` 槽**，不会出现「7 个 worker 全睡在提交上、没人轮询」。
- `worker_loop` 只改一处：`Wait(ms)` → 锁外 sleep。

### 3.4 429 熔断：常量 + 一个方法

**常量**（与现有 `BUSY_BACKOFF_BASE_MS` / `BUSY_BACKOFF_MAX_MS` 同风格，不加 CLI 参数）：

```
RATE_LIMIT_BACKOFF_BASE_MS = 60_000
RATE_LIMIT_BACKOFF_MAX_MS  = 900_000
RATE_LIMIT_TOTAL_WAIT_ALERT_MS = 6 * 3600 * 1000   // 仅告警，不新增暂停状态
```

**`Ctx::on_rate_limited()`**：

```
wait = min(RATE_LIMIT_BACKOFF_MAX_MS, BASE * 2^(level))
breaker_until = now + wait
level += 1
rate_limit_total_wait += wait
if rate_limit_total_wait > ALERT: log("⚠️ 累计限流等待 X 分钟，疑似配额耗尽，建议停止检查账户")
log("🚧 429 限流，全局暂停 Xs（第 N 次）")
```

- 成功提交：`level = 0`；**不清未来的 `breaker_until`**，让它自然到期（避免一个成功把别人的熔断关掉）。
- 累计等待只**告警**，不新增 `paused` 状态（用户自己决定停不停）。

### 3.5 轮询阶段的 429：不再吞掉，交给调度器开熔断

**现状**：`poll_thread`（`lovart/task.rs:161-251`）把 429 当成 `is_transient`，自己 10→60s 退避，**永远不会返回给 `handle_poll_error`**，所以轮询触发的限流不会开全局熔断。

**改成**：

- `poll_thread` 的三处错误分支（`get_status`、done 后二次 `get_status`、`get_result`）在 `is_transient` 之前加：
  ```
  if classify_error(&error) == ErrorClass::RateLimit {
      return Err(error);   // 不吞，交给调度器
  }
  ```
- `handle_poll_error`（`scheduler.rs:962`）在 `match error.kind()` **之前**加：
  ```
  if classify_error(error) == ErrorClass::RateLimit {
      shared.on_rate_limited();
      if is_final_sweep {
          // 收尾只跑一轮：只落状态，不 requeue（否则可能死循环）
          shared.update(id, Unresolved, RecordPatch { error: Some(Some("限流，全局暂停中")), .. });
      } else {
          shared.requeue(id, Running, RecordPatch { ready_at: Some(0), error: Some(Some("限流，全局暂停中")), .. });
      }
      return;
  }
  ```

**关键：轮询 429 必须保持 `Running` / `Unresolved`，绝不能回 `Pending`**——回 Pending 会重新提交，重复生成。兜底阶段（`is_final_sweep`）只 `update` 不 `requeue`（详见 04 契约）。

### 3.6 `finish` 删除唤醒

**现状**（`scheduler.rs:364-380`）：任何终态都清空**所有**排队任务的 `ready_at`。

**改成：直接删除这个循环，不做任何唤醒。**

```
Shared::finish(id, new_status, patch)
  ├─ 锁 Ctx
  ├─ state.update(id, patch)
  └─ 解锁；日志
```

- 它是本次事故的放大器（一个终态唤醒 155 个，同步撞限流）。
- 它是纯优化：没有它，402/409 的任务最多等到自己的 `ready_at` 到期（`busy_backoff` 封顶 60s），`TakeOutcome::Wait` 会按 `ready_at` 到期唤醒。
- 删掉它，少一个机制、少一类 bug；代价只是 402 重投最多慢 60s，在 1s 全局间隔下可接受。

### 3.7 `set_mode` 惰性初始化（不是简单删除）

**现状**：`run.rs:920` 启动调一次；`scheduler.rs:590-594` **每次提交前又调一次**（一次提交 = 2 个请求）。如果只删 per-submit 调用、保留启动调用，启动那次失败后就没有任何地方再设置模式（可能按 fast 扣费）。

**改成**：

- **删除** `run.rs:920` 的启动调用。
- **删除** `scheduler.rs:590-594` 的 per-submit 调用。
- `Ctx` 加 `mode_ready: bool`。
- `run_submit` 开头：
  ```
  if !shared.mode_ready():
      ports.set_mode(deps, true)?;   // 失败 → handle_submit_error（429 开熔断、重投）
      shared.mark_mode_ready();
  ```
- `mode_ready` 用 **once 守卫**（`AtomicBool::compare_exchange` 或锁内 `mode_initializing`），避免 7 个 worker 同时调 `set_mode`。
- 提交遇到 mode 相关错误时 `mark_mode_stale()`，下次提交重设。

**净效果**：两个调用点合并成一个惰性初始化点；正常跑批只调 1 次。

### 3.8 `--retry-failed` 复用同一份重置

**现状**：`gui.rs:717 reset_for_retry` 是 GUI 私有；CLI 没有。

**改成**：

- 把重置逻辑抽成纯函数（`engine/state.rs` 或 `engine/retry.rs`）：
  ```
  pub fn reset_for_retry(store: &mut StateStore, id: &str) -> Result<(), StateError>
  ```
- `gui.rs` 只保留「跑批中禁止重跑」的检查，然后调共享函数（**删除本地补丁**）。
- CLI 建队时，对 `Failed && thread_id.is_none()` 调同一个函数：

```
{ status: Pending, attempts: 0, busy_retries: 0, ready_at: 0,
  thread_id: clear, artifacts: clear, files: clear, error: clear }
// ref_urls / ref_signature 保留（重跑仍要带垫图）
```

- 带 threadId 的 Failed：日志跳过，避免重复生成。
- **一份补丁，两个调用方**。

## 5. 边界情况

1. **7 个 worker 同时等间隔**：`take_job` 返回 `Wait`，worker 在锁外 sleep；醒来重新抢。
2. **等待中 Ctrl+C**：`sleep_or_abort` 200ms 粒度响应。
3. **429 在提交**：开熔断；任务回 `Pending`、`ready_at=0`、不写 `busy_retries`。
4. **429 在轮询**：开熔断；非兜底保持 `Running`、兜底只 `update(Unresolved)`；**不回 Pending**，兜底也不 requeue（详见 04）。
5. **402/409**：只退避该任务，全局不受影响。
6. **熔断期间**：Submit 和 Recheck 都 `Wait`；Running 任务的轮询暂停，熔断到期继续。
7. **熔断导致轮询超时**：`task_timeout` 90 分钟，熔断封顶 15 分钟；单次熔断不会超时，连续熔断可能超时 → 转 `Timeout`，由现有复查机制兜底。
8. **重启**：`ready_at` 落盘；`breaker_until` / `last_submit_at` / `mode_ready` 在内存，重启后重新开始（可接受）。
9. **时钟**：闸门用 `Instant`（单调）；`ready_at` 用 `now_ms`（要落盘），不混用。
10. **下载**：走 `reqwest` 直连，不占闸门；**上传**：走 `lovart_request`，靠间隔约束。
11. **`state.jsonl` 膨胀**：加载时自动 compact，无需处理。
12. **`queue.jsonl`**：是 GUI 导出的提示词清单，不是状态源；只重置 `state.jsonl`。
13. **`set_mode` 并发**：once 守卫，避免 7 个 worker 同时调。
14. **闸门挡住 Submit 时**：跳过 Submit 继续找 `Redownload` / `RecheckFinal`，不让低优先级任务饿死。

## 7. 测试（假 Transport，零网络）

1. `classify_error`：6 个码各自归到正确 `ErrorClass`；`409` 可重试；`is_busy_error` / `is_retryable_http_status` 已删除（编译期保证无第二份）。
2. **提交 429**：开全局熔断；**不写 `busy_retries`**；`ready_at=0`；熔断期间 `take_job` 返回 `Wait`。
3. **轮询 429**：`poll_thread` 返回错误；`handle_poll_error` 开熔断；任务保持 `Running`，**不回 Pending**。
4. **402/409**：仍走 `busy_retries` + `ready_at`，全局不受影响。
5. **间隔**：连续两次提交间隔 ≥ `task_interval`；重试也受约束。
6. **`finish`**：不修改任何其他任务的 `ready_at`（唤醒已删除）。
7. **`--retry-failed`**：只重置无 threadId 的 Failed；GUI 与 CLI 走同一个函数。
8. **`set_mode`**：正常跑批只调 1 次；并发首提不会重复调用。
9. **端到端**：160 任务 + 前 K 次 429 → 全部完成；提交间隔全部达标。

## 8. 分期

**一次做完，不分两期。** 本计划没有「请求层闸门」——那会是第二套限速，明确不做。

如果以后确实需要按请求级限速，正确做法是**替换** `take_job` 闸门，而不是在旁边再加一个 `RateGate`。

## 10. 验收标准

- [ ] 并发仍为 7，硬上限 8 未下调。
- [ ] 任意连续两次提交间隔 ≥ `--task-interval-ms`（含重试）。
- [ ] 429 期间全局提交数 = 0；429 **不再**写 `busy_retries`。
- [ ] 轮询 429 会开熔断，且任务**不回 Pending**（不重复生成）。
- [ ] 402/409 只影响单任务，不影响全局。
- [ ] `is_busy_error` / `BUSY_CODES` / `is_retryable_http_status` 已删除，无第二份分类；测试同步更新。
- [ ] `run_submit` 里不再有 per-submit `set_mode`；正常跑批只调 1 次。
- [ ] `finish` 不再唤醒任何任务（其他任务的 `ready_at` 不变）。
- [ ] `reset_for_retry` 只有一份，GUI 与 CLI 共用。
- [ ] 无 `rate_retries`、无 `RateLimited`、无 `RateGate`、无令牌桶、无新状态。
- [ ] `cargo test` 全绿，新增测试覆盖 1~9。

## 11. 第二轮复查修正（本轮新增的洞）

| # | 洞 | 修正 |
|---|---|---|
| 1 | `poll_thread` 把 429 当瞬态**吞掉**，轮询限流永远不开熔断 | 429 直接 `return Err`，由 `handle_poll_error` 开熔断 |
| 2 | 轮询 429 若回 `Pending` 会**重复生成** | 非兜底保持 `Running`；兜底只 `update(Unresolved)`，不 requeue |
| 3 | `set_mode` 不能简单删——启动失败后没人再设 | 改成 `mode_ready` **惰性初始化**，两处调用合并成一处 |
| 4 | `take_job` 挡住 Submit 就 `Wait`，会**饿死** `Redownload` / `RecheckFinal` | 挡住时跳过 Submit，继续找下一个候选 |
| 5 | `Wait` 只算间隔，会漏掉更早的 `ready_at` / 熔断到期 | `Wait` 取四者最小值 |
| 6 | 删 `is_busy_error` 会**编译失败**（测试引用） | 同步改 `tests/client_contract.rs` |
| 7 | `finish` 需要 `prev` 状态判断是否真释放槽位 | 先读 `prev` 再 `update` |
| 8 | `Ctx` 漏了 `rate_limit_total_wait` | 补上 |

## 11.1 第三轮架构审核（SSOT / 重复实现 / 复杂度位置）

| # | 发现 | 修正 |
|---|---|---|
| 1 | `BUSY_CODES` 与 `is_retryable_http_status` 双口径：409 提交可退避、轮询被判死 | 收成 `ErrorClass` 一张表；`is_retryable_error` 派生；删 `is_retryable_http_status` |
| 2 | 两套退避公式（5→60s、60→900s）各写一遍 | 收成 `exponential_backoff(level, base, max)` 一个实现 |
| 3 | `finish` 唤醒是纯优化，却是事故放大器 | **删除唤醒**，靠 `ready_at` + `idle_wait` |
| 4 | `task_interval` / `max_busy_retries` 默认值在 `run.rs` 和 `run_scheduler` 各一份 | 默认只在 `run_scheduler`；`run.rs` 未给参数时传 `None` |
| 5 | 闸门 5 个字段散在 `Ctx` 上，方法也散 | 收进私有 `SubmitGate`（同文件，不是新模块） |
| 6 | `mode_initializing: bool` + 等待循环易错 | 改成 `Shared.mode_init: Mutex<()>` 双检 |

## 12. 与上一稿的差异

| 项 | 上一稿 | 本稿 |
|---|---|---|
| 性质 | 叠一层限速 | **替换现有 busy 退避** |
| 错误分类 | 新增 3 个判据 + 保留 `is_busy_error` | **一张 `ErrorClass`，`is_retryable_error` 派生** |
| 429 计数 | 新增 `rate_retries` | **不新增；429 不按任务计次** |
| 轮询 429 | 未处理 | **返回给调度器开熔断，且不回 Pending** |
| `set_mode` | 删 per-submit，保留启动 | **两处都删，改惰性初始化** |
| 闸门 | 新增 `RateGate` 模块 | **只在 `take_job`，一个闸门** |
| 节流 | 令牌桶 + 间隔 | **只留间隔** |
| 参数 | 8+ 个 | **2 个** |
| 新状态 | `RateLimited` | **不加** |
