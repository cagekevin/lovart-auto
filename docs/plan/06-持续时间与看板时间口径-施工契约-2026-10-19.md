# 持续时间与看板时间口径 · 施工契约（State 1 契约 / State 2 数据流 / State 3 测试）

> 状态：**草案（待评审）**。
> 本文是唯一规范：字段语义、状态矩阵、显示文案、排序规则、测试断言都以这里为准。
> 行号按 2026-10-19 版本；施工后以函数名为准。

---

## 0. 需求复述

1. **只有正在生产（占用服务端槽位）的任务才显示"已持续"**，并且每秒更新。
2. **完成后停止计时**，改为静态的「结束 时刻」。
3. **还没提交的任务不显示持续时间**——它没开始，没有"持续"可言。
4. 顺带收口同一事实的多份实现，删掉明显多余的字段与显示行。

# State 1 · 契约

## 1.1 输入源（时间字段的真源）

| # | 来源 | 字段 | 语义 | 写入时机 |
|---|---|---|---|---|
| I1 | `state.jsonl` | `state_since` | **进入当前 status** 的时刻（ISO） | 仅在 `status` 变化时写（`StateStore::update`，`state.rs:877`）；新建记录 = 创建时刻（`state.rs:564`） |
| I2 | `state.jsonl` | `submitted_at` | **首次拿到 threadId** 的时刻（ISO） | 首次 `thread_id` 落库时写；重跑重置时清空（`state.rs:882-889`） |
| I3 | `state.jsonl` | `updated_at` | 最后一次落盘时刻 | 每次 `update` 都写；**不是**状态起点 |
| I4 | `STATUS_TABLE` | `holds_slot` / `terminal` / `actions` | 状态属性（唯一真源） | 编译期常量 |

**不新增任何输入源**：不新增记录字段、不读 `.env`、不加时钟注入。

## 1.2 输出目标

| # | 目标 | 形态 | 写入点 | 可见性 |
|---|---|---|---|---|
| O1 | `--status --json` / `get_state` | `stateSinceText: string \| null` | `run.rs::build_status_json` | GUI / CLI / 外部脚本 |
| O2 | 终端看板 | 文本（`[已持续 X]` 或 `结束 MM-DD HH:MM`） | `run.rs::print_status` | CLI |
| O3 | 任务卡 | DOM 文本（`已持续 X` / `结束 MM-DD HH:MM`） | `ui/app.js::taskCard` | GUI |
| O4 | 轮询原地更新 | `[data-elapsed]` 文本 | `ui/app.js::refreshBoard` | GUI |

**明确删除**：JSON 的 `generatedAt`；前端卡片 `task-time` 整行；CLI 的 `· 已提交 X`。

## 1.3 `stateSinceText` 字段契约（**语义收窄**）

| 记录状态 | `group` | `stateSinceText` | 说明 |
|---|---|---|---|
| `pending` | queued | `null` | 还没提交 |
| `unresolved` | queued | `null` | 等下次兜底复查，不在生产 |
| `download_failed` | queued | `null` | 图已生成，只差取回 |
| `submitting` | active | `"12秒"` | 正在提交 |
| `running` | active | `"3分20秒"` | 正在生成 |
| `timeout` | active | `"1分05秒"` | 占槽复查中 |
| `needs_confirm` | waiting | `null` | 停住等人，不计时 |
| `done` / `failed` / `no_artifact` | finished | `null` | 终态，改看 `stateSince` 绝对时刻 |

- 类型：`string | null`，**不再下发 `"—"`**。
- 格式（沿用 `format_elapsed`）：`45秒` / `12分30秒` / `1时05分`。
- 判据唯一：`task_group(status) == "active"`。**不新增第二份状态清单。**

## 1.4 状态矩阵（渲染契约）

| 组 | 卡片时间格 | CLI 行尾 |
|---|---|---|
| active | `已持续 {stateSinceText}`，每秒原地更新 | `[已持续 {stateSinceText}]` |
| queued | **无** | 无 |
| waiting | **无**（异常块已有「需你确认」） | 无 |
| finished | `结束 {formatTime(stateSince)}`，静态 | `结束 {MM-DD HH:MM}`，静态 |

- `stateSince` 缺失（TS 时代旧记录）：GUI 不渲染该格；CLI 打 `结束 未知`。
- `finished` 显示**绝对时刻**，不显示"结束至今多久"。

## 1.5 排序契约（`board_order`）

按 `task_group` 分档，组内规则如下：

| 组 | rank | 组内排序 |
|---|---|---|
| active | 0 | `line` 升序（无 `line` 用 `id`） |
| queued | 1 | `line` 升序（无 `line` 用 `id`） |
| waiting | 2 | `state_since` 倒序（未知沉底），再 `id` |
| finished | 3 | `state_since` 倒序（未知沉底），再 `id` |

- 取代现有 `(is_unfinished, state_since)` 二分：`needs_confirm` 不再沉进「已结束」。
- 前端四组各自过滤渲染，组间顺序由版面决定，组内顺序由本函数决定。

## 1.6 边界

**In scope**：`stateSinceText` 语义收窄、`board_order` 分档、CLI 分组与时间显示、前端卡片时间格、删 `generatedAt` / `task-time` / `· 已提交`。

**Out of scope**：
- 不新增「总耗时」（`submitted_at → state_since`）——需要时另立契约。
- 不改 `state_since` / `submitted_at` / `updated_at` 的写入时机。
- 不改 `STATUS_TABLE`、`TaskRecord` schema。
- 不改 `resume_unfinished`（`is_unfinished`）与 `remove_open_tasks`（`is_board_open`）的作用域差异——见 1.7。
- 不动 `filesPresent` 每秒磁盘 stat 的开销。

# State 2 · 数据流

## 2.1 单向链路

```
state.jsonl（唯一真源）
  └─ StateStore::all()
      └─ board_order()                     ← 排序唯一入口（按 task_group 分档）
          └─ 逐条派生：
               group        = task_group(status)
               elapsed_text = active ? format_elapsed(state_since) : None
          └─ build_status_json()           ← 展示字段唯一出口
               stateSinceText = elapsed_text（null 表示"不显示时长"）
               stateSince / submittedAt / updatedAt 原样
               （generatedAt 删除）
      ├─ GUI get_state()  ──► ui/app.js 四组渲染 + data-elapsed 原地更新
      └─ CLI print_status()
            ├─ --json  ⇒ 直接复用 build_status_json（**不再前置读盘**）
            └─ 文本    ⇒ 复用 files_present() / status_counts()，按 task_group 四段
```

- **没有任何一层自己算时间**：前端只显示字符串；CLI 只显示字符串。相对时长只在 Rust 算一次，避免多端时钟漂移。
- **读盘只读一次**：`print_status` 的 JSON 分支提前返回，文本分支才打开 store；两条路径都不重复 `all()` / `board_order` / 产物 stat。

## 2.2 单条任务时序

| 步 | 事件 | status | group | `state_since` | 卡片显示 |
|---|---|---|---|---|---|
| 1 | 建记录 | pending | queued | 创建时刻 | 无时间格 |
| 2 | 被 worker 认领 | submitting | active | 认领时刻 | 已持续 0秒 起跳 |
| 3 | 拿到 threadId | running | active | 提交成功时刻 | 已持续（从 0 重算） |
| 4 | 402/429 重投 | pending | queued | 重投时刻 | **时间格消失** |
| 5 | 再次认领 | submitting | active | 认领时刻 | 从 0 重新起跳 |
| 6 | 终态 | done/failed/… | finished | 完成时刻 | 结束 MM-DD HH:MM |

> 契约明确：`stateSinceText` 是**当前这一段状态**的时长，不是任务总耗时；重投后归零是预期行为。要总耗时另立契约。

## 2.3 一致性约束

1. `stateSinceText` 非空 ⇔ `group == "active"`（唯一判据）。
2. 前端不得出现 `'—'` 判断；`null` 即不渲染。
3. CLI 四段分组顺序固定：处理中 → 排队 → 待你处理 → 已结束。
4. 终态一律显示绝对时刻，不显示相对时长。
5. 文本看板与 JSON 看板的分组、顺序、时长必须来自**同一组函数**（`task_group` / `board_order` / `elapsed_text`），不得各写一份。
6. `print_status` 的 `--json` 分支必须在任何读盘动作**之前**返回，禁止"先读一遍再调 `build_status_json` 再读一遍"。

## 3.2 手工验收

## 3.3 回归风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 外部脚本读 `generatedAt` | 字段消失 | 全仓零消费；在 README/CHANGELOG 注明 |
| 外部脚本读 `stateSinceText` 的 `"—"` | 变成 `null` | 同上；无文档承诺 |
| CLI 文本分组变化 | 人读为主 | 文本输出本就不是稳定接口 |
| 前端签名未含时间 | 计时节点残留 | 签名已含 `status`，组变化会重建 DOM |
| 文本 summary 显示范围与 JSON 不同 | 误以为漏了状态 | 刻意：文本只列「未完成 / 有异常」，JSON 列全量；在 `status_counts` 旁注释说明 |
| `print_status` 提前返回 | 文本分支变量作用域变化 | 只移动 `if as_json` 位置，文本逻辑原样 |
