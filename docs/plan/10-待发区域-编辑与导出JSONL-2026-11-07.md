# 待发区域：编辑 / 导出 JSONL

> 2026-11-07 · 一期一事：**让待发队列能改、能存**。导入已有，不改发送。

## 要什么

用户想把发送队列编排好、**先不生成**，存成 JSONL；以后想跑时再导入、再改。

| 能力 | 现状 | 本期 |
|---|---|---|
| 导入 | `inbox` 已有 | 不动 |
| 编辑 | 无 | **待发面板加「编辑 JSONL」**（文本编辑器） |
| 导出 | 无 | **待发面板加「存为 JSONL」**（选路径存） |

## 怎么做（就两条数据流）

```
编辑：  点「编辑 JSONL」 → 文本 = 待发序列化 → 改 → 保存
        → validate_draft(text)
             ├─ 有错 → 列出来，**不动待发**
             └─ 无错 → 待发 = 解析结果 → 关窗

导出：  点「存为 JSONL」 → 保存对话框 → export_draft(text, path)
```

## 后端只有两个命令

```rust
validate_draft(text) -> { tasks, errors }   // 复用 parse_prompts，就是 --check 那份
export_draft(path, text) -> path            // 直接写文件
```

`validate_draft` **不新增任何校验**：内部调 `parse_prompts`（CLI `--check`、投喂前校验用的同一份），错误原样带回（形如「第 3 行：prompt 必填」）。

## 三条边界

1. **不落盘到固定文件**：没有 `var/draft.jsonl`，没有自动保存。存哪里由用户在保存对话框里定。
2. **不改发送**：`publish_queue` 一个字节不动。
3. **关窗口会丢待发**：与现在一致。要「重开还在」是另一期的事。

## 验收

1. 加 5 条 → 编辑 JSONL → 改一条模型 → 保存 → 待发里那条变了。
2. 删掉某行 `prompt` → 保存 → 报「第 N 行：prompt 必填」，**待发不变**。
3. 存为 JSONL → `.\lovart-client.exe --prompts 那个文件 --check` 通过。
