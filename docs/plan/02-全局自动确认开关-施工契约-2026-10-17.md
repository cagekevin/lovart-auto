## 0. 需求复述

一个**全局持久**开关：打开后，所有批次（GUI 发布 / 重跑异常 / 接着查 / CLI）在轮询中遇到上游 `pending_confirmation`（高成本操作）时，**自动确认并继续**；关掉后下一次判定立刻停止。历史 `needs_confirm` 不补确认。花钱必须可见：顶栏常驻状态 + 本批计数 + 批次结束告警。

**一个控件**：顶栏 chip。设置页不再放第二个开关（同一件事的第二套 UI/命令面，已删）。

# State 1 · 契约

## 1.1 输入源

| # | 来源 | 形态 | 解析规则 | 失败怎么办 |
|---|---|---|---|---|
| I1 | 顶栏 chip | 点击 → `invoke('set_auto_confirm', { enabled })` | `enabled: bool` | 命令 `Err(String)` → `notice` 原文，界面状态不变 |
| I2 | `.env` 文件 | `LOVART_AUTO_CONFIRM=<值>` | `read_auto_confirm` → `(bool, Option<告警文案>)` | 缺键/文件不存在 ⇒ `(false, None)`；非法值/读失败 ⇒ `(false, Some(文案))` |
| I3 | CLI 参数 | `--auto-confirm` / `--no-auto-confirm` | `known_args()` 白名单；两者互斥 | 同时出现 ⇒ 报错退出，不跑 |
| I4 | 上游状态 | `GET /chat/status` 的 `status`；`GET /chat/result` 的 `pending_confirmation` | 既有判定（精确字符串 / `is_truthy`，`task.rs:121-177`） | 既有轮询错误处理 |
| I5 | 批次结束 | `run_scheduler` 返回（返回前已 join 全部 worker） | — | 既有 |

## 1.4 边界

**In scope**：开关持久化与热更新；轮询中的自动确认（status + result 两处）；每任务每批一次许可；计数 / 告警 / chip / CLI；`.env` 读写统一到 `connection.rs`。

### 1.7.6 内部接口形状

```text
// lovart/task.rs —— 协议层只认三态，不知道策略怎么来的
pub enum AutoConfirmDecision { Allow, Disabled, AlreadyUsed }

pub fn poll_thread(
    deps: &ClientDeps,
    thread_id: &str,
    allow: &dyn Fn() -> AutoConfirmDecision,   // 在"即将确认"那一刻求值
    confirmed: &AtomicUsize,                    // confirm 成功后 +1，与轮询收场无关
) -> Result<Value, LovartError>

// 两处 pending 分支共用的唯一实现（Ok = 继续轮询）
fn resolve_pending(
    deps: &ClientDeps,
    thread_id: &str,
    allow: &dyn Fn() -> AutoConfirmDecision,
    confirmed: &AtomicUsize,
) -> Result<(), LovartError>

// engine/scheduler.rs —— 一个机制，三件事
pub struct AutoConfirm {
    enabled: Arc<AtomicBool>,            // 与 GuiState 共享（热更新）
    confirmed: AtomicUsize,              // 本批计数
    attempted: Mutex<HashSet<String>>,   // 本批许可
}
impl AutoConfirm {
    pub fn new(enabled: Arc<AtomicBool>) -> Arc<Self>;
    pub fn disabled() -> Arc<Self>;                 // 测试 / 默认
    pub fn decide(&self, id: &str) -> AutoConfirmDecision;
    pub fn confirmed(&self) -> &AtomicUsize;
    pub fn count(&self) -> usize;
}

// 端口
Ports::poll(deps, thread_id, task_timeout, allow, confirmed)

// 结构体增量
SchedulerOptions.auto_confirm: Arc<AutoConfirm>   // 1 个字段
Shared.auto_confirm:          Arc<AutoConfirm>   // 1 个字段
RunningBatch.auto_confirm:    Arc<AutoConfirm>   // 1 个字段（读计数）
GuiState.auto_confirm:        Arc<AtomicBool>
GuiState.env_lock:            Mutex<()>

// connection.rs —— .env 的唯一读写入口
pub const AUTO_CONFIRM_KEY: &str = "LOVART_AUTO_CONFIRM";
/// 值 + 需要告知用户的问题（None = 一切正常）。读失败/非法值都降级为 false 并给文案。
pub fn read_auto_confirm(path: &Path) -> (bool, Option<String>);
pub fn update_env_keys(path: &Path, updates: &[(&str, String)]) -> Result<(), String>;
fn env_line_key(line: &str) -> Option<&str>;   // 与 parse_dot_env 共用
```

**`decide` 的判定顺序**：先 `enabled`（关 ⇒ `Disabled`，不碰集合），再占位（首次 `Allow`，否则 `AlreadyUsed`）。关掉后已用许可的任务报"未开启"，对应用户最后一个动作。

## 1.8 边缘情况判定表

| 场景 | 判定 |
|---|---|
| `.env` 不存在 / 缺键 | 关；不告警 |
| 值为 `1` / `yes` / 空 / 乱写 | 关 + 告警 |
| `.env` 读失败（文件存在） | 关 + 告警（`load_dot_env` 对读失败静默，必须这层报） |
| 写 `.env` 失败 | 返回错误；**内存值不变**（先写盘成功再 store） |
| 原行是 `export KEY=...` / `KEY = value` | 更新器必须认出来（共用 `env_line_key`），**不得追加第二行** |
| 同名键多行 | 全部改成同一值 |
| 保存设置与切开关并发 | `env_lock` 串行化读-改-写 |
| 跑批中打开 / 关闭 | 下一个 pending 立即按新值 |
| 同一任务第二次 pending | `AlreadyUsed` → 转人工，文案警告"再确认会再扣一次" |
| confirm 失败（500/超时/断网） | 转 `PendingConfirmation`，**不重试**，原文进 `error` |
| confirm 成功后轮询超时/取消 | 计数已 +1，不丢账 |
| 历史 `needs_confirm` | 不动；开关打开时非阻塞提示 |
| 已终态 | 不受影响 |
| 多实例 | 各自原子量；`.env` 后写覆盖先写（不支持多实例） |
| 手改 `.env` | 运行中不感知；重启后生效 |
| 系统环境变量 | 忽略 |
| CLI 两参数同时给 | 报错退出 |

# State 2 · 数据流

## 2.0 总图（单向）

```text
        ┌──────────────────────────────────┐
        │ .env: LOVART_AUTO_CONFIRM        │  ← 持久真源（connection.rs 管读写）
        └──────────┬───────────────────────┘
   启动 read_env_flag│ 切换 update_env_keys（env_lock 内）
                   ▼
        ┌──────────────────────────────────┐
        │ GuiState.auto_confirm(AtomicBool)│  ← 全局运行真源
        └──────────┬───────────────────────┘
       start_run 克隆│
                   ▼
        Arc<AutoConfirm>{ enabled, confirmed, attempted }   ← 每批一份
                   │
                   │ poll_and_finish 构造 allow 闭包
                   ▼
   allow(id) ──► Ports::poll ──► poll_thread ──► confirm_thread（HTTP）
   &confirmed ─►   （透传）          │
                                    ├─ Allow      → confirm → confirmed+1 → continue
                                    ├─ Disabled   → Err[未开启]
                                    └─ AlreadyUsed→ Err[已确认过一次]
                   │
                   ▼
        AutoConfirm.confirmed
          ├─► get_state.autoConfirmed ──► 顶栏（1s）
          ├─► 批次结束（Ok/Err）──► push_alert ──► notice
          └─► CLI 结束 ──► stdout
```

## 2.1 链路 A：启动初始化

```text
GuiState::new(cwd)
  ├─ load_dot_env(.env)                              [既有：密钥等]
  ├─ let (v, warning) = connection::read_auto_confirm(.env)   [唯一实现]
  │     └─ warning 有值 ⇒ push_alert(warning)
  └─ Arc::new(AtomicBool::new(v)) → GuiState
```

## 2.2 链路 B：切换开关（唯一入口）

```text
[顶栏 chip] click
  ├─ 当前 ON  → invoke set_auto_confirm(false)          （关闭永不弹窗）
  └─ 当前 OFF → askConfirm(固定文案) → invoke set_auto_confirm(true)
                      │
                      ▼
        GuiState.env_lock
          ├─ connection::update_env_keys(.env, [(KEY, v)])
          ├─ 写盘失败 → Err 原文，内存不变
          └─ atomic.store(v)
                      │
                      ▼
        前端：用返回值**立即**更新 chip；失败 ⇒ notice 原文，chip 不变
             ON 且 waiting>0 ⇒ notice(历史提示)
```

`get_state` 只做对账（每秒），不承担"切换后第一次刷新"。

## 2.3 链路 C：开跑装配

```text
start_run
  ├─ auto = AutoConfirm::new(Arc::clone(&state.auto_confirm))   [每批新建]
  ├─ SchedulerOptions { auto_confirm: clone, … }
  └─ RunningBatch { cancelled, label, ids, auto_confirm: clone }
        └─ 后台线程 run_scheduler
```

## 2.4 链路 D：轮询中的确认（唯一花钱点）

```text
poll_and_finish
  ├─ let auto = Arc::clone(&shared.auto_confirm)
  ├─ let allow = || auto.decide(id)
  └─ ports.poll(deps, thread_id, timeout, &allow, auto.confirmed())
        └─ RealPorts::poll → poll_thread(deps, thread_id, allow, confirmed)

poll_thread 的两处 pending（status / result）都调 resolve_pending：
  ├─ allow() = Disabled    → Err[未开启]
  ├─ allow() = AlreadyUsed → Err[已确认过一次，手动会再扣]
  └─ allow() = Allow
        ├─ confirm OK  → confirmed.fetch_add(1) → Ok（继续轮询）
        └─ confirm Err → Err[失败 + 原文]（不重试）
```

- `allow()` 是唯一的"检查 + 占位"点：读开关、插集合，一步完成。
- 同一任务同一批，第二次 pending 必然 `AlreadyUsed`（**不再需要局部 `confirmed_once`**）。
- 计数在 confirm 成功那一刻落，**不经返回值**。

## 2.5 链路 E：计数与收尾

```text
confirm 成功 → AutoConfirm.confirmed + 1

① 跑批中：get_state → RunningBatch.auto_confirm.count() → JSON.autoConfirmed
② 批次结束（Ok / Err / 取消）：start_run 在**清 running 之前**读 count → N>0 ⇒ push_alert
③ CLI：`let result = run_scheduler(...); if count>0 { println } ; result?`
```

## 2.6 链路 F：CLI

```text
known_args() ← auto-confirm / no-auto-confirm（互斥）
  ├─ auto_confirm_flag(&args) -> Result<Option<bool>, String>   [纯函数，可测]
  ├─ let (file_value, warning) = connection::read_auto_confirm(.env)
  │     └─ warning 有值 ⇒ eprintln!（与 GUI 同一条文案）
  ├─ enabled = flag.unwrap_or(file_value)
  ├─ AutoConfirm::new(Arc::new(AtomicBool::new(enabled)))
  ├─ run_scheduler(options)
  └─ 先读 count 打印，再 `?`（错误路径也要报账）
```

## 2.7 唯一入口表

| 事实 | 唯一真源 | 唯一写入口 | 唯一读入口 |
|---|---|---|---|
| 开关（持久） | `.env` 的 `AUTO_CONFIRM_KEY` | `update_env_keys` | `read_env_flag` |
| 开关（运行） | `GuiState.auto_confirm` | `set_auto_confirm` | `AutoConfirm::decide`（策略）/ `get_state`（展示） |
| 每任务许可 | `AutoConfirm.attempted` | `AutoConfirm::decide` | 同上 |
| 本批计数 | `AutoConfirm.confirmed` | `resolve_pending`（confirm 成功后） | `count()` → get_state / 告警 / CLI |
| 花钱动作 | `client::confirm_thread` | 人工 `confirm_task` + 自动路径 | — |
| 待确认状态 | 状态表 `NeedsConfirm` | `handle_poll_error` | 看板 |
| 告警 | `GuiState.alerts` | `push_alert` | `take_alerts` |

**禁止**：在 `poll_thread` 里读文件/环境变量；在 UI 里自己算开关状态；另建第二份许可集合或计数器；给 `TaskRecord` 加字段。

## 2.8 失败拦截点表

| 节点 | 失败 | 拦截方式 | 用户可见性 |
|---|---|---|---|
| 启动读 `.env` | 读失败 / 非法值 | `false` + `push_alert` | 启动后弹告警 |
| 启动读 `.env` | 文件不存在 / 缺键 | `false`，不告警 | — |
| 切开关写 `.env` | 写失败 | `Err(原文)`，内存不变 | `notice` |
| `decide` | 无（纯判断） | — | — |
| `confirm_thread` | 网络 / 5xx / 超时 | 包成 `PendingConfirmation`，不重试 | 卡片 `error` 原文 |
| 轮询 | 既有 | 不变 | 既有 |
| 告警 | 通道故障 | `flushAlerts` 显示到看板通知 | 看板顶部 |

## 2.9 依赖方向与禁环

```text
gui.rs / run.rs  →  engine::scheduler  →  lovart::task  →  lovart::client
        │                  │                   │
        └── 只传 Arc ───────┘                   └── 只回调 + 计数器，不 import engine
```

- `AutoConfirmDecision` 定义在 `lovart::task`，由 engine 构造 → 单向。
- `AutoConfirm` 留在 engine，不进入 `ClientDeps`（协议层不做花钱决策）。
- 禁止：`lovart::task` 读文件/环境变量；`engine` 直接发 HTTP。

## 2.10 可变性与并发纪律

| 状态 | 类型 | 谁改 | 纪律 |
|---|---|---|---|
| 全局开关 | `Arc<AtomicBool>` | `set_auto_confirm` | `Relaxed` 读写 |
| 本批计数 | `AtomicUsize`（在 `Arc<AutoConfirm>` 内） | `resolve_pending` | 只增不减 |
| 许可集合 | `Mutex<HashSet<String>>`（在 `AutoConfirm` 内） | `decide` | 锁内只做 insert，无 I/O |
| `.env` 文本 | 文件 | `update_env_keys` | 读-改-写整体在 `env_lock` 内 |

- 不新增全局 `static`；不 clone 整个 `Ctx`；不在持锁期间做网络 I/O。

## 2.11 排障埋点（沿用既有通道）

本仓没有 logger / eventBus，不新造：

| 事件 | 通道 | 说明 |
|---|---|---|
| 自动确认成功 | `Shared::log`（`[w{id}] ✅ 自动确认 …`） | CLI 打印；GUI 丢弃（既有） |
| 确认失败 | 任务 `error` 字段 | 卡片可见，原文透传 |
| 批次总账 | `push_alert` → `notice` | GUI 唯一可见出口 |
| 开关切换失败 | 命令 `Err` → `notice` | 不静默 |
| 开关切换成功 | chip 即时更新 | 无 toast，避免噪音 |

## 3.3 协议层（`Fake` transport 脚本化）

公共：`deps.done_recheck = ZERO`；断言 `fake.seen()` 的**方法 + 路径 + 次数**，以及计数器。

| ID | 响应序列 | 期望 |
|---|---|---|
| P1 | `[pending]`，开关关 | `Err(PendingConfirmation)`；confirm 0；计数 0 |
| P2 | `[done, done, result{pending_confirmation:{…}}]`，开关关 | 同上（对象形状也必须判待确认） |
| P3 | `[pending, confirmOK, done, done, result(items)]`，开关开 | `Ok(items)`；confirm 恰好 1 次（POST `/chat/confirm`，body 含 `t-1`）；confirm 之后仍有 **2 次 GET status**（轮询 + done 复核，证明没跳过状态机）；计数 1 |
| P4 | `[done, done, result{pending_confirmation:{…}}, confirmOK, done, done, result(items)]` | `Ok(items)`；confirm 1；计数 1 |
| P5 | `[pending, confirmOK, pending]` | `Err(PendingConfirmation)`；message 含「已自动确认过一次」；confirm 1；计数 1 |
| P6 | `[pending, HTTP 500 {message:"boom"}]` | `Err(PendingConfirmation)`；message 含「自动确认失败」**且含 `boom`**（原文透传）；confirm 1；计数 0 |
| P7 | `[pending, confirmOK, HTTP 401]` | `Err(Upstream)`（不是 PendingConfirmation）；计数 **1**（不随轮询失败丢失） |
| P8 | 开关开跑一轮 → 关闭 → 再跑 `[pending]` | 第二轮 `Err`，message 含「未开启」；confirm 总数仍 1（跨调用生效） |
| P9 | 自定义 transport：服务第一条 status 时把开关置 false；`[pending]` | `Err`；confirm **0**（证明开关是在"确认那一刻"读的，不是轮询开始时快照） |

**P9 的实现要求**：`Fake` 加一个**仅测试用**的 `on_send` 钩子（`Option<Arc<dyn Fn(&HttpRequest)>>`），不进入生产代码。
