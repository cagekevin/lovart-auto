## 0. 结论（一句话）

把 mockup v3 的四处改动落地到 `ui/`：① 两个弹窗共用**同一套大尺寸外壳**；② 标题栏只留标题 + 右上角 SVG 加号/叉（加号 = 原底部新建按钮，不新增入口）；③ 预设列表由**行改成 4 列卡片**，垫图以缩略图显示在卡片左下角；④ 素材库文案「发送到」→「添加到」。编辑态**不改结构**——现有 `index.html:349-356` 已经是「垫图在上、正文在下、同一张 `.composer`」，正是用户要的形态。

## 3. 形状与数据链

### 3.1 统一外壳（`.dialog-mid` 一处）

现状 `ui/style.css:1573-1575`：`.dialog-mid { width: min(720px, 92vw); }`，注释说「与编辑区同档宽度」——这条注释随改动一起改。

新形状：
```css
.dialog-mid {
  width: min(1080px, 94vw);
  height: min(720px, calc(100vh - 112px));
  display: flex;
  flex-direction: column;
}
```
- **只改 `.dialog-mid`**，不动 `.dialog`（发布确认 / 清空确认 / 导入 / 设置仍是小框）——一个尺寸源，不给别的弹窗加第二套。
- 两个弹窗（`index.html:329` 和 `372`）都挂 `.dialog-mid`，自动一起变。
- 高度给足后，`.preset-list` / `.library-grid` 的 `max-height: 56vh` 要改成 `flex: 1; min-height: 0; overflow: auto`，否则内容区仍只占半屏。

### 3.2 标题栏（加号 + 叉同款 SVG）

- `index.html` 的 `svg-defs`（约 27-51）新增两个 symbol：
  - `i-plus`: `M12 5v14M5 12h14`
  - `i-close`: `M6 6l12 12M18 6L6 18`
  - 两者同为 `viewBox="0 0 24 24"`，同一套 stroke 由 CSS 给。
- `#btnPresetNew`（现 `index.html:339`，在 `.dialog-foot` 里）**移动**到 `#maskPresets .dialog-head`，在 `#btnPresetClose` 前；`#btnLibraryAdd`（现 `382`）同理移到 `#maskLibrary .dialog-head`。**id 不变** ⇒ `app.js` 的接线不动。
- 两个按钮内容从文字 `＋` 改成 `<svg><use href="#i-plus"/></svg>`；两个关闭按钮从 `×` 改成 `<svg><use href="#i-close"/></svg>`。
- CSS：`.dialog-icon` 与 `.dialog-close` **合并成一条规则**（26×26、透明、flex 居中、svg 15×15、stroke-width 1.7），两者共用同一规格；标题栏 `gap: 8px`，标题 `margin-right: auto` 把两个按钮推到右侧相邻。
- 旧的 `#presetListView .dialog-foot { justify-content: flex-start; }`（1819）和 `#maskLibrary .dialog-foot`（1888）：两个 foot 都空了 ⇒ 连同 `.dialog-foot` 节点一起删（垂直删净），不是留个空条。
  - ⚠️ 但**编辑态**的 `.dialog-foot`（取消 / 保存）必须保留。

### 3.3 预设列表：行 → 4 列卡片

`app.js:1702-1737 renderPresetList` 的 DOM 形状改为：

```
div.preset-grid
└─ article.preset-card                  ← 原 .preset-item
   ├─ div.card-top
   │  ├─ span.card-name                 ← 原 .preset-pick-name，走 displayName()
   │  ├─ button.icon-btn                ← 原 .preset-act（修改）
   │  └─ button.icon-btn.is-danger      ← 原 .preset-act.is-danger（删除）
   ├─ p.card-text                       ← 原 .preset-pick-text
   └─ div.card-meta
      └─ span.card-ref.ph-* (0~N 张)    ← 垫图缩略图，28×28
```

- **整卡可点 = 取用**：`click` 绑在 `article.preset-card` 上，但编辑/删除按钮的 click 要 `stopPropagation()`，否则点图标会连带取用（这是新增的必要性——原来是 `div.preset-item` 包三个兄弟节点，没有嵌套）。
- 图标沿用 `index.html` 现成的 `i-edit` / `i-trash`，用 `svgIcon()`，**不新画 SVG**。
- 名字仍走 `window.Presets.displayName(preset)`（唯一兜底规则），不在 app.js 里写 `preset.name || 首行`。
- 空态 `div.preset-empty` 保留（plan 13 §4）。

**垫图缩略图的数据链**（新增的唯一一处取数）：

```
Preset.images: [{file}]                   // 真源在 Rust，前端不定义
  → window.Presets.resolveImages([...])   // presets.js:49，已有唯一解析入口
  → { ok:true, images:[{file,path,label}] }
  → app.js 用 path 生成 <img src=toFileUrl(path)>
  → 按 file 建 Map，渲染时查表；解析失败 ⇒ 该卡不显示缩略图
```

- **一次解析所有卡片的 file**（收集成一批调一次 `resolveImages`），不要每张卡调一次命令 —— 否则 N 张卡 N 次 IPC。
- 缩略图占位用 CSS 渐变还是破图？用真实 path（复用 `toFileUrl`，与素材库同一入口）。解析失败时**不渲染 `<img>`**，留空白 `.card-meta`（保持卡片高度一致）。
- 不新增后端字段、不把 path 写进 Preset 形状（`file` 才是真相，path 是派生）。

### 3.4 素材库

- 外壳、标题栏按 §3.1/§3.2。
- `.library-grid` 的 `repeat(auto-fill, minmax(160px, 1fr))` **保留**（plan 20 明确「尺寸只由这一行决定、不要滑杆」）——弹窗变大后列数自然变多，不改这个值。
- `max-height: 56vh` 按 §3.1 改成 flex 撑满。
- 空态与删除逻辑不动。

### 3.5 文案（4 处用户可见）

| 文件:行 | 现 | 新 |
|---|---|---|
| `ui/index.html:281` | viewer 按钮「发送到素材库」 | 「添加到素材库」 |
| `ui/app.js:1879` | 空态「…点「发送到素材库」」 | 「…点右上角「＋」」 |
| `ui/app.js:1948` | toast「已发送到素材库：…」 | 「已添加到素材库：…」 |
| 新增的加号 `aria-label` | — | 「添加到素材库」 |

代码注释里的「发送到素材库」（`app.js:1292/1851/2538/3852`、`style.css:1049/1620`、`index.html:279`）**同批改词**，保持一份事实一处；`docs/plan/20` 是历史施工记录，不改。命令名 `send_to_library` 是接口名，**不改**。

## 5. 之后（每条一句为什么可以等）

- **素材库缩略图尺寸滑杆**：plan 20 明确否决（不要第二个 localStorage 键）；现在列数由弹窗宽度自适应。
- **卡片上直接编辑正文**：用户没提；编辑仍走右上角加号 → 编辑器。
- **预设卡片按最近使用排序**：plan 13 定「存储顺序即展示顺序」；改排序要动 Rust，不是本轮。
- **把 mockup 里的占位渐变搬到生产**：生产用真实图片，占位渐变只属于设计稿。
