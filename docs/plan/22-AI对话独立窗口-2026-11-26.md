# AI 对话「拉出去」成独立窗口 · 施工契约

> 状态：**施工中**（2026-11-26）
> 用户原话：「看下他的 AI 助手的形态，还能拉出来做独立面板」（参照 `G:\01画布项目\AI-Canvas-tauri`）
> 前置：plan 21（面板与六条命令）· ADR-0005（一个能力一个入口）· ADR-0010（形态不冒充第一性）

---

## 1. 第一性

**一处真相，两处显示。** 删掉"独立窗口"，需求退回"面板只能待在应用里"；
删掉"同一份真相"，独立窗口就该自己再存一份会话 —— 那才是真的两套。

| 要素 | 删掉后 | 判定 |
|---|---|---|
| 从面板拉出去 = 第二个 Tauri 窗口 | 用户要的形态消失 | **第一性** |
| 两窗共用 `data/chat-history.json` + 同一把 `Mutex<ChatStore>` | 出现第二份会话 | **第一性**（约束：不许有第二真相） |
| 一个窗口改了，另一个窗口要知道 | 另一窗显示旧列表（界面说谎） | **第一性** |
| 停靠回来 | 只能关窗再点按钮 | 紧邻（同批做） |
| 记住窗口尺寸 / 位置 | 每次重开回默认大小 | **之后**（要新落盘状态，先不加） |
| 系统 × 关掉后主窗口自动恢复 dock | 主窗口 dock 仍是隐藏的 | **之后**（按钮永远是 toggle，不制造隐性状态） |

## 2. 最小切片

点面板顶栏「↗」→ 出现一个独立窗口（label `assistant`），里面还是那个面具；
在独立窗口里发一句话 → 主窗口的面板（如果开着）内容跟着变。

## 3. 形状与数据链

### 3.1 谁拥有窗口

**Rust**（`gui.rs`）。前端只发命令、只收事件 —— 前端拿不到"窗口对象"，也就不存在两处关闭逻辑。

| 命令 | 入参 | 行为 |
|---|---|---|
| `open_assistant_window` | 无 | 已有 `assistant` 窗口 ⇒ `unminimize → show → set_focus`；没有 ⇒ 建窗（420×780，最小 320×420，标题「AI 对话」） |
| `close_assistant_window` | 无 | 关掉 `assistant` 窗口（不存在当成功） |
| `dock_assistant_window` | 无 | 先 `emit_to("main", "assistant://dock")`，再关窗 —— 一次动作，不留半态 |

建窗用 `initialization_script("window.__ASSISTANT_WINDOW__ = true")` 打标记，
**不用 `?assistant=1`**：URL 查询串要穿一层 Tauri 的 path 解析，标记写在 window 对象上不依赖这条路。

### 3.2 同步（这是本轮最容易做重的地方）

参照实现（AI-Canvas-tauri）用了 4 个事件 + 100 多行增量补丁，因为**它的真相在主窗口的 store 里**。
我们的真相在文件里、`Mutex<ChatStore>` 是**全进程共享**的 ⇒ 独立窗口直接调同一组 `assistant_*` 就拿到同一份。

所以只需要 **1 条广播**：

- 任一 `assistant_*` 成功后，后端 `emit_to(<另一个窗口>, "assistant://changed", ())`（`window.label()` 决定另一个是谁）。
- 两个窗口都 `listen` 它 → 调 `plugin.refresh()`（本来就有）。
- **不转发动作、不推快照、不做增量合并**：动作就是命令，状态就是文件。

### 3.3 独立窗口里跑的是什么

同一份 `index.html` / `app.js`，靠 `window.__ASSISTANT_WINDOW__` 早退：

```
DOMContentLoaded
  ├─ 独立窗口 ⇒ 只 mount 插件 + 让 dock 铺满 + 收事件     （不 loadModels / 不 refreshBoard / 不轮询 / 不接拖放）
  └─ 主窗口   ⇒ 原来的全部初始化；面板仍是右侧浮层，多两个动作：↗ 拉出去、收 assistant://dock 停靠回来
```

⚠️ **必须早退**：跑两份完整 boot = 两套 1Hz 轮询 + 两套拖放监听（都在写同一份状态），
比"少一个功能"糟得多。

### 3.4 插件的边界（不因宿主能力而变脏）

「拉出去 / 停靠」**不写进插件契约**，而是 `createAssistantPlugin({ …, actions })` 里可选的
`onDetach` / `onDock`：宿主给了才渲染那两个图标。别的宿主不给 ⇒ 按钮根本不出现，
插件依旧零 import、不认窗口。

### 3.5 权限

`src-tauri/capabilities/default.json` 的 `"windows": ["main"]` 必须加 `"assistant"`，
否则独立窗口里 `plugin:event|listen` 被 ACL 拒（历史教训：这个文件就是为这条报错建的）。
**不新增** `core:event:allow-emit`：所有事件从 Rust 发，前端只监听。

## 5. 之后

- 记住窗口尺寸/位置：要新的落盘字段（`data/` 下多一个状态），先不加。
- 独立窗口被系统 × 关掉后主窗口自动恢复 dock：需要一个"窗口已关"事件；现在按钮就是 toggle，不欠用户一步。
- 第二个独立窗口 / 多显示器定位：用户没提。

## 6. 不做

| 项 | 为什么 |
|---|---|
| 前端推快照 / 转发动作 / 增量合并 | 真相共享 ⇒ 这套是纯负担（参照实现是被它的 store 真相逼出来的） |
| 插件内认窗口与 `invoke('close_...')` | 插件要能整目录拷走；窗口是宿主能力 |
| `core:event:allow-emit` | 事件全从 Rust 发；多一条发送权限就多一个面 |
| 独立窗口里的主界面（看板/编辑区） | 那等于开第二个应用；用户要的是"对话能拉出来" |

## 7. 验收

| # | 步骤 | 期望 |
|---|---|---|
| H1 | 主窗口点面板顶栏「↗」 | 主窗口的面板收起，出现独立窗口（420×780，标题「AI 对话」），内容与刚才一致 |
| H2 | 独立窗口里发一句话 | 回复正常；主窗口点「AI 对话」重新打开面板 ⇒ 新消息已在（同一个 `chat-history.json`） |
| H3 | 主窗口删掉一个会话 / 新建一个 | 独立窗口的下拉列表跟着变（没点它也会刷新） |
| H4 | 独立窗口点「⤢」停靠 | 独立窗口关闭，主窗口的面板打开，会话不变 |
| H5 | 独立窗口连续点两次「↗」（主窗口） | 第二次不新开窗口，只是把已有窗口提到前面 |
